> ข้อมูลจากโค้ด FE ณ 2026-10-16 (branch `develop` commit `4c73f5e`)

**Route:** `/buriram/campaign/landing/{slug แคมเปญ}` (ไม่มี rewrite ใน `proxy.ts`)

**ไฟล์หน้า:** `app/[location]/campaign/landing/[slug]/page.tsx` → template `components/pages/campaign/event-online/EventOnlineLandingDefault.tsx`

**TrackingProvider:** `source: campaign_landing`, `source_id` = id แคมเปญ, `source_type: campaign` (ไม่มี `category`)

ทุก event ในหน้านี้ได้ค่าเริ่มต้นจาก `CampaignLandingTrackingProvider`: `entity_id` = id แคมเปญ (ถ้า component ไม่ได้ส่ง entity_id เอง) และ extra_data `page_view_id`, `campaign_slug`, `campaign_phase`

Template นี้ใช้กับ `buriram` ทุกแคมเปญ จังหวัดอื่นดูเอกสาร "หน้าแคมเปญ Landing" ต่างจากหน้าแคมเปญ Landing คือไม่มี Flash Deal, ใช้ CampaignParticipantsSection แบบไม่มีปุ่ม "สนใจ" (ข้อ 10) และการ์ด "พิเศษจากแคมเปญ" ไม่มีปุ่มลงทะเบียน (ข้อ 5)

## วิธีอ่านตาราง

* **impression** = การ์ดหรือบล็อกเข้ามาในจอ, **click** = กด, **view** = เปิด modal หรือหน้า
* **section_number** = ลำดับ section บนหน้า, **position** = ลำดับการ์ดใน section (เริ่มที่ 1)
* **entity_id** = id ของสิ่งที่ถูกดูหรือกด เช่น id ประกาศ, id แบนเนอร์
* ⚠️ = ค่าไม่ตรงกับ convention ของส่วนอื่น ควรเช็ก

## 0. ทั้งหน้า + ส่วนกลาง

หน้านี้อยู่นอก layout `(interface)` จึงไม่มี Navbar, Pop-up และ Login / Register แถบหัวของหน้าคือ EventCampaignHeader ของแคมเปญเอง (ข้อ 1)

| Component | Event | ประเภท | ยิงเมื่อ | section_name | หมายเหตุ |
|-----------|-------|--------|----------|--------------|----------|
| PageViewTracker | `page_view` | view   | เปิดหน้า | `page_section` | 1 ครั้งต่อหน้า |

⚠️ ไม่มี userMeta จาก session: ทุก event ในหน้านี้ส่ง `is_logged_in = false` และไม่มี `user_id` แม้ผู้ใช้ login อยู่

## **เอกสารข้อกำหนดทางธุรกิจ (BRD)**

**Notification การแจ้งเตือนและการแสดงผล\nแบ่งออกเป็น 3 ระบบ**

1\.ระบบการแจ้งเตือน Backoffice ใช้โดย super admin,admin ของน่าอยู่

2\.ระบบการแจ้งเตือน Console

3\.ระบบการแจ้งเตือนน่าอยู่ Nayoo

**1.บทนำและที่มา**

ฟีเจอร์ Notification มีเพื่อให้เกิดการแจ่งเตือนให้เกิดผลสัมฤทธิ์ในการแจ้งเตือน เพื่อทำให้แพลตฟอร์มเกิดระบบ hook ที่ครบวงจร ในการทำให้เกิดการทำซ้ำในการเข้าใช่งานเข้าสู่ระบบ และการแจ้งเตือนที่ทำให้ผู้ใช้งานสามารถได้รับผลประโยชน์สูงสุด

**2.วัตถุประสงค์ทางธุรกิจ**

**ตารางเหตุการณ์ใช้ Walk-in เป็นตัวอย่าง โดยกฎเดียวกันนี้ใช้กับตัวเลือกพิเศษอื่นทั้งหมดที่หน้าปัจจุบันรองรับ เช่น แคมเปญ รีวิวจากน่าอยู่ และ VDO 360 ดังนี้**

* เมื่อเปลี่ยนขอบเขต จาก Center ไปจังหวัด จากจังหวัดหนึ่งไปอีกจังหวัด หรือจากจังหวัดกลับ Center ให้ล้างตัวกรองทั้งหมด รวมตัวเลือกพิเศษ แล้วกลับเป็นค่าเริ่มต้นของหน้าปลายทาง โดยค่าด้านนอก Full Filter และ URL ต้องตรงกัน
* การแสดงตัวเลือกพิเศษในหน้าปลายทาง ให้ตรวจจากใบประกาศของสถาบันในขอบเขตนั้น หากมีใบประกาศเข้าร่วมอย่างน้อยหนึ่งประเภททรัพย์ ให้แสดงตัวเลือกนั้นแบบยังไม่เลือก หากไม่มีใบประกาศเข้าร่วมเลย ให้ซ่อนตัวเลือกนั้น
* เมื่ออยู่ขอบเขตเดิม ให้คงค่าที่ผู้ใช้เลือกไว้ หากตัวเลือกพิเศษมีใบประกาศเข้าร่วม แต่ไม่มีใบที่ตรงกับประเภททรัพย์และเงื่อนไขอื่นที่เลือก ให้ ไม่แสดงผลลัพธ์การค้นหา โดยไม่ล้างตัวกรองให้อัตโนมัติ
* เมื่อผู้ใช้เลือกตัวเลือกพิเศษใหม่ ให้แสดงเฉพาะใบประกาศของสถาบันที่เข้าร่วมตัวเลือกนั้นและผ่านเงื่อนไขอื่นที่เลือก ภายในขอบเขตปัจจุบัน

1\.หลังจากกด (ซื้อโครงการใหม่ หรือ หมวดอื่นๆ) โดยที่ยังไม่ได้เลือนใดๆ

3\.ขณะที่ยังเห็น filter ส่วนนี้อยู่ (ตัวเลือก 4 หมวด ที่ติดด้านบนจะไม่แสดง)

แม้ว่าจะเลื่อนขึ้น หรือ ลงก็ตาม

4\.หลังจากเลือนลงมาจน เลย filter แล้ว Filter มาติดด้านบน ประเภททรัพย์ เช่น, บ้าน,ดอนโด,ทาวน์โฮม จะถูกยุบเป็นปุ่ม ทรัพย์
