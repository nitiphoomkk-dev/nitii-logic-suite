**EP-04 Product**

* การแสดง product จะแสดงตามการจัดหมวดหมู่ของ โครงการใหม่และรับสร้างบ้าน
* Product ที่ถูกจัดหมวดหมู่จะมีอยู่ 3 section
  * 1. ใต้ <h1><p> เป็นตำแหน่งที่แทนสารบัญ จะสลับแสดง logo แบรนด์โครงการ กับ บริษัทรับสร้างบ้านชั้นนำ ตามหมวดของบทความ (ด้านบนแสดงแค่ 4)
  * 2. ใต้บทความใกล้เคียง จะสลับแสดง logo แบรนด์โครงการ กับ บริษัทรับสร้างบ้านชั้นนำ ตามหมวดของบทความ (ถ้าตำแหน่ง 1 แสดง logo แบรนด์ ตำแหน่ง 2 จะต้องแสดง บริษัทรับสร้างบ้านชั้นนำ)
  * 3. ใต้ product 2 บท banner  จะสลับแสดงระหว่าง โครงการน่าสนใจ( top ads มือ 1) กับ แบบบ้านน่าสนใจ ( top ads แบบบ้าน) (ดึงมาทีละ 4 เท่านั้น มือ 1 รวม super top ads ไว้ตำแหน่งที่ 1)

| หัวข้อ | เงื่อนไข / การกระทำ | Logic การทำงาน / ผลลัพธ์ที่คาดหวัง |
|--------|---------------------|------------------------------------|
| ขอบเขตการใช้งาน | ผู้ใช้กดปุ่ม **Facebook หรือ LINE** ในหน้าบทความหรือหน้าใบประกาศ | ใช้ Logic การลงทะเบียน การข้ามฟอร์ม และการกันรายชื่อซ้ำตามตารางนี้ |
| ปลายทาง Facebook | กด Facebook และผ่านเงื่อนไขการติดต่อแล้ว | เปิด **Facebook Messenger** ของผู้ติดต่อที่กำหนด |
| ปลายทาง LINE | กด LINE และผ่านเงื่อนไขการติดต่อแล้ว | เปิดช่องทาง **LINE** ของผู้ติดต่อที่กำหนด |
| ขอบเขตหน้า | บทความเชื่อมกับใบประกาศ A | หน้าบทความและหน้าใบประกาศ A ถือเป็น **คนละหน้า** สำหรับตรวจสิทธิ์ข้ามฟอร์ม |
| ใบประกาศ → บทความ | ผู้ใช้ไม่ Login ลงทะเบียนในใบประกาศ A สำเร็จ แล้วกด Facebook หรือ LINE ครั้งแรกบนบทความที่เชื่อม A | แสดงฟอร์มหรือ Modal ลงทะเบียนของหน้าบทความ แม้การลงทะเบียนในใบ A ยังไม่ครบ 24 ชั่วโมง |
| บทความ → ใบประกาศ | ผู้ใช้ไม่ Login ลงทะเบียนในบทความที่เชื่อม A สำเร็จ แล้วกด Facebook หรือ LINE ครั้งแรกบนใบ A | แสดงฟอร์มหรือ Modal ของหน้าใบประกาศ A แม้การลงทะเบียนในบทความยังไม่ครบ 24 ชั่วโมง |
| ติดต่อซ้ำในบทความเดิม | ผู้ใช้ไม่ Login เคยลงทะเบียนสำเร็จในหน้าบทความเดียวกัน และยังไม่ครบ 24 ชั่วโมง แล้วกด Facebook หรือ LINE | ไม่แสดงฟอร์มซ้ำ ให้ตรวจรอบการส่งข้อมูลก่อนเปิดช่องทางที่กด |
| ติดต่อซ้ำในใบประกาศเดิม | ผู้ใช้ไม่ Login เคยลงทะเบียนสำเร็จในหน้าใบประกาศเดียวกัน และยังไม่ครบ 24 ชั่วโมง แล้วกด Facebook หรือ LINE | ไม่แสดงฟอร์มซ้ำ ให้ตรวจรอบการส่งข้อมูลก่อนเปิดช่องทางที่กด |
| ครบ 24 ชั่วโมง | ผู้ใช้ไม่ Login และสิทธิ์ข้ามฟอร์มของหน้าที่กำลังใช้งานครบ 24 ชั่วโมงแล้ว | แสดงฟอร์มหรือ Modal ให้ลงทะเบียนใหม่ก่อนเปิด Facebook หรือ LINE |
| Login และมีเบอร์ในบัญชี | ผู้ใช้ Login แล้วกด Facebook หรือ LINE | ใช้ชื่อ–นามสกุลและเบอร์จากบัญชี โดยไม่ต้องกรอกซ้ำ ตรวจเงื่อนไขการใช้ข้อมูลและรอบส่งรายชื่อก่อนเปิดช่องทางที่กด |
| Login แต่ไม่มีเบอร์ในบัญชี | ผู้ใช้ Login แต่บัญชียังไม่มีเบอร์ แล้วกด Facebook หรือ LINE | แสดง Modal ให้กรอกเบอร์ **ทุกครั้ง** แม้เคยกรอกจากอีกหน้าแล้วหรือยังไม่ครบ 24 ชั่วโมง |
| เพิ่มเบอร์ในบัญชี | ผู้ใช้บันทึกเบอร์ที่หน้าแก้ไขโปรไฟล์สำเร็จ | การกด Facebook หรือ LINE ครั้งถัดไปใช้เบอร์จากบัญชี และไม่ต้องแสดง Modal เพื่อกรอกเบอร์ |
| เบอร์ที่กรอกใน Modal | ผู้ใช้ Login แต่บัญชีไม่มีเบอร์ และกรอกเบอร์ใน Modal | ใช้เบอร์สำหรับการลงทะเบียนครั้งนั้น โดยไม่บันทึกเป็นเบอร์ในบัญชีอัตโนมัติ |
| ตรวจการส่งซ้ำ | ลงทะเบียนหรือกดติดต่อจากบทความหรือใบประกาศ โดยทั้งสองจุดอ้างอิง **ใบประกาศ A เดียวกัน** | ตรวจประวัติการส่งโดยใช้ **ใบประกาศ A + ชื่อ + เบอร์โทร** ภายในรอบวันเดียวกัน (เกี่ยวกับการส่งไลน์และรายชื่อลุกค้า) |
| ประวัติ Facebook และ LINE | ผู้ใช้กด Facebook และ LINE ของใบประกาศเดียวกัน | ใช้ประวัติกันรายชื่อซ้ำ **ร่วมกันทั้งสองปุ่ม** |
| ข้อมูลเดิมในวันเดียวกัน | ชื่อ–เบอร์เดิมเคยส่งให้ใบประกาศ A แล้วในวันเดียวกัน | ไม่ส่งรายชื่อและ LINE “ลูกค้ามาแล้ว” ซ้ำ แม้ครั้งก่อนใช้คนละหน้า หรือกดคนละปุ่ม โดยยังเปิดช่องทางที่กดได้หลังผ่านเงื่อนไขของหน้านั้น |
| เริ่มรอบวันใหม่ | ผู้ใช้กดติดต่อหรือลงทะเบียนใหม่หลังเวลา **00:00 น. ตามเวลาไทย** | ตรวจการส่งในรอบวันใหม่ และส่งรายชื่อกับ LINE ได้อีกครั้งเมื่อผ่านเงื่อนไข โดยไม่ส่งอัตโนมัติเพียงเพราะเปลี่ยนวัน |
| คนละใบประกาศ | บทความเชื่อมใบประกาศ B แต่ผู้ใช้เคยลงทะเบียนเฉพาะใบประกาศ A | ตรวจประวัติของ B แยกจาก A แม้ทั้งสองใบอยู่บริษัทเดียวกัน |
| ระบุข้อมูลต้นทาง | ผู้ใช้ส่งข้อมูลจากหน้าบทความ | บันทึกจุดที่ลงทะเบียนว่าเป็น **หน้าบทความ** พร้อมอ้างอิงใบประกาศที่เชื่อม และส่งให้ผู้รับตามที่กำหนดของจุดติดต่อ |
| การตรวจสิทธิ์ Walk-in | จุดติดต่อมีการรับสิทธิ์ Walk-in | ตรวจสิทธิ์ตามกฎ Walk-in แยกจากกฎกันรายชื่อซ้ำรายวัน |

### ตัวอย่างสำหรับ Dev และ Tester

| กรณี | เหตุการณ์ | ผลลัพธ์ที่คาดหวัง |
|------|-----------|-------------------|
| **1. Facebook ใบประกาศ → Facebook บทความ** | ไม่ Login ลงทะเบียนผ่าน Facebook ในใบ A เวลา 10:00 น. แล้วกด Facebook บนบทความที่เชื่อม A เวลา 10:10 น. ด้วยชื่อ–เบอร์เดิม | แสดงฟอร์มของบทความเพราะเป็นคนละหน้า เมื่อส่งสำเร็จให้เปิด Messenger และไม่ส่งรายชื่อหรือ LINE แจ้งเตือนซ้ำในวันเดียวกัน |
| **2. Facebook ใบประกาศ → LINE บทความ** | ไม่ Login ลงทะเบียนผ่าน Facebook ในใบ A แล้วกด LINE บนบทความที่เชื่อม A ในวันเดียวกันด้วยชื่อ–เบอร์เดิม | แสดงฟอร์มของบทความ เมื่อผ่านเงื่อนไขให้เปิด LINE และไม่ส่งรายชื่อหรือ LINE แจ้งเตือนซ้ำ |
| **3. LINE บทความ → Facebook ใบประกาศ** | ไม่ Login ลงทะเบียนผ่าน LINE ในบทความที่เชื่อม A แล้วกด Facebook บนใบ A ในวันเดียวกันด้วยชื่อ–เบอร์เดิม | แสดงฟอร์มของใบ A เมื่อผ่านเงื่อนไขให้เปิด Messenger และไม่ส่งรายชื่อหรือ LINE แจ้งเตือนซ้ำ |
| **4. กดคนละปุ่มในบทความเดิม** | ไม่ Login ลงทะเบียนผ่าน Facebook ในบทความสำเร็จ แล้วกด LINE บนบทความเดิมภายใน 24 ชั่วโมง | ข้ามฟอร์ม ตรวจรอบส่งข้อมูล แล้วเปิด LINE โดยไม่ส่งรายชื่อหรือ LINE แจ้งเตือนซ้ำในวันเดียวกัน |
| **5. ข้ามวันแต่ยังไม่ครบ 24 ชั่วโมง** | ไม่ Login ลงทะเบียนในบทความเวลา 23:50 น. แล้วกด Facebook หรือ LINE ในบทความเดิมเวลา 00:10 น. | ข้ามฟอร์มได้เพราะยังไม่ครบ 24 ชั่วโมง และส่งรายชื่อกับ LINE แจ้งเตือนได้อีกครั้งตามรอบวันใหม่เมื่อผ่านเงื่อนไข |
| **6. คนละใบประกาศ** | ลงทะเบียนใบ A แล้วกด Facebook หรือ LINE จากบทความที่เชื่อมใบ B | ตรวจสิทธิ์ฟอร์มของหน้าบทความ และตรวจประวัติการส่งของ **B แยกจาก A** |
| **7. Login ไม่มีเบอร์** | Login โดยบัญชีไม่มีเบอร์ เคยกรอกเบอร์ในใบ A แล้วมากด Facebook หรือ LINE บนบทความที่เชื่อม A | แสดง Modal ให้กรอกเบอร์อีกครั้ง; หากชื่อ–เบอร์เดิมเคยส่งให้ A ในวันเดียวกัน ไม่ส่งรายชื่อและ LINE แจ้งเตือนซ้ำ |

## Acceptance Criteria — หน้ารายละเอียดบทความกลาง

เกณฑ์ด้านล่างอ้างอิง Logic ในหน้านี้และเอกสารที่เชื่อมโยง ใช้ตรวจทั้ง Desktop และ Mobile ตามตำแหน่งที่ระบุ โดยรายการที่ยังขัดกันแยกไว้ในหัวข้อรอตัดสินใจ
