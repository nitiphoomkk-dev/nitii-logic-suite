**Solution Banner สำหรับหน้าเว็บไซต์จังหวัด**

ฉบับ 1.0 · 4 พฤศจิกายน 2569 · จัดทำโดยนิติ๊ · ตามคำสั่งผู้ใช้ให้ประยุกต์กฎภาษาและ A/B จาก Top Banner จังหวัด โดยคงผังและขนาด Banner

**ขอบเขตที่นำมาใช้:** เฉพาะจังหวัดปัจจุบัน รวมหมวดน่าอยู่ที่ผ่านเงื่อนไข ไทยบังคับ จีน/อังกฤษใช้ไทยสำรอง และ A/B แยกภาษา รวมข้อมูล Desktop/Mobile ภายในภาษาเดียวกัน ส่วน Banner คงสูงสุด **3 Slot ต่อจุดวาง** ตาม [Banner 3 ภาษา](https://wiki.infonayoo.co/doc/banner-3-Xfb8HGQLZJ) ไม่ยกเพดานและขนาดภาพของ Top Banner มาใช้

เอกสารนี้เป็น Solution ใหม่สำหรับ Dev และ Tester ไม่ใช่หลักฐานว่าระบบจริงพัฒนาแล้ว ตัวอย่างและภาพจำลองใช้ข้อมูลสมมติ

## EP-01 ขอบเขตและเงื่อนไขการแสดงผล

**หลักการทำงาน:** ดึง Candidate Banner ของจังหวัดปัจจุบัน รวมหมวดน่าอยู่ → ตรวจสถานะ เวลา สิทธิ์ ประเภทหน้า และไทยบังคับตรงอุปกรณ์ → สำหรับแต่ละจุดวาง Shuffle Candidate ทั้งหมดที่มีสิทธิ์ในจุดนั้น → เลือกสูงสุด 3 Slot → เลือกภาพภาษาผู้ใช้หรือไทยสำรอง → เลือก A/B ด้วยน้ำหนักของภาษาภาพจริง → แสดงรายการละหนึ่งภาพและคงชุดระหว่างเลื่อน

| รหัส | หัวข้อ | เงื่อนไข / การกระทำ | Logic การแสดงผล / การทำงาน |
|------|--------|---------------------|----------------------------|
| BNP-01 | ขอบเขตหน้า | หน้าเว็บไซต์จังหวัดมีผัง Banner เดิมตาม EP-05 | ใช้ Solution นี้ทั้ง Desktop และ Mobile ในจุดวางที่หน้านั้นรองรับ |
| BNP-02 | จังหวัด | เปิดหน้าจังหวัดขอนแก่น | ดึง Banner ที่มีสิทธิ์แสดงจังหวัดขอนแก่น ไม่ใช้จังหวัดอื่นมาเติม |
| BNP-03 | หมวดน่าอยู่ | Banner น่าอยู่ของจังหวัดปัจจุบันผ่านเงื่อนไข | รวมเข้า Candidate ร่วมกับหมวดอื่น ไม่ใช้กฎตัดน่าอยู่ของ Center |

### 10.2 นิยามและสูตรรายภาษา

กำหนด L เป็นภาษาไทย จีน หรืออังกฤษ ต้องคำนวณสูตรนี้แยก L ทีละภาษา

| ตัวแปร | ความหมาย / วิธีรวม |
|--------|--------------------|
| IMP_AB_A[L] | ผลรวม Impression สำหรับ A/B ฝั่ง A ของภาษา L จาก Desktop + Mobile โดยแต่ละอุปกรณ์ใช้ข้อมูลตั้งแต่รีเซ็ตล่าสุดของตน |
| CLICK_AB_A[L] | ผลรวม Click สำหรับ A/B ฝั่ง A ในขอบเขตเดียวกัน |
| IMP_AB_B[L] / CLICK_AB_B[L] | รวมแบบเดียวกันแต่ใช้ฝั่ง B ของภาษา L |
| CTR_AB_A[L] / CTR_AB_B[L] | CTR ของแต่ละฝั่งในภาษา L จากยอดรวม Click ÷ Impression ไม่ใช่ค่าเฉลี่ย CTR ของอุปกรณ์ |
| RAW_P_A[L] | น้ำหนัก A ก่อนจำกัดช่วงของภาษา L |
| P_A[L] / P_B[L] | น้ำหนักเลือกภาพ A/B ของภาษา L ใช้ร่วมบน Desktop และ Mobile เมื่อมีภาพครบสองฝั่ง |
| CTR Performance | สถิติผลการแสดงจริงตามประวัติกราฟฟิก เก็บไว้เมื่อเปลี่ยนภาพ และไม่นำมาแทน input A/B หลังรีเซ็ต |

ใช้สูตรเมื่อ Impression รวมของ A และ B ในภาษา L มากกว่า 0 และ CTR_AB_A[L] + CTR_AB_B[L] มากกว่า 0

```text
CTR_AB_A[L] = (CLICK_AB_A[L] / IMP_AB_A[L]) × 100
CTR_AB_B[L] = (CLICK_AB_B[L] / IMP_AB_B[L]) × 100

RAW_P_A[L] = CTR_AB_A[L] / (CTR_AB_A[L] + CTR_AB_B[L]) × 100
P_A[L] = MAX(30, MIN(70, RAW_P_A[L]))
P_B[L] = 100 - P_A[L]
```

หากภาษา L คำนวณไม่ได้ตามเงื่อนไขข้างต้น ให้ P_A[L] = 50 และ P_B[L] = 50 คำนวณจากค่าจริงก่อนแสดงทศนิยมในตัวอย่าง

| CTR A ของภาษา L | CTR B ของภาษา L | สัดส่วนดิบ A : B | น้ำหนักใช้จริง A : B |
|-----------------|-----------------|------------------|----------------------|
| 3%              | 2%              | 60:40            | 60:40                |
| 9%              | 1%              | 90:10            | 70:30                |
| 1%              | 9%              | 10:90            | 30:70                |
| 2%              | 2%              | 50:50            | 50:50                |
| 0% โดยมี Impression | 2%              | 0:100            | 30:70                |
| 2%              | 0% โดยมี Impression | 100:0            | 70:30                |
| 0%              | 0%              | หารด้วยศูนย์ไม่ได้ | 50:50 เฉพาะภาษา L    |
| ฝั่งใดมี Impression รวมเป็น 0 | —               | CTR ยังไม่ครบสองฝั่ง | 50:50 เฉพาะภาษา L    |

น้ำหนักเป็นโอกาสเลือกภาพตอนจัดชุดใหม่ ไม่ใช่จำนวนครั้งที่รับประกัน ไม่ใช่ให้ฝั่ง CTR สูงแสดง 100% และไม่ใช้ CTR ไปเรียงลำดับ Slot แทน Shuffle

**ขอบเขตข้อมูลน้อย:** การแยกภาษาทำให้แต่ละภาษาสะสมข้อมูลของตน รอบนี้ยังไม่กำหนดจำนวน Impression/Click ขั้นต่ำเพิ่มเติม ใช้กฎเริ่มใหม่และกรณีคำนวณไม่ได้ข้างต้น ไม่เพิ่มเกณฑ์รอข้อมูลขึ้นเอง หากต้องการขั้นต่ำเพื่อประเมินความเชื่อมั่น ต้องกำหนดเป็นกฎเพิ่มเติมก่อนนำไปใช้

## EP-11 จำลองคำนวณ CTR ของ Banner แยกภาษา

ตัวอย่างชุดนี้แยกจากสถานการณ์ EP-07 เป็นข้อมูล A/B ของ Banner Source SX เท่านั้น รวมเหตุการณ์จริงของ Source นี้จากจุดวางที่มีสิทธิ์ตามเกณฑ์นับเดิม แต่ไม่รวม Top Banner และไม่รวม Source อื่น

| ภาษา | A: Click / Impression รวม Desktop+Mobile | CTR A | B: Click / Impression รวม Desktop+Mobile | CTR B | น้ำหนัก A:B |
|------|------------------------------------------|-------|------------------------------------------|-------|-------------|
| ไทย  | 400 / 10,000                             | 4%    | 200 / 10,000                             | 2%    | ประมาณ 66.67:33.33 |
| จีน  | 10 / 1,000                               | 1%    | 50 / 1,000                               | 5%    | 30:70 หลังจำกัดช่วง |
| อังกฤษ | 30 / 1,000                               | 3%    | 30 / 1,000                               | 3%    | 50:50       |

ไทย: 4 ÷ (4+2) × 100 = ประมาณ 66.67%; จีน: 1 ÷ (1+5) × 100 = ประมาณ 16.67% จึงจำกัด A=30%, B=70%; อังกฤษได้ 50:50

| เหตุการณ์ | ภาพ/น้ำหนักที่ใช้ |
|-----------|-------------------|
| เว็บไทย ภาพไทย A/B ครบ | ใช้ไทยประมาณ 66.67:33.33 ทั้ง Desktop/Mobile |
| เว็บจีน ภาพจีน A/B ครบ | ใช้จีน 30:70 ทั้งสองอุปกรณ์ ไม่ใช้น้ำหนักไทย |
| เว็บอังกฤษ Mobile ไม่มีอังกฤษ แต่มีไทย A/B | ใช้ไทยประมาณ 66.67:33.33 นับ input ให้ไทย Mobile ที่แสดงจริง ไม่ลง input อังกฤษซ้ำ |
| เว็บจีนมีจีน B ภาพเดียว | ใช้จีน B 100% แม้น้ำหนักจีนเก็บไว้ 30:70 |
| Banner SX ได้ตำแหน่งทั้งบนและล่าง | แต่ละจุดเลือกภาพของตนด้วยน้ำหนัก Source+ภาษาเดียวกัน ผลอาจเหมือนหรือต่างกันได้ |

การเก็บภาษาเว็บไซต์และภาษาภาพจริงแยกกันทำให้ดูผลรายภาษาได้ ไทยสำรองลง input ไทยเพียงครั้งเดียวต่อเหตุการณ์จริง ไม่ใช่กฎตัดสถิติซ้ำของ Source ข้ามจุดวาง การนับ Impression/Click คงเกณฑ์เดิมของระบบ

## EP-12 จำลองการเปลี่ยนภาพและรีเซ็ตเฉพาะภาษาที่เกี่ยวข้อง

ใช้ข้อมูล SX จาก EP-11 สมมติ **เปลี่ยนภาพจีน–Mobile ฝั่ง A เพียงภาพเดียว** ส่วนภาพคู่อื่นไม่เปลี่ยน

### 12.1 สิ่งที่เปลี่ยนทันที

| รายการ | ก่อนแก้ภาพ | หลังแก้ภาพสำเร็จ |
|--------|------------|------------------|
| input A/B จีน–Mobile ฝั่ง A | IMP 500 / Click 5 | เริ่มรอบคำนวณใหม่จาก 0 / 0 |
| input A/B จีน–Mobile ฝั่ง B | IMP 500 / Click 25 | เริ่มรอบคำนวณใหม่จาก 0 / 0 ด้วย แม้ไม่ได้แก้ไฟล์ B |
| input จีน–Desktop | A = 5/500; B = 25/500 ในรูป Click/IMP | คงเดิม ใช้รวมเฉพาะภาษาจีนในรอบถัดไป |
| input อีก 4 คู่ของไทยและอังกฤษ | ตาม EP-11  | คงเดิม ไม่ย้ายมารวมคำนวณจีน |
| น้ำหนักจีน | 30:70      | 50:50 ทันทีจนถึงรอบรายวันถัดไป |
| น้ำหนักไทย | ประมาณ 66.67:33.33 | คงเดิม           |
| น้ำหนักอังกฤษ | 50:50      | คงเดิม ไม่ถูกรีเซ็ตตามภาษาจีน |
| Performance จริงของภาษาจีนก่อนแก้ | A = 10/1,000; B = 50/1,000 ในรูป Click/IMP | เก็บไว้ครบ ไม่เปลี่ยนเป็น 0 |
| ชุดสไลด์ที่เลือกไว้แล้ว | มีภาพต่อ Slot ตามชุดนั้น | คงเดิมระหว่างเลื่อน/Loop น้ำหนักใหม่ใช้เมื่อจัดชุดใหม่ |

การรีเซ็ต input ไม่ใช่การลบประวัติ Performance และไม่เอา input จีน–Mobile ก่อนรีเซ็ตกลับมาคำนวณน้ำหนักรอบใหม่

### 12.2 เส้นเวลาตัวอย่าง

| เวลา / เหตุการณ์ | น้ำหนักจีนสำหรับชุดใหม่ | ไทยและอังกฤษ |
|------------------|-------------------------|--------------|
| ก่อนแก้ภาพ       | 30:70                   | ใช้ค่าของตนตาม EP-11 |
| 4 พ.ย. เวลา 12:00 น. แก้จีน–Mobile A สำเร็จ | 50:50 ทันที             | คงเดิม       |
| หลังแก้และก่อนรอบรายวันถัดไป | ยังใช้ 50:50 แม้มีข้อมูลสะสมเพิ่ม | คงค่าล่าสุดของตน ไม่คำนวณข้ามภาษา |
| หลัง 00:00 น. วันที่ 5 พ.ย. ถึงรอบคำนวณ | รวมจีน Desktop + จีน Mobile หลังรีเซ็ตล่าสุดของแต่ละคู่ แล้วคำนวณใหม่ | แต่ละภาษาคำนวณจากข้อมูลตนตามรอบรายวัน |
| มีการแก้ภาพจีนอีกครั้ง | กลับ 50:50 จนรอบรายวันถัดไปอีกครั้ง | ไม่รีเซ็ตตาม |

**หากจีน–Mobile ยังไม่มีข้อมูลใหม่เมื่อถึงรอบรายวัน:** จีน–Desktop ยังมี CTR A = 5/500 = 1% และ B = 25/500 = 5% จึงคำนวณน้ำหนักจีนได้ **30:70 หลังจำกัดช่วง** ไม่ต้องรอให้ทั้งสองอุปกรณ์มีข้อมูล และไม่นำไทยหรืออังกฤษมาเติม ผลนี้ใช้เมื่อถึงรอบรายวัน ไม่ใช่ทันทีหลังแก้ภาพ

### 12.3 กรณีมีข้อมูลใหม่ก่อนรอบรายวัน

สมมติจีน–Mobile หลังแก้มี A = IMP 200 / Click 12 และ B = IMP 200 / Click 2 ส่วนจีน–Desktop ไม่มีข้อมูลเพิ่ม

| ข้อมูล A/B ภาษาจีน | IMP A | Click A | IMP B | Click B |
|--------------------|-------|---------|-------|---------|
| จีน–Desktop ที่ไม่ได้รีเซ็ต | 500   | 5       | 500   | 25      |
| จีน–Mobile หลังรีเซ็ต | 200   | 12      | 200   | 2       |
| รวมใช้คำนวณน้ำหนักจีน | 700   | 17      | 700   | 27      |

| ขั้นตอน | ผลลัพธ์ |
|---------|---------|
| CTR_AB_A[ZH] = 17 ÷ 700 × 100 | ประมาณ 2.428571% |
| CTR_AB_B[ZH] = 27 ÷ 700 × 100 | ประมาณ 3.857143% |
| RAW_P_A[ZH] = CTR A ÷ (CTR A + CTR B) × 100 | ประมาณ 38.636364% |
| น้ำหนักจีนหลังจำกัดช่วง | ประมาณ 38.64:61.36 |
| น้ำหนักไทยและอังกฤษ หากข้อมูลไม่เพิ่มจากตัวอย่าง | ไทยประมาณ 66.67:33.33 และอังกฤษ 50:50 |

Performance ภาษาจีนในตัวอย่างยังสะสมประวัติก่อนแก้: A = 22/1,200 หรือ CTR ประมาณ 1.8333%; B = 52/1,200 หรือ CTR ประมาณ 4.3333% การนำค่านี้มาแทน input หลังรีเซ็ตจะได้น้ำหนักหลังจำกัดช่วง 30:70 ซึ่งไม่ตรงผลที่ต้องใช้ประมาณ 38.64:61.36 จึงต้องแยกข้อมูลสองส่วนนี้

หากแก้หลายคู่ ให้เริ่ม input ทั้ง A/B เฉพาะคู่ที่แก้ และตั้ง 50:50 เฉพาะภาษาที่มีการแก้ เช่น แก้ไทย Mobile กับจีน Desktop จะรีเซ็ตน้ำหนักไทยและจีน ส่วนอังกฤษคงเดิม หากแก้ครบทั้ง 6 คู่จะเริ่ม input ใหม่ทุกคู่และเริ่มน้ำหนักทั้ง 3 ภาษาใหม่ที่ 50:50 โดยยังเก็บ Performance

## EP-14 ภาพจำลองและแนวทางส่งต่อ

ภาพใช้ข้อมูล EP-07 เพื่ออธิบายการคัดจังหวัด หมวดน่าอยู่ Shuffle รายจุดและการซ้ำข้ามจุด ไม่ใช่ภาพหน้าจอระบบจริง

 ![ภาพจำลองสูตร A/B แยกภาษาและรีเซ็ตเฉพาะคู่ที่แก้](https://wiki.infonayoo.co/api/attachments.redirect?id=67ab5cac-2182-4de8-9f33-b00a756f54be)

### 14.3 แนวทางทางเทคนิค — ข้อเสนอ ไม่ใช่ผลตรวจ implementation

| เรื่อง | แนวทางที่เสนอ |
|--------|---------------|
| ตัวระบุสถิติ | แยก Product=Banner, Source Slot, ภาษาภาพ, อุปกรณ์, ทางเลือกและรุ่นภาพ พร้อมจุดวางเพื่อวิเคราะห์ โดยไม่อ้างชื่อ field/API จริง |
| Performance กับ A/B | เก็บจุดเริ่มคำนวณรายคู่แยกจากประวัติจริง ไม่ลบ Performance เมื่อแก้ภาพ |
| ภาพไทยสำรอง | เก็บภาษาเว็บไซต์และภาษาภาพจริงแยกกัน คำนวณ A/B ตามภาพจริง ไม่ลงเหตุการณ์เดียวเป็น input ทั้งไทยและภาษาหน้าเว็บ |
| งานคำนวณชนกับแก้ภาพ | ป้องกันผลคำนวณก่อนแก้มาเขียนทับน้ำหนัก50:50ล่าสุดของภาษาที่แก้ |
| ชุดรายจุดวาง | เก็บลำดับ Source และภาพที่เลือกไว้ต่อจุดเพื่อคงระหว่างเลื่อน ไม่สร้างกฎให้ผล A/B ของ Source เดียวต้องเหมือนทั้งหน้า |
| นิยาม Impression/Click | ยึดเกณฑ์เหตุการณ์เดิม ไม่สร้างเวลาเห็นภาพขั้นต่ำหรือการกันซ้ำข้ามจุดขึ้นใหม่ในเอกสารนี้ |

**ขอบเขตในอนาคต:** รอบนี้มีเพียง A/B สองทางเลือกต่อภาษา ไม่เพิ่มจำนวนทางเลือกตามจำนวนภาษา หากเพิ่มมากกว่าสองต้องกำหนดกฎน้ำหนักใหม่ก่อน และไม่ยกขั้นต่ำ30%ไปใช้กับ4ทางเลือกเพราะรวมขั้นต่ำจะเป็น120%
