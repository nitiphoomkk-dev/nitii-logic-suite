**Solution Banner จังหวัด — แบบที่ 1 รวม 3 ภาษาและทุกอุปกรณ์ก่อนคำนวณ A/B**

ฉบับ 1.0 · 4 พฤศจิกายน 2569 · ผู้จัดทำ: นิติ๊ · สถานะ: Solution ตามคำตัดสินผู้ใช้สำหรับ Dev และ Tester

**เป้าหมาย:** ใช้ผลรวม Click/Impression ของไทย จีน อังกฤษ และ Desktop/Mobile ภายใน Banner Source Slot เดียวกัน เพื่อคำนวณน้ำหนัก A/B เพียงหนึ่งชุด แล้วใช้ชุดน้ำหนักนั้นกับทุกภาษาและทุกจุดวางของ Source เดียวกัน โดยยังดูรายงาน CTR แยกภาษาได้

คำสั่งผู้ใช้ครั้งนี้เลือก **แบบที่ 1** แทนวิธีแยกน้ำหนักรายภาษาของ [Solution Banner จังหวัดฉบับก่อน](https://wiki.infonayoo.co/doc/solution-banner-3-ab-ctr-shuffle-slot-wU9RYIkYJt) ไม่ได้แก้ไขต้นทางเดิม เอกสารใหม่นี้คงผัง Banner จังหวัด สูงสุด3 Source Slotต่อจุดวาง ไทยบังคับ/ไทยสำรอง ขนาดและวิธีเลื่อนเดิม และไม่รวมข้อมูลกับ Top Banner หรือ Pop-up

**หนึ่ง Source Slot = หนึ่งน้ำหนักรวม A:B** ไม่ใช่น้ำหนักเดียวร่วมทุกบริษัท ทุกจังหวัด หรือทุก Product ตัวเลขและภาพจำลองเป็นข้อมูลสมมติ ไม่ใช่ผลทดสอบระบบจริง

## EP-01 ขอบเขตและเงื่อนไขการแสดงผล


1. ดึง Banner ของจังหวัดที่ผู้ใช้กำลังใช้งาน รวมหมวดน่าอยู่ แล้วคัดเฉพาะรายการที่เปิดแสดง อยู่ในช่วงเวลา มีภาพตรงอุปกรณ์ และมีสิทธิ์แสดงได้ทุกจุดบนหน้านั้น
2. สุ่มเลือก Banner **สูงสุด 3 รายการ** เป็นชุดเดียวสำหรับทั้งหน้า หากมีไม่ครบให้แสดงเท่าที่มี
3. แต่ละรายการเลือกภาพตามภาษาที่ผู้ใช้เลือก หากไม่มีให้ใช้ภาพไทยสำรอง ถ้ามีทั้ง A/B ให้สุ่มเลือก **หนึ่งภาพตามน้ำหนักล่าสุด**
4. ทุกจุดวางใช้ **Banner ชุดเดียวกันและภาพเดียวกัน** แต่สุ่มลำดับแยกกัน เช่น จุดบนแสดง A → B → C ส่วนจุดล่างแสดง C → A → B
5. ระหว่างเลื่อนหรือวนสไลด์ ให้ใช้ชุด ลำดับ และภาพเดิม **ไม่สุ่มใหม่ทุกครั้งที่เลื่อน**
6. เมื่อเปลี่ยนหน้าหรือย้อนกลับ ให้ใช้ **รายการและภาพที่จัดไว้ของหน้าปลายทาง** หากเงื่อนไขยังเหมือนเดิม แล้วสุ่มเฉพาะลำดับใหม่แยกแต่ละจุดครับ

### **7.1 ตัวอย่างจังหวัดเดียวกัน ภาษาอังกฤษ Mobile**

**Candidate SX, S2, S3, S4 ผ่านสิทธิ์ครบทุกจุด สมมติ Shuffle เลือกชุดร่วม SX / S2 / S3 โดย SX มีอังกฤษ A/B ใช้น้ำหนักรวม 61.11:38.89 และผลเลือกได้ EN-B; S2 ไม่มีอังกฤษ ใช้ไทยสำรองและเลือกได้ TH-A; S3 มีอังกฤษ A ภาพเดียว ใช้ EN-A 100%**

| **จุดวาง** | **สมาชิกชุดร่วม** | **ตัวอย่างลำดับ Carousel และภาพ** |
|--------|---------------|-------------------------------|
| **บน** | **SX / S2 / S3** | **SX EN-B → S2 TH-A → S3 EN-A** |
| **ล่าง** | **SX / S2 / S3** | **S3 EN-A → SX EN-B → S2 TH-A** |
| **กลาง — เฉพาะหน้าที่มี 3 จุด** | **SX / S2 / S3** | **S2 TH-A → S3 EN-A → SX EN-B** |

**SX ทุกจุดต้องเป็น EN-B เหมือนกัน S2 ทุกจุดเป็น TH-A และ S3 ทุกจุดเป็น EN-A การใช้ไทยสำรองของ S2 ไม่เปลี่ยนภาษาเว็บไซต์ และไม่เพิ่ม Source หรือภาพที่เหลือเข้ามาเป็นสไลด์ใหม่**

| **เวลาตัวอย่างเมื่อสองจุดเริ่มพร้อมกัน** | **บน** | **ล่าง** |
|--------------------------------------|-----|------|
| **0 วินาที**                         | **SX EN-B** | **S3 EN-A** |
| **4 วินาที**                         | **S2 TH-A** | **SX EN-B** |
| **8 วินาที**                         | **S3 EN-A** | **S2 TH-A** |
| **12 วินาที**                        | **กลับ SX EN-B ภาพเดิม** | **กลับ S3 EN-A ภาพเดิม** |

**เวลาเป็นตัวอย่าง ไม่บังคับว่าทุกจุดต้องเริ่มพร้อมกัน 3 Source × 2 จุด = 6 ช่องแสดง แต่ยังเป็น Source ต่างกันเพียง 3 รายการ ไม่ใช่ 6 รายการ**

### **7.2 สิทธิ์แต่ละจุดต่างกัน**

**ถ้า Source A ใช้ได้ทุกจุด แต่ B ใช้ได้เฉพาะจุดบน ให้ A เข้าชุดได้ ส่วน B ไม่เข้าชุดร่วม ไม่ใส่ B เฉพาะจุดบน จำนวนร่วมจึงอาจไม่ครบ 3 ทุกจุดต้องใช้สมาชิกชุดเดียวกันเสมอ**

### **7.3 หน้า 1 → หน้า 2 → กลับหน้า 1**

**สมมติหน้า 1 จัดชุด SX / S2 / S3 ไว้แล้ว และหน้า 2 จัดชุด SX / S3 / S4 ไว้แล้ว ชุดของสองหน้าอาจเหมือนกันได้ ไม่บังคับให้สมาชิกต่างกัน**

| **การกระทำ** | **จุดบน** | **จุดล่าง** |
|----------|-------|---------|
| **เปิดหน้า 1** | **SX → S2 → S3** | **S3 → SX → S2** |
| **ไปหน้า 2** | **S4 → SX → S3** | **SX → S3 → S4** |
| **กลับหน้า 1** | **S2 → S3 → SX** | **SX → S2 → S3** |

**เมื่อกลับหน้า 1 ให้คง SX / S2 / S3 และภาพที่เลือกไว้ของชุดหน้า 1 แต่ Shuffle ลำดับแยกจุดใหม่ ไม่เอา S4 จากหน้า 2 มาแทนสมาชิกเพียงเพราะเปลี่ยนหน้า ส่วน Refresh หรือเปลี่ยนภาษาให้ประเมินและเลือกชุดร่วมใหม่ตาม EP-06**

นิยามcเป็นหนึ่งใน6คู่ภาษา–อุปกรณ์ของSourceเดียวกัน ยอดแต่ละคู่ใช้ข้อมูลตั้งแต่resetล่าสุดของคู่นั้น

```text
CLICK_A_TOTAL = SUM(CLICK_A[c])
IMP_A_TOTAL   = SUM(IMP_A[c])
CLICK_B_TOTAL = SUM(CLICK_B[c])
IMP_B_TOTAL   = SUM(IMP_B[c])

CTR_A_TOTAL = CLICK_A_TOTAL / IMP_A_TOTAL × 100
CTR_B_TOTAL = CLICK_B_TOTAL / IMP_B_TOTAL × 100
RAW_A = CTR_A_TOTAL / (CTR_A_TOTAL + CTR_B_TOTAL) × 100
P_A = MAX(30, MIN(70, RAW_A))
P_B = 100 - P_A
```

ใช้สูตรเมื่อIMPรวมAและBมากกว่า0 และCTRรวมA+CTRรวมBมากกว่า0 มิฉะนั้นP_A=P_B=50 คำนวณด้วยค่าจริงก่อนย่อทศนิยมเพื่อแสดงผล

| น้ำหนักดิบA | MIN(70, ดิบA) | MAX(30, ผลก่อนหน้า) | น้ำหนักใช้จริงA:B |
|-------------|---------------|---------------------|-------------------|
| 90%         | 70            | 70                  | 70:30             |
| 10%         | 10            | 30                  | 30:70             |
| 60%         | 60            | 60                  | 60:40             |

**70:30เป็นขอบเขต ไม่ใช่สัดส่วนตายตัวทุกวัน** และเป็นโอกาสสุ่ม ไม่รับประกันA7/B3ในทุก10ครั้ง ไม่ใช้CTRมาเรียงSourceแทนShuffle ไม่เพิ่มเกณฑ์IMPขั้นต่ำหรือการทดสอบนัยสำคัญที่ต้นทางยังไม่กำหนด

## EP-11 จำลองการคำนวณรวมและการรายงานภาษา

### 11.1 ข้อมูลของBanner Source SX

ตัวเลขทั้งหมดเป็นข้อมูลสมมติในขอบเขตinputหลังresetล่าสุดของแต่ละคู่ รายงานตารางนี้รวมDesktop/Mobileในภาษาเดียวกันไว้แล้ว

| ภาษาภาพ | A Click/IMP | CTR Aรายงานภาษา | B Click/IMP | CTR Bรายงานภาษา |
|---------|-------------|-----------------|-------------|-----------------|
| ไทย     | 400/10,000  | 4%              | 200/10,000  | 2%              |
| จีน     | 10/1,000    | 1%              | 50/1,000    | 5%              |
| อังกฤษ  | 30/1,000    | 3%              | 30/1,000    | 3%              |
| รวมSource | 440/12,000  | 3\.666667%      | 280/12,000  | 2\.333333%      |

```text
CTR A รวม = 440 / 12,000 × 100 = 3.666667%
CTR B รวม = 280 / 12,000 × 100 = 2.333333%
RAW_A = 3.666667 / (3.666667 + 2.333333) × 100 = 61.111111%
น้ำหนักใช้จริงของ SX = A 61.11% : B 38.89%
```

คำนวณจากเศษส่วนจริงก่อนย่อทศนิยม ไม่ใช้ตัวเลข3.67และ2.33ที่ปัดเพื่อแสดงมาคำนวณต่อ

| บริบทที่เลือกภาพSX | น้ำหนักที่ใช้เมื่อมีA/Bครบ | ข้อมูลที่ลงinputเมื่อเกิดเหตุการณ์จริง |
|--------------------|----------------------------|----------------------------------------|
| ไทยDesktop/Mobile  | 61\.11:38.89               | ไทยและอุปกรณ์จริง                      |
| จีนDesktop/Mobile  | 61\.11:38.89               | จีนและอุปกรณ์จริง                      |
| อังกฤษDesktop/Mobile | 61\.11:38.89               | อังกฤษและอุปกรณ์จริง                   |
| เว็บอังกฤษ แต่ไม่มีอังกฤษและใช้ไทยสำรอง | 61\.11:38.89               | ไทยและอุปกรณ์จริง ไม่ลงอังกฤษซ้ำ       |
| SXได้ตำแหน่งทั้งบนและล่าง | ทั้งสองจุด61.11:38.89 ผลสุ่มอาจต่างกัน | แต่ละเหตุการณ์จริงพร้อมจุดวางตามเกณฑ์เดิม |
| ภาษาปัจจุบันมีเพียงA/เพียงBที่ใช้ได้ | ภาพที่มี100%               | ภาพจริงและอุปกรณ์จริง                  |

จีนBมีCTRรายงาน5%สูงกว่าจีนA1% แต่ยังใช้น้ำหนักรวมSX61.11:38.89 ไม่ใช้30:70เฉพาะจีน นี่เป็นผลของการเลือกแบบที่1 ไม่ใช่ข้อผิดพลาดของสูตร

### 11.2 รายงานยังแยกภาษาได้

การใช้น้ำหนักร่วมไม่ได้บังคับให้ลบรายละเอียดรายภาษา สามารถรวมรายงานหรือแสดงรายภาษา/อุปกรณ์/ทางเลือก/จุดวางจากข้อมูลเหตุการณ์ที่เก็บไว้ แต่ไม่นำCTRของแถวรายภาษามาตั้งweightแยกอีกครั้ง การรายงานตามภาษาภาพจริงต่างจากรายงานตามภาษาเว็บไซต์เมื่อมีไทยสำรอง จึงต้องระบุขอบเขตรายงานให้ชัด
