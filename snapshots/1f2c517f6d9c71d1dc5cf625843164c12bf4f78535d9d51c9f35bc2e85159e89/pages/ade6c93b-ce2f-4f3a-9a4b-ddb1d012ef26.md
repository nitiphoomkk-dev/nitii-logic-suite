## EP-03 การเลือกภาษาและอุปกรณ์ — ทุก Slot ต้องมีภาพไทย

**เงื่อนไขข้อมูล:** ทุก Slot ที่นำมาเลือกแสดงต้องมีภาพภาษาไทยที่ใช้ได้อย่างน้อย 1 ทางเลือก คือ A หรือ B บนอุปกรณ์ที่นำมาแสดง ภาษาไทยเป็นภาษาบังคับ จีนและอังกฤษเป็นภาษาที่เพิ่มได้ การมีไทยบังคับไม่ได้หมายความว่าต้องมีทั้ง A และ B ครบสองภาพ

**ใช้ภาพภาษาที่ผู้ใช้เลือกก่อน → หากไม่มี ให้ใช้ไทยของ Slot เดิมบนอุปกรณ์ปัจจุบัน**

การไม่มีจีนหรืออังกฤษไม่ทำให้ Slot ที่มีไทยบังคับหลุดจากชุดแสดงผล

## EP-04 Shuffle Slot และเลือก A/B ตาม CTR ช่วง 30–70%

### 4.1 Shuffle ระดับ Slot

| รหัส | หัวข้อ | เงื่อนไข / การกระทำ | Logic การทำงาน |
|------|--------|---------------------|----------------|
| TBP-S01 | หน่วย Shuffle | เตรียมชุด Slot ที่ผ่านเงื่อนไข | แต่ละ Slot เข้า Shuffle เพียงหนึ่งรายการ แม้มี A/B ครบและมีครบสามภาษา |
| TBP-S02 | จำนวนที่นำมาใช้ | Shuffle Candidate สำเร็จ | เลือกไม่เกิน 8 รายการแรกตามลำดับหลัง Shuffle ไม่จำกัดชุด Candidate เหลือ 8 ก่อนสุ่ม |
| TBP-S03 | ประเภทและภาษาสำรอง | Candidate มีหมวดน่าอยู่และหมวดอื่นที่มีสิทธิ์ | รวม Candidate ในชุดเดียวก่อน Shuffle และเลือกไม่เกิน 8 ไม่จัดน่าอยู่หรือ Slot ที่ใช้ไทยสำรองไว้ท้ายเป็นพิเศษ |
| TBP-S04 | การซ้ำ | จัดชุดแสดงผลหนึ่งรอบ | Slot เดิมอยู่ได้เพียงหนึ่งตำแหน่ง ไม่นำอีกภาษา อีกทางเลือก หรือไฟล์อีกอุปกรณ์มาแตกเป็น Slot เพิ่ม |
| TBP-S05 | แยกจาก A/B | Shuffle ลำดับ Slot  | Shuffle ใช้สุ่มลำดับ Slot ส่วนน้ำหนัก A/B ใช้เลือกภาพ A หรือ B ภายใน Slot นั้น โดยไม่เปลี่ยนจำนวนหรือลำดับ Slot ที่เลือกไว้ |

### 4.2 เลือกภาพภายในแต่ละ Slot

## EP-05 จำนวนและการแสดงผล — สูงสุด 8 Slot

กำหนด **S = จำนวน Candidate ของจังหวัดปัจจุบันที่ผ่านสถานะ เวลา สิทธิ์ และมีภาพไทยบังคับตรงอุปกรณ์แล้ว**

กำหนด **M = MIN(S, 8)** เป็นจำนวน Slot ที่เลือกเข้าชุดแสดงผลหลัง Shuffle

**จำนวน Slot ในชุดแสดงผล = M และจำนวนภาพในชุดสไลด์ = M**

| Candidate ที่ผ่านเงื่อนไข S | Slot ที่เลือกแสดง M | จำนวนภาพในชุดสไลด์ |
|-----------------------------|---------------------|--------------------|
| 0                           | 0                   | 0                  |
| 1                           | 1                   | 1                  |
| 7                           | 7                   | 7                  |
| 8                           | 8                   | 8                  |
| 9                           | 8                   | 8                  |
| 10                          | 8                   | 8                  |
| 12                          | 8                   | 8                  |
| 20                          | 8                   | 8                  |
| N                           | MIN(N, 8)           | MIN(N, 8)          |

**สูงสุด 8 ไม่ใช่บังคับครบ 8:** หากมี Candidate น้อยกว่า 8 ให้แสดงตามจำนวนจริง ไม่ทำสำเนา Slot ไม่แตกอีกภาษา/A/B เป็นภาพเพิ่ม และไม่ดึงจังหวัดอื่นมาเติม

|------|---------------------|-----------------|
| TBP-D01 | ไม่มี Candidate ผ่านเงื่อนไข | ไม่มีภาพ Top Banner ให้แสดง ไม่สร้างภาพทดแทนหรือดึงจังหวัดอื่นมาเติม การจัดพื้นที่ว่างใช้ UI เดิม |
| TBP-D02 | มี Candidate หนึ่งรายการ | แสดงหนึ่ง Slot หนึ่งภาพ ไม่ทำสำเนาเพิ่ม |
| TBP-D03 | มี Candidate มากกว่าหนึ่งรายการ | Shuffle Candidate ทั้งหมดก่อนเลือกไม่เกิน 8 Slot แสดงเป็นสไลด์และเลื่อนดูครบเฉพาะ Slot ในชุดที่เลือก |
| TBP-D04 | เลื่อนครบภาพสุดท้าย | วนกลับภาพแรกของชุดเดิม คงภาพและลำดับ ไม่ดึง Slot นอกชุดหรือ A/B อีกภาพมาแทรก |
| TBP-D05 | มีภาพ Desktop/Mobile | Desktop ใช้ 4,038 × 1,440 px; Mobile ใช้ 1,074 × 603 px ตามเดิม |
| TBP-D06 | ชุดมีมากกว่าหนึ่งภาพและ Auto Slide ทำงาน | เลื่อนภาพถัดไปทุก 4 วินาทีตามเดิม |
| TBP-D07 | ผู้ใช้กดเลื่อนซ้ายหรือขวา | เลื่อนภายในชุดเดิม ไม่ Shuffle หรือเลือก A/B ใหม่ |
| TBP-D08 | ภาพที่แสดงมีลิงก์แนบ | เปิดลิงก์ที่ผูกกับภาพ/ทางเลือกที่แสดงจริงในแท็บใหม่ รวมกรณีไทยสำรอง |
| TBP-D09 | ภาพที่แสดงไม่มีลิงก์แนบ | ไม่เปิดปลายทางจากภาพหรือทางเลือกอื่นมาแทน |

### 7.2 มี Candidate เกิน 8 Slot

จังหวัดขอนแก่นมี Candidate ที่ผ่านเงื่อนไขและมีไทยบังคับ **12 Slot** คือ S1–S12

ตัวอย่างลำดับหลัง Shuffle: **S8 → S3 → S12 → S1 → S6 → S10 → S2 → S11 → S4 → S9 → S5 → S7**

เลือก **8 Slot แรก** คือ S8, S3, S12, S1, S6, S10, S2 และ S11 แต่ละ Slot เลือกภาษาหลักหรือไทยสำรอง แล้วเลือก A/B เพียงหนึ่งภาพ

ชุดนี้จึงมี **8 ภาพ** เมื่อเลื่อนครบ S11 ให้กลับ S8 ไม่เลื่อนไป S4/S9/S5/S7 ที่อยู่นอกชุด การ Refresh หรือจัดชุดใหม่ครั้งถัดไปอาจเลือกได้คนละชุด หากมี Candidate เพียง 5 Slot ให้แสดง 5 ภาพ ไม่เติมให้ครบ 8

### 10.2 นิยามและสูตรรายภาษา

กำหนด L เป็นภาษาไทย จีน หรืออังกฤษ ต้องคำนวณสูตรนี้แยก L ทีละภาษา

| ตัวแปร | ความหมาย / วิธีรวม |
|--------|--------------------|
| IMP_AB_A[L] | ผลรวม Impression สำหรับ A/B ฝั่ง A ของภาษา L จาก Desktop + Mobile โดยแต่ละอุปกรณ์ใช้ข้อมูลตั้งแต่รีเซ็ตล่าสุดของตน |
| CLICK_AB_A[L] | ผลรวม Click สำหรับ A/B ฝั่ง A ในขอบเขตเดียวกัน |
| IMP_AB_B[L] / CLICK_AB_B[L] | รวมแบบเดียวกันแต่ใช้ฝั่ง B ของภาษา L |
| CTR_AB_A[L] / CTR_AB_B[L] | CTR ของแต่ละฝั่งในภาษา L จากยอดรวม Click ÷ Impression ไม่ใช่ค่าเฉลี่ย CTR ของอุปกรณ์ |
| RAW_P_A[L] | น้ำหนัก A ก่อนจำกัดช่วงของภาษา L |
| P_A[L] / P_B[L] | น้ำหนักเลือกภาพ A/B ของภาษา L ใช้ร่วมบน Desktop และ Mobile เมื่อมีภาพครบสองฝั่ง |
| CTR Performance | สถิติผลการแสดงจริงตามประวัติกราฟฟิก เก็บไว้เมื่อเปลี่ยนภาพ และไม่นำมาแทน input A/B หลังรีเซ็ต |

ใช้สูตรเมื่อ Impression รวมของ A และ B ในภาษา L มากกว่า 0 และ CTR_AB_A[L] + CTR_AB_B[L] มากกว่า 0

```text
CTR_AB_A[L] = (CLICK_AB_A[L] / IMP_AB_A[L]) × 100
CTR_AB_B[L] = (CLICK_AB_B[L] / IMP_AB_B[L]) × 100

RAW_P_A[L] = CTR_AB_A[L] / (CTR_AB_A[L] + CTR_AB_B[L]) × 100
P_A[L] = MAX(30, MIN(70, RAW_P_A[L]))
P_B[L] = 100 - P_A[L]
```

หากภาษา L คำนวณไม่ได้ตามเงื่อนไขข้างต้น ให้ P_A[L] = 50 และ P_B[L] = 50 คำนวณจากค่าจริงก่อนแสดงทศนิยมในตัวอย่าง

* **กรณี A ชนะขาดลอย (ได้ 90%):**\n `MIN(70, 90)` ได้ 70 ➔ `MAX(30, 70)` ➔ **ได้ 70%** *(โดนล็อกเพดานบน ไม่ให้เกิน 70)*
* **กรณี A แพ้หลุดลุ่ย (ได้ 10%):**\n `MIN(70, 10)` ได้ 10 ➔ `MAX(30, 10)` ➔ **ได้ 30%** *(โดนช่วยดันขึ้นมา ไม่ให้ต่ำกว่า 30)*
* **กรณีคะแนนสูสี (ได้ 60%):**\n `MIN(70, 60)` ได้ 60 ➔ `MAX(30, 60)` ➔ **ได้ 60%** *(อยู่ในกรอบ 30–70 อยู่แล้ว ใช้ค่าจริงได้เลย)*

| CTR A ของภาษา L | CTR B ของภาษา L | สัดส่วนดิบ A : B | น้ำหนักใช้จริง A : B |
|-----------------|-----------------|------------------|----------------------|
| 3%              | 2%              | 60:40            | 60:40                |
| 9%              | 1%              | 90:10            | 70:30                |
| 1%              | 9%              | 10:90            | 30:70                |
| 2%              | 2%              | 50:50            | 50:50                |

น้ำหนักเป็นโอกาสเลือกภาพตอนจัดชุดใหม่ ไม่ใช่จำนวนครั้งที่รับประกัน ไม่ใช่ให้ฝั่ง CTR สูงแสดง 100% และไม่ใช้ CTR ไปเรียงลำดับ Slot แทน Shuffle

**ขอบเขตข้อมูลน้อย:** การแยกภาษาทำให้แต่ละภาษาสะสมข้อมูลของตน รอบนี้ยังไม่กำหนดจำนวน Impression/Click ขั้นต่ำเพิ่มเติม ใช้กฎเริ่มใหม่และกรณีคำนวณไม่ได้ข้างต้น ไม่เพิ่มเกณฑ์รอข้อมูลขึ้นเอง หากต้องการขั้นต่ำเพื่อประเมินความเชื่อมั่น ต้องกำหนดเป็นกฎเพิ่มเติมก่อนนำไปใช้

## EP-11 จำลองคำนวณและการแสดงผลแบบแยกภาษา

ตัวเลขทั้งหมดเป็นข้อมูลสมมติของ Slot S1 จังหวัดขอนแก่น ใช้ชุดเดียวกับภาพเปรียบเทียบที่ผู้ใช้เลือกแบบที่ 2 ไม่ใช่สถิติระบบจริง สมมติทุกภาษาใช้งานได้และข้อมูลอยู่ในขอบเขตหลังรีเซ็ตล่าสุดของแต่ละคู่

### 11.1 ข้อมูล A/B แยก 6 คู่

|------|---------|-------|---------|-------|---------|

| ไทย  | Mobile  | 5,000 | 200     | 5,000 | 100     |

### 11.2 รวมอุปกรณ์แล้วคำนวณแยกภาษา

| ภาษา | A: Click / IMP | CTR A | B: Click / IMP | CTR B | น้ำหนักดิบ A : B | น้ำหนักใช้จริง A : B |
|------|----------------|-------|----------------|-------|------------------|----------------------|
| ไทย  | 400 / 10,000   | 4%    | 200 / 10,000   | 2%    | 66\.6667:33.3333 | ประมาณ 66.67:33.33   |
| จีน  | 10 / 1,000     | 1%    | 50 / 1,000     | 5%    | 16\.6667:83.3333 | 30:70 หลังจำกัดช่วง  |
| อังกฤษ | 30 / 1,000     | 3%    | 30 / 1,000     | 3%    | 50:50            | 50:50                |

ตัวอย่างคำนวณจีน: A = 1 ÷ (1 + 5) × 100 = ประมาณ 16.6667% เมื่อจำกัดช่วงได้ A 30% และ B 70% ผลนี้ใช้ทั้งจีน Desktop และจีน Mobile

**ไม่ใช้ผลรวมน้ำหนักข้ามภาษา:** หากรวมทั้งสามภาษาจะได้ A = 440/12,000 และ B = 280/12,000 คิดเป็นน้ำหนักประมาณ 61.11:38.89 ซึ่งเป็นวิธีเดิมและไม่ใช่น้ำหนักที่ใช้เลือกภาพในฉบับนี้ การรวมยอดเพื่อดูภาพรวมรายงานไม่ทำให้น้ำหนักรายภาษาเปลี่ยนตาม

ห้ามเฉลี่ย CTR Desktop กับ Mobile ตรง ๆ ต้องรวม Click และ Impression ภายในภาษาเดียวกันก่อนหาร แม้แต่ละอุปกรณ์มีจำนวนแสดงไม่เท่ากัน

## EP-12 จำลองการเปลี่ยนภาพและรีเซ็ตเฉพาะภาษาที่เกี่ยวข้อง

ใช้ข้อมูล S1 จาก EP-11 สมมติ **เปลี่ยนภาพจีน–Mobile ฝั่ง A เพียงภาพเดียว** ส่วนภาพคู่อื่นไม่เปลี่ยน

### 12.1 สิ่งที่เปลี่ยนทันที

### 12.2 เส้นเวลาตัวอย่าง

|------------------|-------------------------|--------------|
| ก่อนแก้ภาพ       | 30:70                   | ใช้ค่าของตนตาม EP-11 |
| 4 พ.ย. เวลา 12:00 น. แก้จีน–Mobile A สำเร็จ | 50:50 ทันที             | คงเดิม       |

| หลัง 00:00 น. วันที่ 5 พ.ย. ถึงรอบคำนวณ | รวมจีน Desktop + จีน Mobile หลังรีเซ็ตล่าสุดของแต่ละคู่ แล้วคำนวณใหม่ | แต่ละภาษาคำนวณจากข้อมูลตนตามรอบรายวัน |

**หากจีน–Mobile ยังไม่มีข้อมูลใหม่เมื่อถึงรอบรายวัน:** จีน–Desktop ยังมี CTR A = 5/500 = 1% และ B = 25/500 = 5% จึงคำนวณน้ำหนักจีนได้ **30:70 หลังจำกัดช่วง** ไม่ต้องรอให้ทั้งสองอุปกรณ์มีข้อมูล และไม่นำไทยหรืออังกฤษมาเติม ผลนี้ใช้เมื่อถึงรอบรายวัน ไม่ใช่ทันทีหลังแก้ภาพ

### 12.3 กรณีมีข้อมูลใหม่ก่อนรอบรายวัน

สมมติจีน–Mobile หลังแก้มี A = IMP 200 / Click 12 และ B = IMP 200 / Click 2 ส่วนจีน–Desktop ไม่มีข้อมูลเพิ่ม

| ข้อมูล A/B ภาษาจีน | IMP A | Click A | IMP B | Click B |
|--------------------|-------|---------|-------|---------|
| จีน–Desktop ที่ไม่ได้รีเซ็ต | 500   | 5       | 500   | 25      |
| จีน–Mobile หลังรีเซ็ต | 200   | 12      | 200   | 2       |
| รวมใช้คำนวณน้ำหนักจีน | 700   | 17      | 700   | 27      |

| ขั้นตอน | ผลลัพธ์ |
|---------|---------|
| CTR_AB_A[ZH] = 17 ÷ 700 × 100 | ประมาณ 2.428571% |
| CTR_AB_B[ZH] = 27 ÷ 700 × 100 | ประมาณ 3.857143% |
| RAW_P_A[ZH] = CTR A ÷ (CTR A + CTR B) × 100 | ประมาณ 38.636364% |
| น้ำหนักจีนหลังจำกัดช่วง | ประมาณ 38.64:61.36 |
| น้ำหนักไทยและอังกฤษ หากข้อมูลไม่เพิ่มจากตัวอย่าง | ไทยประมาณ 66.67:33.33 และอังกฤษ 50:50 |

Performance ภาษาจีนในตัวอย่างยังสะสมประวัติก่อนแก้: A = 22/1,200 หรือ CTR ประมาณ 1.8333%; B = 52/1,200 หรือ CTR ประมาณ 4.3333% การนำค่านี้มาแทน input หลังรีเซ็ตจะได้น้ำหนักหลังจำกัดช่วง 30:70 ซึ่งไม่ตรงผลที่ต้องใช้ประมาณ 38.64:61.36 จึงต้องแยกข้อมูลสองส่วนนี้

หากแก้หลายคู่ ให้เริ่ม input ทั้ง A/B เฉพาะคู่ที่แก้ และตั้ง 50:50 เฉพาะภาษาที่มีการแก้ เช่น แก้ไทย Mobile กับจีน Desktop จะรีเซ็ตน้ำหนักไทยและจีน ส่วนอังกฤษคงเดิม หากแก้ครบทั้ง 6 คู่จะเริ่ม input ใหม่ทุกคู่และเริ่มน้ำหนักทั้ง 3 ภาษาใหม่ที่ 50:50 โดยยังเก็บ Performance

## EP-14 ข้อควรระบุให้ทีมพัฒนาและขอบเขตในอนาคต

### 14.1 แนวทางบันทึกข้อมูล — ข้อเสนอทางเทคนิค

รายละเอียดต่อไปนี้เป็น **ข้อเสนอให้ทีมพัฒนากำหนดวิธีทำ** เพื่อรักษากฎที่ยืนยันแล้ว ไม่ใช่การอ้างว่าระบบปัจจุบันรองรับแล้ว

| เรื่อง | แนวทางที่เสนอ |
|--------|---------------|
| แยกสถิติ A/B จาก Performance | เก็บจุดเริ่มคำนวณของแต่ละคู่ภาษา–อุปกรณ์ และเก็บน้ำหนักแยก Slot + ภาษา โดยยังเก็บ Performance และประวัติภาพเดิม |
| ภาษาสำรอง | ดำเนินการตาม TBP-CTR13–14: ใช้ชุดน้ำหนักไทยและนับ input ไทยครั้งเดียว ส่วนการเก็บภาษาเว็บไซต์ควบคู่ภาษาภาพจริงให้ทีมพัฒนากำหนดรูปแบบข้อมูล |
| การอ้างอิงเหตุการณ์ | อ้างอิง Slot ต้นทาง ทางเลือก A/B ภาษา อุปกรณ์ และรุ่นภาพที่แสดงจริง เพื่อไม่โยน Click ของภาพเก่ามาปน input หลังรีเซ็ตของภาพใหม่ |
| การแก้ภาพชนกับรอบคำนวณ | ป้องกันผลคำนวณก่อนแก้ภาพมาเขียนทับน้ำหนัก 50:50 ล่าสุดของภาษาที่แก้ และไม่ให้น้ำหนักหรือ input ของภาษาอื่นเปลี่ยนตาม |
| ความหมาย Click/Impression | ใช้เกณฑ์บันทึกเหตุการณ์ของระบบเดิม เอกสารนี้ไม่เพิ่มนิยามนับ Impression จากแค่โหลดรายการ หรือกำหนดเวลามองเห็นขึ้นใหม่ |

### 14.2 มากกว่า 2 ทางเลือก — อ้างอิงเพื่ออนาคตเท่านั้น

ภาพต้นทางให้สูตรทั่วไปว่า `น้ำหนักดิบของกราฟฟิก i = CTR_i ÷ ผลรวม CTR ของทุกกราฟฟิก × 100`

Solution รอบนี้ยังใช้ **A/B สองทางเลือกต่อ Slot** เท่านั้น ไม่เพิ่มจำนวนทางเลือกตามจำนวนภาษา และยังไม่เปิดใช้สูตรหลายทางเลือก หากขยายในอนาคตต้องกำหนดขอบเขตน้ำหนักใหม่ก่อน โดยไม่ยกกฎขั้นต่ำ 30% ไปใช้ตรง ๆ กับ 4 ทางเลือก เพราะรวมขั้นต่ำจะเป็น 120%
