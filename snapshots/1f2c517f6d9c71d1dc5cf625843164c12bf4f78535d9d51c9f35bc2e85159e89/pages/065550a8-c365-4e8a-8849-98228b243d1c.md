**คำตอบถึง BE (2026-10-29): FE รองรับ BE-11 ชื่อเป็น string แล้ว — เปิด** `**ENABLE_DISPLAY_NAMES**` **บน staging ได้**

ตอบเรื่อง "[งาน 3 ภาษา] BE-11 เปลี่ยนชื่อที่ใช้แสดงผลจาก object เป็น string" (go-system-listing-service `feature/i18n`, `docs/i18n_contract.md` §9) ไฟล์นี้บอกเฉพาะสิ่งที่เปลี่ยนจากฉบับที่ส่งไปแล้ว ไฟล์หลักคือ `docs/backend-i18n/backend-i18n-request.md`

## สรุป

* **FE อ่านได้ทั้ง 2 แบบแล้ว:** ทุก field ในรายการ BE-11 ที่เว็บสาธารณะ (`next-frontend-nayoo-service`) ใช้ รับได้ทั้ง `{ th, en, zh }` (แบบเดิม) และ string ในภาษาที่ขอ ผลลัพธ์ของแบบเดิมเหมือนก่อนแก้ทุกอย่าง
* **BE เปิด flag** `**ENABLE_DISPLAY_NAMES**` **บน staging ได้เลย** หลัง FE branch `feature/setup-project-3-languages` ขึ้น staging (ยังไม่ deploy ณ วันที่เขียน) แจ้ง FE เมื่อเปิด เพื่อเทสแบบ string
* **Accept-Language:** ทุก fetch ของ route ในรายการส่ง header นี้แล้ว (`fetchJson` ใส่ให้อัตโนมัติ, fetch ตรงใช้ `localeHeader()`) ค่าเป็น `th` / `en` / `zh-CN` ตามภาษาของหน้า string ที่ได้จึงเป็นภาษาของหน้าเสมอ
* **ข้อควรระวัง:** route กลุ่มที่อยู่ (`/province/`, `/district/:id`, `/sub-district/:id`, `/zone/by-province/:id`, `/zone/by-province-slug/:slug`) และ `/search/property-types`, `/search/styles` **ไม่มีการใช้ในเว็บสาธารณะ** แต่ `next-frontend-console-service` เรียกใช้ (ตัวเลือกที่อยู่ในฟอร์มลงประกาศ / โปรไฟล์ / ตัวกรอง) FE ฝั่งเว็บสาธารณะไม่ได้ตรวจ repo นั้น ถ้าเปิด flag แล้ว console ยังอ่าน `.th` อยู่ ชื่อในฟอร์มจะว่าง ต้องให้ console ส่ง `X-I18n-Raw: 1` หรือแก้ให้รับ string ก่อน

## สิ่งที่ FE ทำกับ string

* แสดงตามที่ส่งมา ไม่แปลงหรือแปลซ้ำ
* หน้าไทยเดิมแสดงชื่อโครงการ / บริษัทแบบ "ชื่อไทย - English" เมื่อได้ object พอเป็น string จะแสดงชื่อเดียวที่ BE ส่ง (ภาษาไทยหรือ fallback) ถ้าต้องการคง "ไทย - English" บนหน้าไทย BE ต้องส่งชื่อที่ต่อกันแล้วมาเอง หรือส่ง object แบบเดิมสำหรับหน้า `th`
* slug ใน URL ของ FE ใช้ field `slug` จาก BE เป็นหลัก มี 2 จุดที่ยังสร้าง slug จาก `name.en` เมื่อไม่มี `slug`:
  * `project_info.property_type[]` ที่ไม่มี `slug` → ได้ slug ทั่วไป `house` บนหน้า `th` / `zh` ขอให้ทุก property type มี `slug` เสมอ
  * `home-page/blog-company-block` → ลิงก์แบรนด์สร้างจาก `name.en` + `company_id` บนหน้า `th` / `zh` ส่วนชื่อใน URL จะกลายเป็น `developer-<id>` แต่ยังเปิดหน้าได้ เพราะหน้าปลายทางอ่าน id ท้าย URL

## ขอ BE


1. แจ้ง FE เมื่อเปิด `ENABLE_DISPLAY_NAMES` บน staging
2. ยืนยันว่า `support-provinces` (`province.name`) จะเปลี่ยนเป็น string ด้วยหรือไม่ (ไม่อยู่ในรายการ BE-11 แต่ FE รองรับแล้ว)
3. แจ้งทีม console ก่อนเปิด flag เรื่อง route ที่อยู่ / property-types / styles

## วิธีตรวจ (หลังเปิด flag)

```bash
# ต้องได้ "string" ในภาษาที่ขอ
curl -s -H "apikey: $KEY" -H "Accept-Language: en" "$API/api/listing/coming-soon?limit=1" | jq '.data[0].project_name | type'
curl -s -H "apikey: $KEY" -H "Accept-Language: en" "$API/api/listing/home-page/blog-company-block?tag=<tag>" | jq '.data.items[0].name | type'
curl -s -H "apikey: $KEY" -H "Accept-Language: zh-CN" "$API/api/listing/profile-company-home-builder/details/10" | jq '{name: (.data.name|type), province: (.data.province.name|type)}'
# ต้องได้ "object" เมื่อขอ raw
curl -s -H "apikey: $KEY" -H "X-I18n-Raw: 1" "$API/api/listing/coming-soon?limit=1" | jq '.data[0].project_name | type'
```
