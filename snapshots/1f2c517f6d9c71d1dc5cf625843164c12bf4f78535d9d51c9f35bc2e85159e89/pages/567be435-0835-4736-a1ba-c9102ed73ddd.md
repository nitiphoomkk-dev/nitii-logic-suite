**Features requirement document (Pending)**

| \*\*Features name \*\* | คู่มือผู้ใช้งาน<br>แยกตามสิทธิ authorize user |
|--------------------|--------------------------------------------|
| **Description**    | เครื่องมือที่ใช้ในการแก้ปัญหาให้ User เบื้องต้น ในการทำความเข้าใจเกี่ยวกับปัญหาที่เกิดขึ้นจากระบบ ผ่านฟีเจอร์ที่เรียกว่า คู่มือผู้ใช้งาน,เพื่อขายของ |
| **User problem**   | User ที่เข้ามาใช้งานในระบบ ไม่เข้าใจวิธีการทำงานต่างๆในระบบ ทำให้เกิด overload กับ แอดมิน backoffice ที่ต้องมาแก้ปัญหาให้กับ user  ทำให้ admin ต้องถืองาน overload |
| **Value proposition** | เพื่อเพิ่มความเข้าใจและแก้ปัญหาเบื้องต้นของ user ผ่านการใช้ คู่มือผู้ใช้งาน |
| \*\*Assumption \*\* | 1\.User มีความเข้าใจการใช้งานไม่มากเพียงพอในระบบ<br>2. การทำฟีเจอร์คู่มือผู้ใช้งานจะช่วยลดปัญหา overload ของ แอดมิน backoffice |
| **In of scope**<br> | 1\.การจัดหมวดหมู่คู่มือ (Categories)ตามฟังก์ชันการใช้งาน<br>2. ระบบการแสดงเนื้อหาคู่มือ แยกตามประเภทของผู้ใช้งาน<br>3. ระบบค้นหา(Search)หัวข้อในคู่มือเพื่อให้หาข้อมูลง่ายขึ้น<br>4. เพื่อตอบโจทย์หน้าที่ SEO ที่ต้องการติด target page ข้อง SEO<br>5. ขายของในบางหน้า(sales desk) |
| **Out of scope**   | 1\.ระบบแชทสด (Live Chat) หรือการโต้ตอบกับเจ้าหน้าที่แบบ Real-time<br>2. การแจ้งเตือนแบบ Push Notification เมื่อมีการอัปเดตคู่มือ<br>3. วิดีโอสอนการใช้งาน |
| **MVP**            | ระบบต้องสามารถใช้งานจริง มีการแสดงผลแยกคู่มือผู้ใช้งาน<br>แยกตามสิทธิ authorize user ,สามารถพิมพ์ค้นหาได้<br> |
