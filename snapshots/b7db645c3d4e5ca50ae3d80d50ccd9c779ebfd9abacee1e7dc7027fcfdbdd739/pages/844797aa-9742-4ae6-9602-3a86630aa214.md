**Solution Insert Card จังหวัด — แบบที่ 1 รวมน้ำหนักทั้ง 3 ภาษาและทุกอุปกรณ์**

ฉบับ 1.0 · 4 พฤศจิกายน 2569 · ผู้จัดทำ: นิติ๊ · สถานะ: ร่าง Solution ใหม่ตามคำตัดสินผู้ใช้ สำหรับ Dev และ Tester

เป้าหมายคือให้ Insert Card ของจังหวัดปัจจุบันรวมหมวดน่าอยู่มีโอกาสเข้าแสดงผลตาม Shuffle ระดับรายการต้นทาง และใช้ผล Click/Impression เพื่อเวทน้ำหนักระหว่าง **Slot A กับ Slot B ของ Source เดียวกัน** โดยยังแสดงเพียงหนึ่งการ์ดต่อ Source ต่อหน้า แบบที่ 1 รวมข้อมูลทั้งสามภาษาและ Desktop/Mobile ก่อนคำนวณ จึงมีน้ำหนัก A/B ชุดเดียวต่อ Source

**คำตัดสินผู้ใช้ล่าสุด:** “ขอแก้คำใหม่เป็น เวทน้ำหนักจาก slot A และ slot B ส่วนภาษาการแสดงผลให้ตรงกับเงื่อนไขภาษา” จึงใช้ Shuffle เฉพาะการเลือกลำดับ Source ภายนอก แล้วเลือก Slot A/B ภายในด้วยน้ำหนัก รวมกรณี A/B เป็นคนละรูปแบบ เช่น A เป็น Free Text และ B เป็น Video เมื่อเลือก B ต้องแสดง Video ของ B ตามกฎภาษา ไม่ย้อนกลับไปเลือก A เพราะ A มีภาพตรงภาษา

**สถานะกฎ:** คำตัดสินล่าสุดอยู่เหนือข้อความ “ไม่มี A/B Test / Shuffle ภายใน” ใน [Insert Card 3 ภาษา](https://wiki.infonayoo.co/doc/insert-card-3-y3Zp0zHyHV) revision 20 และการจัดลำดับด้วย Ranking ในร่าง Product จังหวัด โดยไม่แก้ต้นทาง กฎ `web_language` เป็น bucket ทดลองก่อนเลือก A/B และการหา bucket ที่ต้อง reset ตามสื่อที่ใช้ตรง/สำรอง เป็น **กฎออกแบบของ Solution ใหม่ที่อนุมานให้การทำงานครบวงจร** ไม่ใช่คำพูดผู้ใช้ยืนยันทุกกรณี และไม่ใช่ข้ออ้างว่าระบบจริงทำแล้ว

## EP-03 ความพร้อมแสดงและการ Resolve ภาษา

ตรวจความพร้อมของแต่ละ A/B ตามรูปแบบก่อนนำ Source เข้า Shuffle โดยภาพสามภาษาต้องมีไทยที่ใช้ได้ ส่วนสื่อชุดเดียวต้องมีสื่อเดิมที่ใช้ได้ การเลือกภาษาเกิด **หลังเลือก A/B** และไม่เปลี่ยน A/B ที่เลือกแล้ว

| รหัส | เงื่อนไข | Logic การทำงาน |
|------|----------|----------------|
| ICM1-L01 | A หรือ B เป็นรูปแบบภาพสามภาษา แต่ไม่มีภาพไทย | ทางเลือกนั้นไม่พร้อมแสดง แม้มีภาพ EN/ZH ไม่ถือภาพ EN/ZH เป็นไทยเอง |
| ICM1-L02 | รูปแบบภาพสามภาษามีไทย และมีภาพตรง web_language | เมื่อเลือกทางเลือกนั้น ใช้ภาพตรงภาษาเว็บไซต์ |
| ICM1-L03 | รูปแบบภาพสามภาษามีไทย แต่ไม่มีภาพตรง web_language | ใช้ภาพไทยของ A/B ที่เลือก ไม่ใช้ภาษาที่สามและไม่หยิบภาพของอีก A/B |
| ICM1-L04 | ทางเลือกเป็น Video หรือสื่อชุดเดียวที่ไม่รองรับภาพสามภาษา และสื่อผ่านเงื่อนไข | ถือเป็น TH โดยไม่ต้องเพิ่มช่องภาพไทย หน้า TH ใช้เป็นหลัก หน้า EN/ZH ใช้สื่อเดิมเป็นไทยสำรอง |
| ICM1-L05 | ผลเลือกเป็น B Video บนเว็บ EN/ZH แม้ A มีภาพตรงภาษา | แสดง B Video เดิม ไม่ย้อนกลับไป A ไม่แปลเสียงหรือข้อความใน Video และไม่เปลี่ยนภาษาเว็บไซต์ |
| ICM1-L06 | A/B ใช้ได้เพียงฝั่งเดียว | ใช้ฝั่งนั้น 100% ไม่สุ่มฝั่งที่ไม่มีสื่อ/ไม่ผ่านเงื่อนไข และไม่เปลี่ยนน้ำหนักที่เก็บของ Source เพราะเหตุนี้ |
| ICM1-L07 | ไม่มี A/B ใดใช้ได้ | Source ไม่เป็น Candidate ไม่สร้างการ์ดว่างหรือยืมสื่อ Source อื่น |
| ICM1-L08 | เปลี่ยนภาพภาษาใดใน A/B | เปลี่ยนเฉพาะสื่อที่แก้ สื่อภาษาอื่นและอีก A/B ไม่ถูกเขียนทับ; ผล reset input เป็นอีกเรื่องตาม EP-12 |
| ICM1-L09 | แสดงทางเลือกเดียวกันต่างอุปกรณ์ | ใช้ภาพ/Video/URL ชุดเดียวกัน Layout และจำนวนบรรทัดต่างตามกฎเดิมได้ |

| ภาษาของภาพที่มีใน A/B ที่เลือกแล้ว | เว็บ TH | เว็บ EN | เว็บ ZH |
|------------------------------------|---------|---------|---------|
| TH, EN, ZH                         | TH      | EN      | ZH      |
| TH, EN                             | TH      | EN      | TH สำรอง |
| TH, ZH                             | TH      | TH สำรอง | ZH      |
| TH อย่างเดียว                      | TH      | TH สำรอง | TH สำรอง |
| Video / สื่อชุดเดียว               | สื่อเดิม TH | สื่อเดิม TH สำรอง | สื่อเดิม TH สำรอง |

ตัวอย่าง Source SX มี A Free Text ไทย/อังกฤษ/จีน และ B Video ชุดเดียว เมื่อ A/B พร้อมทั้งคู่ เว็บ ZH ยังเลือก A หรือ B ด้วยน้ำหนัก Source ก่อน ถ้าได้ A แสดงภาพ ZH ถ้าได้ B แสดง Video TH ไม่ทำให้ B หายจากการทดลองภาษาจีน

## EP-10 สูตรน้ำหนักรวมและรอบคำนวณ

| รหัส | เรื่อง | Logic |
|------|--------|-------|
| ICM1-W01 | รอบ daily | คำนวณรอบรายวันหลัง 00:00 น. เวลาไทย จาก input สะสมตั้งแต่ reset ล่าสุดของแต่ละ web bucket ไม่ล้างข้อมูลทุกวันและไม่ใช้เฉพาะวันก่อนหน้า |
| ICM1-W02 | ขอบเขตรวม | ภายใน Source เดียว รวม Click A ของ TH+EN+ZH และรวม IMP A ของ TH+EN+ZH เช่นเดียวกับ B โดยยอดแต่ละ bucket รวมอุปกรณ์แล้ว |
| ICM1-W03 | CTR รวม | CTR_A = Click_Aรวม / IMP_Aรวม; CTR_B = Click_Bรวม / IMP_Bรวม ไม่เฉลี่ย CTR ย่อยหรือน้ำหนักรายภาษา |
| ICM1-W04 | น้ำหนักดิบ | ถ้าหารได้ RawP_A = CTR_A / (CTR_A + CTR_B); RawP_B = 1 − RawP_A |
| ICM1-W05 | เพดาน / ขั้นต่ำ | P_A = MIN(70%,MAX(30%,RawP_A)); P_B = 100% − P_A จึงได้ 30:70 ถึง 70:30 ไม่บังคับ A เป็นฝั่งชนะ |
| ICM1-W06 | Zero-IMP guard | ถ้า IMP รวมของ A หรือ B เป็น 0 หรือ CTR_A+CTR_B=0 ใช้ 50:50 ที่ระดับยอดรวม Source ไม่ตรวจว่าทุก bucket ต้องมี IMP ก่อน |
| ICM1-W07 | บาง bucket ยังว่าง | ถ้า Source รวม A/B แล้วหารได้ ใช้ยอดรวมที่มี ไม่บังคับรอครบสามภาษา |
| ICM1-W08 | Click ศูนย์ฝั่งเดียว | ถ้าทั้งคู่มี IMP แต่ A Click=0 และ B Click>0 น้ำหนักเป็น 30:70 ไม่ตีความว่าไม่มีข้อมูลทั้งคู่ |
| ICM1-W09 | กำลังรอ daily หลังแก้สื่อ | Source ใช้ 50:50 ถึงรอบ daily ถัดไป ไม่คำนวณทับทันทีจากยอดที่ยังเหลือ |
| ICM1-W10 | ใช้กับการแสดง | น้ำหนักหนึ่งชุดใช้ทุกภาษาและอุปกรณ์เมื่อ A/B พร้อมทั้งคู่; ถ้ามีฝั่งเดียวให้ใช้ 100% โดยไม่แก้ weight ที่เก็บ |

เปอร์เซ็นต์ในตัวอย่างแสดงทศนิยมสองตำแหน่งเพื่ออ่านง่าย การคำนวณใช้อัตราส่วนก่อนปัดเพื่อไม่สะสมความคลาดเคลื่อน วิธีเก็บ precision เป็นรายละเอียดทางเทคนิคที่ยังไม่ใช่ schema ที่ตรวจแล้ว

| CTR รวม A / B | น้ำหนักก่อน clamp | น้ำหนักที่ใช้ A:B |
|---------------|-------------------|-------------------|
| 3% / 2%       | 60:40             | 60:40             |
| 9% / 1%       | 90:10             | 70:30             |
| 1% / 9%       | 10:90             | 30:70             |
| 0% / 2% โดยทั้งคู่มี IMP | 0:100             | 30:70             |
| 0% / 0% หรือฝั่งใด IMPรวม=0 | คำนวณตามสูตรไม่ได้ | 50:50             |

## EP-11 จำลองตัวเลขรวมน้ำหนักทั้ง 3 ภาษา

ข้อมูลสมมติของ Source SX คือ A Free Text TH/EN/ZH และ B Video TH โดย input ต่อไปนี้แยกตาม **ภาษาเว็บไซต์** แต่ละแถวรวม Desktop/Mobile แล้ว B Video ที่เว็บ ZH/EN จึงยังอยู่ใน bucket ZH/EN ตามลำดับ แม้ภาษาสื่อจริงเป็น TH

| web bucket | A Click | A IMP | CTR A | B Click | B IMP | CTR B | น้ำหนักแยกภาษาถ้าคิดแบบที่ 2 เพื่อเปรียบเทียบ |
|------------|--------:|------:|------:|--------:|------:|------:|-----------------------------------------------|
| TH         | 400     | 10,000 | 4%    | 200     | 10,000 | 2%    | 66\.67:33.33                                  |
| ZH         | 10      | 1,000 | 1%    | 50      | 1,000 | 5%    | 30:70 หลัง clamp                              |
| EN         | 30      | 1,000 | 3%    | 30      | 1,000 | 3%    | 50:50                                         |
| **รวมสำหรับแบบที่ 1** | **440** | **12,000** | **3.6666667%** | **280** | **12,000** | **2.3333333%** | **61.11:38.89 ชุดเดียว**                      |

RawP_A = (440/12,000) ÷ [(440/12,000)+(280/12,000)] = 440/720 = 61.1111111% จึงใช้ **A 61.11% / B 38.89%** ไม่ติด clamp

| เว็บ / อุปกรณ์ที่กำลังจัดหน้า | น้ำหนัก A:B แบบที่ 1 | ถ้า SX ได้ A | ถ้า SX ได้ B |
|-------------------------------|----------------------|--------------|--------------|
| TH Desktop / Mobile           | 61\.11:38.89         | ภาพ A-TH     | Video B-TH   |
| EN Desktop / Mobile           | 61\.11:38.89         | ภาพ A-EN หรือ A-TH สำรองหาก EN ไม่มี | Video B-TH สำรอง |
| ZH Desktop / Mobile           | 61\.11:38.89         | ภาพ A-ZH หรือ A-TH สำรองหาก ZH ไม่มี | Video B-TH สำรอง |

ความต่างจากแบบที่ 2 อยู่ที่วิธีรวมและน้ำหนักที่ใช้ ไม่ใช่การตัด B Video ออกจากภาษาที่ไม่มี Video แปล แบบที่ 1 ไม่เอา (66.67+30+50)/3 มาเป็นน้ำหนัก เพราะเป็นการเฉลี่ยเปอร์เซ็นต์ต่างฐานที่ไม่ใช่สูตรรวม Click/IMP

## EP-12 เปลี่ยนสื่อและ reset เฉพาะ bucket ที่ได้รับผล

**กฎออกแบบใหม่จากนโยบาย reset:** หา web bucket ที่การ Resolve สื่อหรือความพร้อมแสดง (eligibility) เปลี่ยน โดยตรวจ **ทุกทางเลือกที่อาจถูกเลือกทั้งก่อนและหลังแก้** ครอบการใช้ตรงภาษาและการใช้ TH สำรอง ไม่ดูเฉพาะการ์ดหรือผล A/B ที่แสดงรอบล่าสุด แล้วเริ่ม input ของ **ทั้ง A และ B** ใหม่ใน bucket ที่ได้รับผล เก็บ input bucket อื่นและ Performance ทุก bucket ไว้ จากนั้นตั้งน้ำหนักร่วมของ Source เป็น **50:50 ทันทีจนถึง daily ถัดไป** การ reset bucket ไม่ใช่การลบสื่อของอีก A/B

ไม่มีคู่ภาษา–อุปกรณ์ เนื่องจากไฟล์ร่วม Desktop/Mobile เมื่อ bucket ได้รับผล input ของอุปกรณ์ทั้งสองใน bucket นั้นเริ่มรอบใหม่รวมกัน ไม่สร้าง reset จีน–Mobile แยกตาม Top Banner

### 12.1 หา bucket ที่ได้รับผลจากสื่อจริง

| กรณีแก้สื่อสำเร็จ | bucket ที่ได้รับผล | สิ่งที่คงไว้ |
|-------------------|--------------------|--------------|
| เปลี่ยน A-ZH โดย A มี TH/EN/ZH ครบ และ B เป็น Video | ZH ทั้ง A/B        | TH และ EN input เดิม; Performance ทุกภาษาและอุปกรณ์ |
| เปลี่ยน A-TH โดย A มี EN/ZH ตรงภาษาอยู่แล้ว | TH ทั้ง A/B        | EN/ZH ไม่ reset เพราะการ Resolve ของ A ไม่ใช้ไฟล์ TH นั้น |
| เปลี่ยน A-TH โดย A ไม่มี EN แต่มี ZH | TH และ EN ทั้ง A/B เพราะ EN ใช้ A-TH สำรอง | ZH input เดิม |
| เปลี่ยน A-TH โดย A มีไทยอย่างเดียว | TH, EN, ZH ทั้ง A/B | Performance; ไม่เหลือ bucket input เดิมของ Source นี้ |
| เปลี่ยน B Video ชุดเดียวที่ใช้ได้ทุกภาษาเว็บ | TH, EN, ZH ทั้ง A/B | Performance; แม้ B จัด media_language เป็น TH ก็ได้รับผลทั้งสาม bucket |
| เพิ่ม/ลบภาพเฉพาะภาษา เช่นเพิ่ม A-EN แทน TH สำรองเดิม | EN ทั้ง A/B เพราะสื่อที่ Resolve เปลี่ยน | bucket ภาษาอื่นที่ไม่เปลี่ยนสื่อ |
| ลบ A-TH ที่เป็นภาพบังคับ แม้ A ยังมี EN/ZH ตรงภาษา | TH, EN, ZH ทั้ง A/B เพราะ A เปลี่ยนเป็นไม่พร้อมแสดงทุกภาษา | Performance; ไม่จำกัดผลเพียง TH เพราะดู label ไฟล์ที่ลบ |
| เปลี่ยนรูปแบบหรือสื่อใหม่ที่เปลี่ยนการ Resolve / ความพร้อมของทางเลือกหลายภาษา | รวม bucket ที่ได้รับผลจากสื่อ/รูปแบบและ eligibility ของทุกทางเลือกก่อนและหลังแก้ อาจครบสามภาษา | เก็บ bucket อื่นที่ตรวจแล้วไม่เปลี่ยน; ไม่อนุมานว่าแก้ทุกอย่างกระทบทุกภาษาเสมอ |

การอ้าง TH เป็น media_language เหมือนกัน ไม่ได้แปลว่าเป็นไฟล์เดียวกัน เช่น A-TH กับ B Video เป็นคนละสื่อ การแก้ A-TH ไม่ reset EN/ZH เพียงเพราะ B Video มี label TH หากการ Resolve ของ A ในสองเว็บนั้นใช้ภาพ EN/ZH ของตนอยู่แล้ว

### 12.2 จำลองแก้ A-ZH จากข้อมูล EP-11

สมมติบันทึกภาพ A-ZH ใหม่สำเร็จ ไม่มีการแก้ภาพ TH/EN หรือ B Video และไม่มีข้อมูลเพิ่มใน bucket อื่น

| รายการ | ก่อนแก้ | ทันทีหลังแก้ |

### 12.3 รอบ daily ถัดไป

| กรณีหลัง reset | input A รวม | input B รวม | CTR รวม A / B | น้ำหนักร่วม Source A:B |
|----------------|-------------|-------------|---------------|------------------------|
| ZH ยังไม่มี input ใหม่ | 430 / 11,000 | 230 / 11,000 | 3\.9090909% / 2.0909091% | **65.15:34.85**        |
| ZH ใหม่ A12/200 และ B2/200 | 442 / 11,200 | 232 / 11,200 | 3\.9464286% / 2.0714286% | **65.58:34.42**        |

กรณีแรก P_A=430/(430+230)=65.1515152% กรณีสอง P_A=442/(442+232)=65.5786350% ดังนั้น ZH ที่ยังว่างไม่บังคับให้ Source คง 50:50 หลัง daily หากยอด TH+EN รวมทั้ง A/B คำนวณได้ แต่ **ก่อน daily ยังต้อง 50:50** ตามกฎเริ่มใหม่

| เหตุการณ์เพิ่มเติม | ผลที่ต้องได้ |
|--------------------|--------------|
| เปลี่ยนภาพหลายภาษา | reset ทั้ง A/B ของทุก web bucket ที่ได้รับผล ตั้งน้ำหนักรวม Source 50:50 ครั้งล่าสุดจน daily |
| เปลี่ยน Video ชุดเดียวและ input ทั้งสาม bucket เริ่มใหม่ | Source 50:50 จน daily; daily ที่ยังไม่มี IMP รวมพอใช้ zero-IMP guard |
| แต่ละ bucket reset คนละเวลา | daily รวมยอดสะสมตั้งแต่ reset ล่าสุดของ bucket นั้น ไม่ใช้ timestamp เดียวล้างทุกภาษา |
| ผ่าน 00:00 โดยไม่แก้สื่อ | ไม่ล้าง input รายวัน ใช้ยอดสะสมต่อ |
| Refresh / เปลี่ยนภาษา / เปลี่ยนอุปกรณ์โดยไม่แก้สื่อ | ไม่ reset และไม่คำนวณทับทันที |
| แก้ Source อื่น    | ไม่ reset input หรือ weight ของ SX |

| ICM1-TP07   | การแสดงIMP | ใช้เกณฑ์eventแสดงจริงเดิม ไม่เกิดIMPเพียงเพราะโหลดCandidate/เลือกทางเลือก;ต้องตรวจนิยามeventจริงก่อนกำหนดthresholdเพิ่ม |
