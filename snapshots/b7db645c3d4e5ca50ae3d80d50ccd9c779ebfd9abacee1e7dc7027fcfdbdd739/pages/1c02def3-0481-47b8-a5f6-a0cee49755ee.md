## **1) แนวคิดและขอบเขต**

### **1.1 กฎกลางของการลงทะเบียนทั้งเว็บไซต์**

ใช้กับจุดที่มีฟอร์มลงทะเบียนความสนใจหรือขอให้ติดต่อกลับจริง ไม่ได้กำหนดให้ทุกหน้าต้องสร้างฟอร์มใหม่ จุดเข้าถึงอาจเป็น Section ในหน้า ปุ่มเปิด Modal แถบติดต่อ/แถบลอย หรือ Tab ลงทะเบียนในแกลเลอรี โดยใช้ UI ของจุดนั้น

| **ประเภทหน้า** | **จุดลงทะเบียนที่ครอบคลุมเมื่อมีฟอร์ม** |
|------------|-------------------------------------|
| หน้าใบประกาศ | โครงการมือ 1 มือสอง ขาย เช่า ขายและเช่า หอพัก และแบบบ้าน ตามตำแหน่งฟอร์มที่มีจริง |
| หน้าโปรไฟล์ | โครงการ/แบรนด์ บริษัทรับสร้างบ้าน นายหน้า และสถาบัน ตามฟอร์มที่เปิดให้ติดต่อ |
| Landing Page / แคมเปญ | ฟอร์มลงทะเบียนสนใจและฟอร์มรับสิทธิ์ โดยเงื่อนไขสิทธิ์ใช้ตามแคมเปญนั้น |
| หน้าค้นหา  | ปุ่มหรือการ์ดที่เปิดฟอร์มลงทะเบียนสนใจ |
| หน้าบทความ / รีวิว | ฟอร์มติดต่อรายการ โครงการ บริษัท หรือผู้รับที่บทความเชื่อมไว้ |
| หน้าสินเชื่อ / section สินเชื่อ ทั้งกรณีเลือกแบบบ้านและไม่เลือกแบบบ้าน | ฟอร์มฝากชื่อ/เบอร์หรือขอคำปรึกษา ใช้เงื่อนไขการคำนวณและผู้รับของฟอร์มนั้น |
| จุดติดต่ออื่น | Modal ก่อนติดต่อ LINE/Facebook/แผนที่ และจุดอื่นที่รับข้อมูลความสนใจจริง |

### **1.2 การแสดงผลเฉพาะจุด**

รูปแบบ Section, Modal, Tab, ชื่อปุ่ม และข้อความต้องตรง UI ของหน้าที่ผู้ใช้ใช้งาน กฎกลางนี้ไม่ได้ทำให้ทุกฟอร์มต้องย้ายไปอยู่ในแกลเลอรี หรือแสดง Modal ชนิดเดียวกันทั้งหมด

### **1.3 ขอบเขตข้อมูลและผู้รับ**

ทุกการส่งต้องระบุรายการหรือแบบฟอร์มต้นทาง และผู้รับที่ฟอร์มนั้นกำหนด หากมีโครงการ แบบบ้าน บริษัท หรือแคมเปญที่เกี่ยวข้อง ต้องอ้างอิงรายการนั้นให้ถูกต้อง ใช้ผู้รับ Center หรือจังหวัดตามกฎของหน้าต้นทาง การนำกฎกลางนี้ไปใช้ไม่เปลี่ยนผู้รับเดิมเอง

### **1.4 ขอบเขตที่ใช้กฎแยก**

การสมัครบัญชี เข้าสู่ระบบ เชื่อมบัญชี และ OTP ใช้กฎบัญชี/ยืนยันตัวตนของตน การกดโทรตรงหรือเปิดลิงก์ที่ไม่มีฟอร์มไม่ถือเป็นการลงทะเบียนใหม่ ส่วนการรับคูปอง Walk-in ต้องตรวจสิทธิ์ตามหัวข้อ 6.4

## **3) Workflow กลางของการลงทะเบียน**

### **3.1 เปิดและกรอกฟอร์ม**


1. ผู้ใช้เข้าหน้าหรือกดจุดติดต่อที่มีฟอร์ม
2. แสดงฟอร์มใน Section, Modal หรือ Tab ตาม UI ของจุดนั้น
3. แสดงหัวข้อ รายการที่สนใจ และผู้รับให้ตรงกับต้นทาง
4. ผู้ใช้กรอกข้อมูลและยืนยันตามเงื่อนไขของฟอร์ม
5. การเปิดฟอร์มหรือดูข้อมูลอย่างเดียวยังไม่สร้างการลงทะเบียน

### **3.2 ตรวจข้อมูลและจัดการผลส่ง**


1. ตรวจช่องบังคับและความยินยอมตามฟอร์ม รวมถึงกฎเบอร์ตัวเลขครบ 10 หลัก ไม่จำกัดเลขขึ้นต้น
2. ตรวจชื่อ/เบอร์เดิมหรือใหม่ตามหัวข้อ 6.1 สำหรับฟอร์มธรรมดา; ถ้าเป็น Walk-in ใช้หัวข้อ 6.4
3. ฟอร์มธรรมดาชื่อเดิม+เบอร์เดิมของรายการนั้น ถ้าส่งแล้วในวันเดียวกัน ไม่เพิ่มลีด ไม่ส่งรายชื่อซ้ำ และไม่ส่ง LINE ซ้ำ
4. กรณีผ่าน ให้บันทึกการลงทะเบียนและส่งรายชื่อผู้สนใจกับ LINE “ลูกค้ามาแล้ว” ถึงผู้รับที่ถูกต้อง
5. แสดงผลตาม Flow และผลบันทึกจริง ไม่แสดงว่าเพิ่มลีดใหม่เมื่อรายการถูกกันซ้ำ
6. การปิดผลลัพธ์หรือเปิดฟอร์มอีกครั้งไม่ทำให้ส่งเพิ่มเอง

### **3.3 รอบวันของฟอร์มธรรมดา**

ใช้เวลา Asia/Bangkok รอบหนึ่งเริ่ม 00:00:00 ของวันนั้น และสิ้นสุดก่อน 00:00:00 ของวันถัดไป เมื่อถึงวันใหม่ ชื่อเดิม+เบอร์เดิมของรายการนั้นลงทะเบียนใหม่ได้อีกครั้งเมื่อผ่านกฎฟอร์ม

**ตัวอย่าง:** ลงทะเบียนวันที่ 19 ตุลาคม เวลา 23:50 น. แล้วส่งข้อมูลเดิมอีกวันที่ 20 ตุลาคม เวลา 00:10 น. ถือเป็นคนละรอบวัน จึงรับใหม่ได้ ส่วนส่งซ้ำวันที่ 19 ตุลาคม เวลา 23:55 น. ยังอยู่รอบเดิมและไม่ส่งซ้ำ

### **3.4 พฤติกรรมเฉพาะแกลเลอรีใบประกาศ**

ผู้ใช้เปิดแกลเลอรี → เลือก Tab ลงทะเบียน → กรอกและส่งข้อมูล → ตรวจตามกฎกลาง → แสดง Modal ผลลัพธ์ซ้อนบนฟอร์ม เมื่อ Modal สิ้นสุด Tab และฟอร์มยังอยู่ การแสดง Tab ไม่ขึ้นกับจำนวนภาพ

| **กลุ่ม UI** | **ฟอร์ม** | **ผลลัพธ์ที่แสดงในตัวอย่าง** |
|----------|-------|--------------------------|
| โครงการ  | ฟอร์มสอบถามข้อมูลโครงการ | Modal “บันทึกข้อมูลสำเร็จ” |
| โครงการ Walk-in | ฟอร์มโครงการพร้อมตัวเลือกเข้าร่วม Walk-in | Modal “สรุปคูปองที่เก็บ” |
| แบบบ้าน  | ฟอร์มขอคำปรึกษาจากบริษัทรับสร้างบ้าน | Modal “บันทึกข้อมูลสำเร็จ” |
| แบบบ้าน Walk-in | ฟอร์มแบบบ้านพร้อมตัวเลือกเข้าร่วม Walk-in | Modal “สรุปคูปองที่เก็บ” |
| มือสอง   | ฟอร์มติดต่อผู้ขายหรือนัดชมทรัพย์ | Modal “บันทึกข้อมูลสำเร็จ” |

ตารางนี้เป็นตัวอย่าง UI ในแกลเลอรี ขอบเขต UI มือสองในภาพท้ายเอกสารไม่รวมหอพัก แต่กฎกลางยังใช้กับฟอร์มสนใจหอพักที่มีจริงตาม UI ของหน้านั้น


## **4) ผลลงทะเบียนและพฤติกรรมของฟอร์ม**

### **4.1 ผลลงทะเบียนธรรมดา**

เมื่อระบบยืนยันผลบันทึกแล้ว แสดงข้อความหรือ Modal สำเร็จตาม UI ของฟอร์มนั้น เช่น แกลเลอรีแสดง “บันทึกข้อมูลสำเร็จ” ซ้อนบนฟอร์ม โดย Tab และฟอร์มยังอยู่เมื่อปิด Modal

ฟอร์มที่เปิดจาก Section หรือ Modal จุดอื่นใช้พฤติกรรมปิด กลับหน้า หรือเข้าถึงฟอร์มตาม UI ของจุดนั้น เอกสารนี้ไม่กำหนดเวลาปิดอัตโนมัติเดียวกันทั้งเว็บไซต์

### **4.2 ผลรับคูปอง Walk-in**

เมื่อ Flow รับคูปองสำเร็จ แสดง Modal “สรุปคูปองที่เก็บ” พร้อมข้อความ “เก็บคูปองสำเร็จ” และข้อมูลคูปองตามผลจริง ใช้จำนวนและสิทธิ์ตามแคมเปญ ไม่ยึดจำนวนจากภาพตัวอย่าง

ตัวอย่างในแกลเลอรีมีปุ่ม X และ “ตกลง” สำหรับปิดสรุปคูปอง โดยฟอร์มยังอยู่ใน Tab จุดรับคูปองอื่นใช้ UI ของตนและกฎสิทธิ์เดียวกับหัวข้อ 6.4

### **4.3 ตารางผลที่ใช้ร่วมกัน**

| **เหตุการณ์** | **ผลที่ต้องตรวจ** |
|-----------|---------------|
| เปิดฟอร์ม / เลือก Tab / เปิด Modal | ยังไม่เพิ่มลีด ไม่ส่งรายชื่อหรือ LINE |
| ส่งข้อมูลไม่ผ่าน | แจ้งช่องหรือเงื่อนไขที่ผิดตาม UI; ไม่แสดงผลสำเร็จ |
| ส่งใหม่ผ่านและไม่ติดกันซ้ำ | บันทึกและส่งรายชื่อกับ LINE ตามรายการและผู้รับที่ถูกต้อง |
| ส่งซ้ำที่ติดกฎของ Flow | ไม่เพิ่มลีด ไม่ส่งรายชื่อและ LINE ซ้ำ |
| ปิดผลลัพธ์ / กลับเข้าแบบฟอร์ม | ไม่สร้างการส่งเพิ่มเอง |
| ปิด Modal ผลลัพธ์ในแกลเลอรี | Tab และฟอร์มยังเข้าถึงได้ |
| บันทึกไม่สำเร็จ | ไม่แสดงว่าลงทะเบียนสำเร็จ |

## **5) Logic เบอร์โทรของฟอร์มลงทะเบียนทั้งเว็บไซต์**

### **5.1 กฎเบอร์โทรที่ต้องรับ**

| **ข้อมูลที่ตรวจ** | **ผลตรวจเบอร์โทร** |
|---------------|----------------|
| ตัวเลขครบ 10 หลัก ทุกเลขขึ้นต้น | ผ่าน           |
| ตัวเลขน้อยกว่า 10 หลัก | ไม่ผ่าน        |
| ตัวเลขมากกว่า 10 หลัก | ไม่ผ่าน        |
| ว่างหรือมีตัวอักษรปน | ไม่ผ่าน        |

### **5.2 ขอบเขตการปรับ**

ให้ตรวจฟอร์มลงทะเบียนความสนใจทุกจุดในเว็บไซต์ รวมทั้ง Component และช่องทางรับข้อมูลที่แต่ละฟอร์มใช้ เพื่อให้กฎตัวเลขครบ 10 หลักโดยไม่จำกัดเลขขึ้นต้น และการส่งรายชื่อ/LINE ทำงานตรงกันทั่วเว็บไซต์

คำยืนยันปัจจุบันคือ **รับตัวเลขครบ 10 หลัก โดยไม่จำกัดเลขขึ้นต้น** ส่วนวิธีจัดการรหัสประเทศ ช่องว่าง หรือเครื่องหมายคั่นก่อนตรวจเบอร์ ยังไม่มีข้อสรุปในเอกสารนี้

| 1    | เดิม | เดิม     | ส่งเมื่อเป็นครั้งแรกของรอบวันนั้น; ถ้าส่งแล้วในวันเดียวกันไม่ส่งซ้ำ | 1 เมื่อรับใหม่ / 0 เมื่อกันซ้ำ |

### **6.2 ชื่อเดิมและเบอร์เดิม: ตัดรอบวันตามเวลาไทย**

| **เงื่อนไข** | **รายชื่อผู้สนใจ / LINE** | **ลีดใหม่** |

| ถึง 00:00 น. ของวันถัดไปแล้วลงใหม่ | ส่งได้อีกครั้งเมื่อข้อมูลผ่าน | 1       |

### **6.3 การนับเวลาและตรวจเบอร์**

| **หัวข้อ** | **กฎกลาง** |
|--------|--------|

| รอบวัน | เริ่ม 00:00:00 และสิ้นสุดก่อน 00:00:00 ของวันถัดไป |
| เริ่มรอบใหม่ | ทุกวันเวลา 00:00 น. พร้อมกันตามเวลาไทย |

| ส่งซ้ำในรอบเดิม | ไม่เพิ่มลีด ไม่ส่งรายชื่อ และไม่ส่ง LINE ซ้ำ |
| เบอร์โทรฟอร์มสนใจ | ตัวเลขครบ 10 หลัก ไม่จำกัดเลขขึ้นต้น ทั้ง Frontend และ Backend |

เวลาจำชื่อ/เบอร์เพื่อเติมข้อมูลอัตโนมัติของแต่ละฟอร์มเป็นคนละเรื่องกับรอบกันข้อมูลซ้ำรายวัน การเริ่มวันใหม่ไม่เปลี่ยนอายุคุกกี้หรือสร้างการส่งข้อมูลเอง

### **6.4 Walk-in: เก็บคูปองตามโครงการหรือบริษัท**

| **กรณี** | **ลีดใหม่** | **รายชื่อ / LINE** |
|------|---------|----------------|
| ชื่อใด ๆ เบอร์เดิม เคยรับโครงการ/บริษัทนี้แล้ว | 0       | ไม่ส่งซ้ำ      |
| ชื่อใด ๆ เบอร์เดิม ยังไม่เคยรับโครงการ/บริษัทนี้ | 1       | ส่ง            |
| ชื่อใด ๆ เบอร์ใหม่ ยังไม่เคยรับโครงการ/บริษัทนี้ | 1       | ส่ง            |

กรณีเคยรับสิทธิ์เดิมแล้ว การเปลี่ยนวันเวลา 00:00 น. ไม่ทำให้รับคูปองของโครงการ/บริษัทนั้นใหม่หรือส่งลีดเพิ่ม การได้รับคูปองต้องผ่านเงื่อนไขแคมเปญเดิมด้วย

### **6.5 ข้อมูลอ้างอิงและผลส่ง**


1. การลงทะเบียนใหม่ที่ผ่านกฎของ Flow ต้องเข้ารายชื่อผู้สนใจและ LINE “ลูกค้ามาแล้ว” ทั้งสองช่องทาง
2. ข้อมูลทั้งสองทางต้องอ้างอิงการลงทะเบียนเดียวกัน พร้อมรายการหรือแบบฟอร์มต้นทางและผู้รับที่ถูกต้อง
3. Center/จังหวัดและผู้รับของแต่ละจุดใช้ตามกฎหน้าต้นทาง รวมถึงฟอร์มหลายรายการและแคมเปญที่มีวิธีกระจายข้อมูลเฉพาะ
4. การเปิด/ปิด UI ไม่เพิ่มการส่ง และต้องยืนยันผลบันทึกจริงก่อนแสดงสำเร็จ
5. กฎชื่อ/เบอร์ในตารางเป็นเกณฑ์รับลงทะเบียนและกันลีดซ้ำ ไม่ได้กำหนดวิธีรวมบุคคลหรือสูตรรายงานสถิติใหม่

## **8) Requirement** 

ฟอร์มลงทะเบียนสนใจหรือขอให้ติดต่อกลับทุกจุดในเว็บไซต์น่าอยู่ ทั้งหน้า Center และจังหวัด บน Desktop และ Mobile ต้องรับเบอร์โทรเป็นตัวเลขครบ 10 หลักโดยไม่จำกัดเลขขึ้นต้น ใช้กฎตรวจเดียวกันทั้ง Frontend และ Backend เมื่อผู้ใช้ยืนยันและผ่านเงื่อนไขฟอร์มกับกฎกันซ้ำ ให้บันทึกและส่งเข้ารายชื่อผู้สนใจพร้อม LINE “ลูกค้ามาแล้ว” โดยอ้างอิงรายการหรือแบบฟอร์มต้นทางและผู้รับให้ถูกต้อง

ฟอร์มธรรมดากรณีชื่อเดิม+เบอร์เดิมของรายการนั้น ไม่เพิ่มลีดหรือส่งรายชื่อ/LINE ซ้ำในวันเดียวกัน โดยเริ่มรอบใหม่ทุกวันเวลา 00:00 น. ตาม Asia/Bangkok ส่วนชื่อเดิม+เบอร์ใหม่ ชื่อใหม่+เบอร์เดิม และชื่อใหม่+เบอร์ใหม่ที่ผ่านเงื่อนไขให้รับและส่งตามตาราง 6.1 กรณี Walk-in ตรวจสิทธิ์ตามโครงการ/บริษัทและเบอร์โทร ผู้ที่เคยรับสิทธิ์เดิมแล้วไม่รับใหม่เพียงเพราะเปลี่ยนวัน

แต่ละจุดแสดง Section, Modal, Tab และผลลัพธ์ตาม UI ของตน สำหรับฟอร์มในแกลเลอรี ให้แสดงเป็น Tab ลงทะเบียนแยกจากรายการภาพ เมื่อผลลงทะเบียนแสดงเป็น Modal แล้วปิด Tab และฟอร์มยังอยู่ การเปิดหรือปิด UI อย่างเดียวไม่สร้างการลงทะเบียนใหม่ การสมัครบัญชี/เข้าสู่ระบบ/OTP ใช้กฎบัญชีเฉพาะของตน
