ตอนนี้ BE รับ header นี้ได้แล้วโดยไม่ต้องแก้โค้ดอะไร FE ส่งได้ทุก request ตามที่ระบุไว้ในเอกสาร

**สถานะแต่ละข้อ**


1. **รับเฉพาะ** `**th**`**/**`**en**`**/**`**zh**` **ถ้าไม่มี header หรือเป็นค่าอื่นให้ใช้** `**th**`**:** ตรงตามนี้อยู่แล้ว เพราะตอนนี้ยังไม่มี service ไหนอ่าน header นี้ ทุก request จึงได้ผลเหมือนส่ง `th` มา
2. **Cache /** `**Vary**`**:** ตอนนี้ยังไม่ต้องตั้ง เพราะ response ยังไม่เปลี่ยนตามภาษา ข้อความเนื้อหายังส่งเป็น `{ th, en, zh }` ชุดเดียวเหมือนเดิม Redis และ APISIX จึงไม่มีทางส่งภาษาผิดหน้า ถ้า endpoint ไหนเริ่มเลือกภาษาตาม header เมื่อไร BE จะตั้ง `Vary: Accept-Language` ให้ endpoint นั้นพร้อมกัน
3. **CORS:** ไม่ต้องแก้ ตามที่ FE แจ้งมา
4. `**/api/locations/tree**`**,** `**/tree/children**`**,** `**/tree/node**`**:** ไม่ได้อ่าน header และ label ยังส่งเป็น `{ th, en, zh }` ตามเดิม cache ร่วมกันได้

**ข้อความที่ BE สร้างตอนรับ request (**`**error.message**`**,** `**message**`**, email/SMS/LINE)**

* ตอนนี้ยังเป็น string ภาษาเดียวตามเดิม ส่วนใหญ่ `error.message` เป็นข้อความเทคนิคภาษาอังกฤษ เช่น `invalid company id` FE แสดงตามที่ได้รับไปก่อนได้
* รอบนี้ BE ยังไม่แปลทุกข้อความ เพราะมีหลายร้อยจุดใน BFF และ service อื่นๆ และส่วนใหญ่เป็น error ที่ผู้ใช้ไม่เห็น

**ขอ FE ช่วยส่งรายการ** ช่วยส่งรายการข้อความที่ FE **แสดงให้ผู้ใช้เห็นจริง** มาให้หน่อย ขอเป็น endpoint + เงื่อนไขที่เกิด + ข้อความปัจจุบัน เช่น ผลส่ง lead form, ผลรับคูปอง, OTP SMS ได้รายการแล้ว BE จะแปลชุดนั้นตามภาษาใน header และตั้ง `Vary: Accept-Language` ให้ endpoint เหล่านั้น
