**คำตัดสินล่าสุด:** ใช้แบบที่ 1 จากภาพเปรียบเทียบ คือรวม Click และ Impression ของไทย จีน อังกฤษ และ Desktop/Mobile ภายใน **Source Slot เดียวกันของ Product Top Banner** ก่อนหา CTR แล้วได้ **น้ำหนัก A/B ชุดเดียวต่อ Source Slot** ใช้น้ำหนักนี้ร่วมทุกภาษาและอุปกรณ์ ไม่ใช้ค่าน้ำหนักแยกภาษาแบบที่ 2 ของต้นทาง

คงกฎจังหวัดปัจจุบันรวมหมวดน่าอยู่ ไทยบังคับและไทยสำรอง Shuffle Candidate แล้วเลือกสูงสุด8 Slot ตลอดจนขนาดภาพ การเลื่อนทุก4วินาที และการคงชุดระหว่าง Loop ตาม [Solution Top Banner จังหวัดต้นทาง](https://wiki.infonayoo.co/doc/solution-top-banner-3-ab-7030-shuffle-slot-MKZCVcJPBC) revision89 อ่าน2026-11-04 07:46:20UTC เอกสารนี้เป็นหน้า Solution ใหม่ ไม่ใช่การแก้ต้นทางหรือหลักฐานว่าระบบจริงพัฒนาแล้ว ตัวเลขและภาพจำลองเป็นข้อมูลสมมติ

## EP-01 ขอบเขตและเงื่อนไขการแสดงผล

**หลักการทำงาน:** ดึง Top Banner จังหวัดปัจจุบันรวมหมวดน่าอยู่ → ตรวจสถานะ เวลา สิทธิ์ และไทยบังคับตรงอุปกรณ์ → Shuffle Candidate ทั้งหมด → เลือกไม่เกิน8 Source Slot → เลือกภาษาผู้ใช้หรือไทยสำรองตรงอุปกรณ์ → ถ้ามี A/B ครบเลือกหนึ่งภาพด้วยน้ำหนักรวมของ Source Slot → แสดง Source ละหนึ่งภาพในชุดสไลด์

| รหัส | หัวข้อ | เงื่อนไข / การกระทำ | Logic การแสดงผล / การทำงาน |
|------|--------|---------------------|----------------------------|
| TBM1-01 | ขอบเขต Product | ใช้ Solution นี้    | ใช้เฉพาะ Top Banner จังหวัด ไม่รวมข้อมูลหรือกฎแสดงผลของ Banner, Pop-up หรือ Insert Card |
| TBM1-02 | จังหวัด | ผู้ใช้อยู่เว็บไซต์ขอนแก่น | ใช้ Top Banner ที่มีสิทธิ์ของขอนแก่น ไม่ยืมจังหวัดอื่นมาเติม |
| TBM1-03 | หมวดน่าอยู่ | รายการน่าอยู่ของจังหวัดปัจจุบันผ่านเงื่อนไข | รวม Candidate ร่วมกับโครงการใหม่ รับสร้างบ้าน และหมวดอื่นที่มีสิทธิ์ |
| TBM1-04 | เงื่อนไขเดิม | ตรวจรายการและภาพ    | คงสถานะ ช่วงเวลา สิทธิ์ และประเภทหน้าตามต้นทาง การมีภาพตรงภาษาไม่ทำให้ข้ามเงื่อนไขเหล่านี้ |
| TBM1-05 | จำนวน  | มี Candidate S รายการ | Shuffle ทั้ง S ก่อนเลือก M=MIN(S,8) รายการแรก ไม่บังคับครบ8 |
| TBM1-06 | หน่วยนับ | Source มีหลายภาษา อุปกรณ์ และ A/B | นับ Source เดียว ไม่เพิ่มน้ำหนักในการ Shuffle หรือแตกเป็นหลาย Slot |
| TBM1-07 | น้ำหนักแบบที่1 | Source ถูกเลือกและภาษาที่ใช้มี A/B ครบ | ใช้ P_A/P_B ชุดเดียวของ Source นั้น ทุกภาษาและอุปกรณ์ใช้ชุดเดียวกัน |

## EP-03 เลือกภาษา อุปกรณ์ และไทยสำรอง

**ภาษาผู้ใช้บนอุปกรณ์ปัจจุบัน → ถ้าไม่มีให้ใช้ไทยของ Source เดิมบนอุปกรณ์นั้น** การเลือกไฟล์ยังแยกตามภาษา แต่การเลือก A/B ใช้น้ำหนักรวมของ Source

| รหัส | เงื่อนไข | Logic การทำงาน |
|------|----------|----------------|
| TBM1-L01 | ผู้ใช้เลือกไทย | ใช้ชุดไทยตรงอุปกรณ์ของ Source เดิม |
| TBM1-L02 | ผู้ใช้เลือกจีน/อังกฤษและมีภาพภาษานั้นใช้ได้ | ใช้ภาษานั้นก่อน ไม่เปลี่ยนไปไทยเพียงเพราะไทยมี A/B มากกว่า |
| TBM1-L03 | ไม่มีภาษาที่ผู้ใช้เลือกบนอุปกรณ์ปัจจุบัน | ใช้ไทยสำรองของ Source เดิม ไม่ใช้จีนแทนอังกฤษหรืออังกฤษแทนจีน |
| TBM1-L04 | ภาษาหลักมีเพียง A หรือ B | ใช้ฝั่งที่มี100% ไม่เติมอีกภาษาหรือสร้างสไลด์ว่าง |
| TBM1-L05 | ไทยสำรองมี A/B ครบ | เลือกไทย A/B ด้วย P_A/P_B รวมของ Source เดียวกัน ไม่ใช้น้ำหนักไทยแยกภาษา |
| TBM1-L06 | ภาษาหลักมี A/B ครบ | ใช้ P_A/P_B รวมชุดเดียวกัน แม้ภาษานั้นยังไม่มี input ของตน หาก Source มีน้ำหนักรวมที่ใช้ได้แล้ว |
| TBM1-L07 | อังกฤษมีเฉพาะ Desktop แต่ใช้ Mobile | ใช้ไทย Mobile ไม่ยืมไฟล์ Desktop |
| TBM1-L08 | ไม่มีไทยที่ใช้ได้ตรงอุปกรณ์ | ข้อมูลไม่ผ่าน requirement ของ Candidate ไม่ใช่กรณี fallback ปกติ |
| TBM1-L09 | ใช้ไทยสำรองบนเว็บอังกฤษ/จีน | เว็บไซต์คงภาษาที่ผู้ใช้เลือก ภาพไม่ถูกแปลอัตโนมัติ |
| TBM1-L10 | เกิดเหตุการณ์กับภาพไทยสำรอง | บันทึกภาษาภาพจริงเป็นไทยในคู่อุปกรณ์นั้นหนึ่งครั้ง แล้วนำยอดไปอยู่ในผลรวม Source ไม่ลงซ้ำให้ภาษาเว็บไซต์ |

## EP-04 Shuffle Source และเลือก A/B ภายใน

| รหัส | หัวข้อ | เงื่อนไข / การกระทำ | ผลการทำงาน |
|------|--------|---------------------|------------|
| TBM1-S01 | หน่วย Shuffle | เตรียม Candidate    | Source หนึ่งเข้า Shuffle หนึ่งรายการ ไม่ใช้จำนวนภาษา/ภาพเป็นน้ำหนัก |
| TBM1-S02 | เพดาน  | Candidateมากกว่า8   | สุ่มลำดับทั้งหมดแล้วเลือก8แรก ไม่ตัด Candidate เหลือ8ก่อนสุ่ม |
| TBM1-S03 | หมวด/ไทยสำรอง | มีน่าอยู่และรายการใช้ไทยสำรอง | ร่วม Shuffle ตามปกติ ไม่จัดท้ายเป็นพิเศษ |
| TBM1-S04 | แยกจาก A/B | มี weight รวมของแต่ละ Source | ไม่ใช้ CTR หรือ weight A/B มาเรียง Source แทน Shuffle |
| TBM1-S05 | A/Bครบ | เลือกภาษาและอุปกรณ์ได้แล้ว | สุ่มหนึ่งภาพด้วย weight รวมล่าสุดของ Source นั้น |
| TBM1-S06 | มีภาพเดียว | เหลือAหรือBที่ใช้ได้เพียงฝั่งเดียว | ใช้ฝั่งนั้น100% ไม่สุ่มไปฝั่งที่ใช้ไม่ได้ |
| TBM1-S07 | เลือกภาพแล้ว | ชุดสไลด์ถูกจัดไว้   | อีกภาษา อีกอุปกรณ์ หรือ A/B ที่ไม่ได้เลือกไม่กลายเป็นภาพเพิ่ม |
| TBM1-S08 | เลื่อน/Loop | ใช้ชุดเดิม          | คงลำดับและภาพ ไม่สุ่มใหม่ทุกรอบ |

**1 Source ที่เลือก = 1ภาพในชุด** น้ำหนักเป็นโอกาสเลือกต่อ Source ตอนจัดชุดใหม่ ไม่ใช่โควตา เช่น70:30ไม่รับประกันว่าในทุก10ครั้งต้องได้ A7/B3 และไม่ได้หมายถึงแบ่ง8 Slotเป็นกลุ่ม A/Bตามจำนวนตายตัว

### 10.2 สูตร

ใช้ข้อมูลหลังresetล่าสุดของแต่ละคู่ i ในSourceเดียวกัน

```text
TOTAL_CLICK_A = SUM(CLICK_A[i]) จาก6คู่ภาษา–อุปกรณ์
TOTAL_IMP_A = SUM(IMP_A[i]) จาก6คู่ภาษา–อุปกรณ์
TOTAL_CLICK_B = SUM(CLICK_B[i]) จาก6คู่ภาษา–อุปกรณ์
TOTAL_IMP_B = SUM(IMP_B[i]) จาก6คู่ภาษา–อุปกรณ์

CTR_A = TOTAL_CLICK_A / TOTAL_IMP_A × 100
CTR_B = TOTAL_CLICK_B / TOTAL_IMP_B × 100
RAW_P_A = CTR_A / (CTR_A + CTR_B) × 100
P_A = MAX(30, MIN(70, RAW_P_A))
P_B = 100 - P_A
```

ใช้สูตรเมื่อTOTAL_IMP_AและTOTAL_IMP_Bมากกว่า0 และCTR_A+CTR_Bมากกว่า0 มิฉะนั้นP_A=P_B=50 คำนวณจากค่าจริงก่อนย่อทศนิยมสำหรับแสดงผล

| CTRรวมA | CTRรวมB | ดิบA:B | น้ำหนักใช้จริง |
|---------|---------|--------|----------------|
| 3%      | 2%      | 60:40  | 60:40          |
| 9%      | 1%      | 90:10  | 70:30          |
| 1%      | 9%      | 10:90  | 30:70          |
| 2%      | 2%      | 50:50  | 50:50          |
| 0%แต่มีIMP | 2%      | 0:100  | 30:70          |
| 2%      | 0%แต่มีIMP | 100:0  | 70:30          |
| 0%      | 0%      | หารศูนย์ไม่ได้ | 50:50          |
| ฝั่งใดIMPรวมเป็น0 | —       | ข้อมูลยังไม่ครบ | 50:50          |

ตัวอย่างจำกัดช่วง: ดิบA90%→MIN(70,90)=70→MAX(30,70)=70; ดิบA10%→MIN(70,10)=10→MAX(30,10)=30; ดิบA60%อยู่ในช่วงจึงคง60% ไม่เพิ่มเกณฑ์จำนวนIMPขั้นต่ำหรือนัยสำคัญทางสถิติที่ยังไม่ได้กำหนด

### 11.2 ขั้นที่ 2: คำนวณหา CTR รวม และคิดเป็นน้ำหนักสุ่ม A : B ชุดเดียว

| **1. หา CTR รวมของฝั่ง A** | `440 ÷ 12,000 × 100` | **3.6666667%** |
| **2. หา CTR รวมของฝั่ง B** | `280 ÷ 12,000 × 100` | **2.3333333%** |
| **3. เทียบสัดส่วนน้ำหนักดิบของฝั่ง A** | `3.6666667 ÷ (3.6666667 + 2.3333333) × 100` | **61.1111111%** *(คำนวณจากค่าจริงก่อนปัดเศษ)* |
| **4. น้ำหนักที่ใช้สุ่มจริง (อยู่ในกรอบ 30–70%)** | อยู่ในกรอบ 30–70% อยู่แล้ว จึงใช้ค่าตามจริง | **ฝั่ง A = 61.11% / ฝั่ง B = 38.89%** |
| **การนำไปใช้กับแต่ละภาษา (ไทย / จีน / อังกฤษ)** | เมื่อภาษานั้นมีรูป A และ B ครบ | **ใช้น้ำหนัก** `**61.11 : 38.89**` **ชุดเดียวกันทั้งหมด** |
| **การนำไปใช้กับอุปกรณ์ (Desktop / Mobile)** | เมื่อเปิดบนคอมพิวเตอร์หรือมือถือ | **ใช้น้ำหนัก** `**61.11 : 38.89**` **ร่วมกัน** โดยดึงไฟล์รูปให้ตรงกับอุปกรณ์ที่ใช้ |

### 11.3 ขั้นที่ 3: รายงานสถิติยังดูแยกภาษาได้เหมือนเดิม (แม้จะใช้น้ำหนักสุ่มร่วมกัน)

แม้ระบบจะใช้น้ำหนักสุ่มชุดเดียว (`61.11 : 38.89`) กับทุกภาษา แต่ข้อมูลสถิติจริงยังถูกเก็บแยกตามภาษาและอุปกรณ์ ทำให้สามารถดูรายงาน CTR แยกรายภาษาได้ตามปกติโดยข้อมูลไม่ถูกยุบรวมกัน:

| ภาษาของรูปที่แสดงจริง | สถิติฝั่ง A (คลิก / มองเห็น) | CTR ฝั่ง A | สถิติฝั่ง B (คลิก / มองเห็น) | CTR ฝั่ง B | น้ำหนักที่ใช้สุ่มแสดงรูป (เมื่อมี A/B ครบ) |
|:----------------------|:----------------------------:|:----------:|:----------------------------:|:----------:|:------------------------------------------:|
| **ไทย**               | 400 / 10,000                 | **4%**     | 200 / 10,000                 | **2%**     | **61.11 : 38.89**                          |
| **จีน**               | 10 / 1,000                   | **1%**     | 50 / 1,000                   | **5%**     | **61.11 : 38.89**                          |
| **อังกฤษ**            | 30 / 1,000                   | **3%**     | 30 / 1,000                   | **3%**     | **61.11 : 38.89**                          |

* **ข้อสังเกตสำคัญ:**
  * หากดูเฉพาะ **ภาษาจีน** จะเห็นว่า **ฝั่ง B มี CTR สูงกว่าฝั่ง A** (`B = 5%` vs `A = 1%`)
  * แต่เนื่องจาก **แบบที่ 1 คิดน้ำหนักจากยอดรวมทั้งรายการ** (ซึ่งภาษาไทยมีคนดูเยอะกว่าและฝั่ง A ชนะ) ตอนสุ่มแสดงรูปภาษาจีนจึงยังคงใช้น้ำหนักรวม `**61.11 : 38.89**` เหมือนกับภาษาอื่น (ไม่ได้แยกไปใช้น้ำหนักเฉพาะภาษาแบบที่ 2 ที่จะได้ ไทย `66.67 : 33.33`, จีน `30 : 70`, อังกฤษ `50 : 50`)
  * ทั้งนี้ การเก็บข้อมูลแยกตามภาษาของรูปที่แสดงจริงและอุปกรณ์ ช่วยให้ยังดูตัวเลข CTR แยกรายภาษาได้ครบถ้วน (โดยเอกสารนี้กำหนดเฉพาะ Logic ของข้อมูล ไม่ได้เพิ่มหน้าจอรายงานใหม่)

## EP-12 ตัวอย่างเมื่อเปลี่ยนรูปภาพ: ล้างคะแนนเฉพาะคู่ที่แก้ แต่ปรับน้ำหนักรวมเป็น 50:50 ชั่วคราว

อ้างอิงข้อมูลรายการ **SX** จาก EP-11 (เดิมมียอดรวม 6 คู่: ฝั่ง A = 440 คลิก / 12,000 การมองเห็น, ฝั่ง B = 280 คลิก / 12,000 การมองเห็น และมีน้ำหนักสุ่มรวมอยู่ที่ **61.11 : 38.89**)

* **สถานการณ์สมมติ:** ผู้ใช้กดเปลี่ยนเฉพาะรูป **จีน–Mobile ฝั่ง A** เพียงรูปเดียว (ส่วนรูปอื่นอีก 5 คู่ไม่ได้แก้ไข)

### 12.1 เกิดอะไรขึ้น "ทันที" ที่กดบันทึกเปลี่ยนรูป

| สิ่งที่ระบบจัดการ | ข้อมูลก่อนแก้รูป | ผลลัพธ์ทันทีหลังแก้รูป |
|:------------------|:-----------------|:-----------------------|
| **1. คะแนนคำนวณ A/B ของคู่** `**จีน–Mobile**` **(คู่ที่แก้)** | • ฝั่ง A: 5 คลิก / 500 การมองเห็น<br>• ฝั่ง B: 25 คลิก / 500 การมองเห็น | **เริ่มนับใหม่เป็น 0 / 0 ทั้งฝั่ง A และ B**<br>*(แม้แก้แค่รูป A รูปเดียว ก็ต้องล้างฝั่ง B ของคู่นี้ด้วยเพื่อเริ่มเทียบกันใหม่)* |
| **2. คะแนนคำนวณ A/B ของอีก 5 คู่ที่ไม่ได้แก้** | • ฝั่ง A รวม: 435 คลิก / 11,500 การมองเห็น<br>• ฝั่ง B รวม: 255 คลิก / 11,500 การมองเห็น | **เก็บยอดสะสมเดิมไว้ครบ ไม่ถูกล้างตาม** |
| **3. น้ำหนักสุ่ม A:B ของรายการ SX** | **61.11 : 38.89** | **ปรับเป็น 50 : 50 ทันที (ทุกภาษาและทุกอุปกรณ์)**<br>ใช้ชั่วคราวไปจนกว่าจะถึงรอบคำนวณหลังเที่ยงคืน (00:00 น.) |
| **4. สถิติจริงสำหรับดูรายงาน (Performance)** | มีประวัติครบทุกคู่ | **เก็บประวัติเดิมไว้ทั้งหมด ไม่ถูกลบตามคะแนนคำนวณ** |
| **5. หน้าจอของผู้ใช้ที่เปิดดูสไลด์อยู่ก่อนแล้ว** | แสดงตามลำดับและรูปเดิม | **แสดงรูปเดิมต่อไปขณะเลื่อนหรือวนลูป**<br>ส่วนคนที่โหลดหน้าใหม่จะได้ใช้น้ำหนัก 50 : 50 |

> **สรุปหลักการสำคัญ:** ระบบล้างคะแนนเฉพาะคู่ `จีน–Mobile` ที่ถูกแก้รูปเท่านั้น (ไม่ได้ล้างทั้ง 6 คู่) แต่เพราะแบบที่ 1 ใช้ **"น้ำหนักสุ่มชุดเดียวร่วมกันทั้งรายการ"** จึงต้องปรับน้ำหนักสุ่มของรายการนี้เป็น **50 : 50 ชั่วคราว** จนกว่าจะคำนวณใหม่ตอนเที่ยงคืน

### 12.2 เกิดอะไรขึ้นเมื่อถึง "รอบคำนวณเที่ยงคืนถัดไป" (หลัง 00:00 น.)

เมื่อข้ามเที่ยงคืน ระบบจะนำ **[คะแนนของ 5 คู่เดิมที่เก็บไว้] + [คะแนนใหม่ของคู่** `**จีน–Mobile**` **หลังแก้รูป]** มารวมกันเพื่อคิดน้ำหนักใหม่ทันที:

| กรณีตัวอย่างหลังเที่ยงคืน | ยอดรวมฝั่ง A (คลิก / มองเห็น) | ยอดรวมฝั่ง B (คลิก / มองเห็น) | CTR รวม (A / B) | น้ำหนักสุ่มใหม่ที่ได้ |
|:--------------------------|:------------------------------|:------------------------------|:----------------|:----------------------|
| **กรณีที่ 1:** คู่ `จีน–Mobile` ยังไม่มีคนดูเพิ่มเลย (0/0) | **435 / 11,500**<br>*(มาจาก 5 คู่เดิม)* | **255 / 11,500**<br>*(มาจาก 5 คู่เดิม)* | 3\.78% / 2.22%  | **63.04 : 36.96**     |
| **กรณีที่ 2:** คู่ `จีน–Mobile`มีคะแนนใหม่เข้ามา<br>*(A ได้ 12/200, B ได้ 2/200 และอีก 5 คู่เท่าเดิม)* | **447 / 11,700**<br>*(435+12 / 11,500+200)* | **257 / 11,700**<br>*(255+2 / 11,500+200)* | 3\.82% / 2.20%  | **63.49 : 36.51**     |

* **ข้อสังเกต:** แม้คู่ `จีน–Mobile` ที่เพิ่งแก้จะยังไม่มีคนเข้ามาดูเลย (เป็น 0/0) เมื่อถึงเที่ยงคืนระบบก็จะคำนวณน้ำหนักใหม่จาก **5 คู่เดิมที่มีข้อมูลอยู่** ได้เลย (`63.04 : 36.96`) ไม่ต้องค้างที่ `50 : 50` รอให้ครบทุกคู่

### 12.3 ข้อควรระวังเรื่องสถิติ และกรณีอื่น ๆ

* **ห้ามนำสถิติรายงาน (Performance) เก่าก่อนแก้รูป กลับมาปนในการคำนวณรอบใหม่:**
  * ระบบต้องแยก **"สถิติสำหรับโชว์ในรายงาน"** ออกจาก **"คะแนนสำหรับคำนวณน้ำหนัก A/B"**
  * *ตัวอย่าง:* หากเผลอนำคะแนนเก่าของ `จีน–Mobile` ก่อนแก้รูปมารวมกับคะแนนใหม่ จะได้ยอดผิดเป็น `A = 452/12,200` และ `B = 282/12,200` ซึ่งจะได้น้ำหนักเพี้ยนเป็น `61.58 : 38.42` (แทนที่จะเป็นค่าที่ถูกต้องคือ `**63.49 : 36.51**`)

| เหตุการณ์ | การทำงานของระบบ |
|:----------|:----------------|
| **แก้รูปพร้อมกันหลายคู่** | ล้างคะแนนคำนวณ A/B เฉพาะคู่ที่แก้ทั้งหมด และปรับน้ำหนักสุ่มของรายการเป็น **50 : 50** จนถึงรอบเที่ยงคืนถัดไป |
| **แก้รูปครบทั้ง 6 คู่** | ล้างคะแนนคำนวณ A/B ทั้ง 6 คู่เริ่มใหม่จาก 0/0 (ยังเก็บประวัติรายงานไว้) และใช้น้ำหนัก **50 : 50** จนกว่าจะมีข้อมูลคำนวณรอบใหม่ |
| **ผู้ใช้เปลี่ยนภาษาเว็บ หรือกด Refresh หน้า** *(โดยไม่ได้แก้ไฟล์รูป)* | **ไม่ล้างคะแนน** และไม่คำนวณน้ำหนักใหม่ทันที (ใช้ค่าน้ำหนักล่าสุดที่มีอยู่) |
| **ข้ามเที่ยงคืน (00:00 น.) โดยไม่มีการแก้รูป** | **ไม่ล้างคะแนนสะสม** นำยอดสะสมที่มีอยู่มาคำนวณน้ำหนักประจำวันตามปกติ |
| **มีการแก้รูปในรายการโฆษณาอื่น (คนละรายการ)** | **ไม่กระทบ**คะแนนหรือน้ำหนักของรายการ SX |
