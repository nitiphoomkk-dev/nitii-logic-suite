API ของ Back Office ส่วนจัดการแคมเปญ (รายการแคมเปญ, สร้าง / แก้ไขแคมเปญ 6 ขั้น, รายชื่อผู้สนใจของแคมเปญ) เขียนจากโค้ดฝั่ง FE ของ Back Office (repo `next-frontend-backoffice-service`, branch `feature/campaign-color-config`) ณ 10 พ.ย. 2569

> **อ่านก่อน** เอกสารนี้สรุปจากโค้ดที่ FE เรียกและอ่านจริง **ไม่ได้ยิง API ทุกเส้นเพื่อคัด response** ตัวอย่าง JSON สร้างจาก type ที่ FE ใช้ ไม่ใช่ response จริงจาก dev ส่วนที่ FE ทำฟอร์มไว้แล้วแต่ API ยังไม่มี แยกไว้ในหัวข้อ 4 เป็น **ร่าง** ต้องตกลงกับ Backend ก่อน (คำถามอยู่ในหัวข้อ 6)

สัญลักษณ์สถานะ: ✅ FE เรียกใช้อยู่ตอนนี้ / 📝 ร่าง FE มีฟอร์มแล้วแต่ยังไม่ส่งหรือยังไม่อ่านจาก API

## 2. กติกากลาง

### Header

ทุกเส้นข้างบน (ยกเว้นระบุไว้) ส่ง

| Header | ค่า |
|--------|-----|
| `apikey` | `NEXT_PUBLIC_API_KEY` |
| `Authorization` | `Bearer <accessToken>` ของผู้ใช้ที่ login |
| `province` | id จังหวัดที่เลือกอยู่ (ตัวเลขตัวเดียว ไม่ใช่ list `province_ids` ของ user) |
| `Content-Type` | `application/json` |

`GET /api/leads` ส่ง header ระบุผู้กระทำเพิ่มตาม spec ของ Leads

### Envelope

```json
{ "success": true, "data": { }, "message": "..." }
```

Error: HTTP ไม่ใช่ 2xx หรือ `success: false` พร้อม

```json
{ "success": false, "error": { "code": "...", "message": "...", "traceId": "...", "chain": ["..."] } }
```

FE แสดง `error.message` (ต่อท้ายด้วย `chain` ถ้ามี) เป็น toast

### ข้อความหลายภาษา (`localized string`)

ฟิลด์ชื่อ / คำอธิบาย / หัวข้อ ใช้รูป `{ "th": "...", "en": "...", "cn": "..." }` ตอนนี้ **FE ส่งเฉพาะ** `**th**` และตอนอ่านเลือก `th` → `en` → `cn` (ดูข้อ 6 เรื่อง `cn` กับ `zh`)

### วันที่ / เวลา

* ส่งเป็น ISO 8601 UTC (`Date.toISOString()`) จากเวลาท้องถิ่นของเบราว์เซอร์ (Asia/Bangkok)
* ตัวเลือกวันในฟอร์มเป็นวันที่ล้วน ได้ `00:00` ตามเวลาไทย เช่น 15 พ.ย. 2569 = `2026-11-14T17:00:00.000Z`
* `web_period.end_at` ส่งเป็น **สิ้นวัน** `23:59:59.999` ตามเวลาไทย เช่น 30 พ.ย. = `2026-11-30T16:59:59.999Z`
* `onsite.start_at` / `end_at` รวม "วัน" กับ "เวลา (HH:mm)" ที่กรอก

### รูปภาพ

ทุก `*_image_path`, `images[]`, `icon_image_path` ฯลฯ เป็น **storage key / path** ที่ได้หลังอัปโหลด (ข้อ 3.11) FE ไม่ส่ง base64 หรือไฟล์ใน body ของแคมเปญ ถ้าช่องไหนไม่มีรูป FE ส่ง `""` หรือไม่ส่งตามที่ระบุในตาราง

### ชื่อหมวดที่ใช้ในแต่ละ API

| ฟอร์ม step 1 | event-campaign API | listing-picker `category` | ป้ายในรายการ BO |
|--------------|--------------------|-------------------------|-----------------|
| โครงการใหม่  | `new`              | `new`                   | โครงการใหม่     |
| อสังหาฯ มือสอง | `secondhand`       | `secondhand_sale`       | อสังหาฯ มือสอง  |
| เช่า / หอพัก | `rent`             | `secondhand_rent`       | เช่า / หอพัก    |
| รับสร้างบ้าน | `home_builder`     | `home_builder`          | รับสร้างบ้าน    |

## 3. Endpoint ที่ใช้อยู่

### 3.1 `GET /api/event-campaigns` รายการแคมเปญ

Query

| Param | ชนิด | ความหมาย |
|-------|------|----------|
| `page` | number | เริ่มที่ 1 |
| `per_page` | number | จำนวนต่อหน้า |
| `search` | string | ค้นหา (ส่งเฉพาะเมื่อไม่ว่าง) |

ตัวอย่าง response (ประกอบจาก type ของ FE)

```json
{
  "success": true,
  "data": {
    "items": [
      {
        "campaign_id": 10,
        "slug": "home-expo-2026",
        "name": { "th": "Home Expo 2026" },
        "promote_image_path": "uploads/promote.webp",
        "logo_image_path": "uploads/logo.webp",
        "participant_types": ["new", "secondhand", "rent", "home_builder"],
        "participant_counts": { "new": 12, "secondhand": 4, "rent": 2, "home_builder": 3, "top": 5 },
        "visibility": "online",
        "status": "active",
        "web_period": {
          "pre_event_at": "2026-11-09T17:00:00.000Z",
          "start_at": "2026-11-14T17:00:00.000Z",
          "end_at": "2026-11-30T16:59:59.999Z"
        },
        "lead_count": 128
      }
    ],
    "pagination": { "currentPage": 1, "itemsPerPage": 10, "totalItems": 1, "totalPages": 1 }
  }

```

Field ที่ FE อ่าน

| Field | ใช้ทำอะไร |
|-------|-----------|
| `campaign_id` | id แถว    |
| `slug` | ชื่อ URL  |
| `name` | ชื่อแคมเปญ (`localized string` หรือ string ก็ได้) |
| `promote_image_path` / `logo_image_path` | รูปในแถว (ใช้ promote ก่อน ไม่มีค่อยใช้ logo) |
| `participant_types[]` | ชิปหมวดที่ร่วม |
| `participant_counts.top` | คอลัมน์ "Top Campaign" |
| `lead_count` | คอลัมน์ผู้สนใจ |
| `visibility` | `draft` / `online` / `offline` |
| `status` | `pre_event` / `active` / `ended` |
| `web_period.*` | วันที่ Pre / เริ่ม / สิ้นสุด |

สถานะที่แสดงในตาราง (FE คำนวณ)

| เงื่อนไข (ตามลำดับ) | สถานะ |
|---------------------|-------|
| `visibility = draft` | แบบร่าง |
| `visibility = offline` | ออฟไลน์ |
| `status = pre_event` | รอออนไลน์ |
| `status = ended`    | สิ้นสุด |
| `web_period.end_at` ผ่านแล้ว | สิ้นสุด (FE เทียบกับเวลาเครื่องเอง) |
| อื่น ๆ              | ออนไลน์ |

`pagination` FE รับได้ทั้ง camelCase (`currentPage`, `itemsPerPage`, `totalItems`, `totalPages`) และ snake_case ขอให้ Backend เลือกแบบเดียว

### 3.2 `GET /api/event-campaigns/{id}` รายละเอียดแคมเปญ

ใช้ตอนเปิดหน้าแก้ไข ผลลัพธ์ถูกแปลงกลับเป็นฟอร์มทุก step ได้ `data` เป็น field เดียวกับ body ของข้อ 3.3 บวก

| Field เพิ่ม | ความหมาย |
|-------------|----------|
| `campaign_id` (หรือ `id`) | id แคมเปญ (FE อ่านทั้งสองชื่อ) |
| `participants[]` | ใบประกาศที่ร่วม พร้อม snapshot ของใบประกาศ (ดูตารางข้างล่าง) |
| `lucky_winners[]` | ผู้โชคดี (มี `id` / `winner_id`, `created_at`, `updated_at`, `order`) |
| `participant_counts` | `{ new, secondhand, rent, home_builder }` |
| `ghost_articles[].article` | `{ title, feature_image }` ของบทความ ใช้แสดงในรายการ (อ่านอย่างเดียว) |

`participants[]` ที่ FE อ่าน

| Field | หมายเหตุ |
|-------|----------|
| `participant_id`, `campaign_id` |          |
| `category` | `new` / `secondhand` / `rent` / `home_builder` |
| `entity_kind` | `post` (ใบประกาศ) หรือ `hb_branch` (รับสร้างบ้าน) |
| `entity_id`, `entity_sub_id` | id ใบประกาศ / บริษัท และ id จังหวัดสำหรับ `hb_branch` |
| `is_top` | Top Campaign |
| `joined_at` | วันที่เข้าร่วม |
| `campaign_videos[]` | `{ id, url, title, order }` FE ใช้เฉพาะอันแรก |
| `campaign_promotions[]` | `{ title, detail, images[], start_date, end_date, order }` FE ใช้เฉพาะอันแรก |
| `listing` | snapshot (ตารางถัดไป) หรือ `null` |

`participants[].listing`

| Field | ใช้ทำอะไร |
|-------|-----------|
| `display_id` | รหัสใบประกาศ |
| `name`, `owner_name`, `zone_name` | ชื่อ, เจ้าของ, ทำเล (localized) |
| `cover_image_path` / `logo_image_path` | รูปในตาราง |
| `property_type_label` | ประเภททรัพย์ |
| `price_range` หรือ `start_price`, `end_price`, `sale_price`, `rent_price` | ราคา (ใช้ `price_range` ก่อน) |
| `post_referent` | `{ company_id, company_name, post_name, project_id }` ใช้กับมือสอง |
| `coming_soon` | ป้าย coming soon (เฉพาะ `post`) ดูข้อ 6 |
| `created_at`, `updated_at` | วันที่ลง / แก้ |

ข้อสังเกตที่ FE ต้องจัดการเมื่ออ่าน

* `card_frames.<หมวด>` ตอน **บันทึก** เป็น string แต่ตอน **อ่าน** API ส่งกลับเป็น `{ "th": "uploads/x.webp", "en": "", "zh": "", "i18n": true }` FE รับได้ทั้งสองแบบ
* ถ้าไม่มี `section_order` หรือว่าง FE ใช้ลำดับเริ่มต้น (ข้อ 5)

### 3.3 `POST /api/event-campaigns` สร้าง, `PATCH /api/event-campaigns/{id}` แก้ไข

### 3.11 อัปโหลดรูป

FE ขอ presigned URL แล้ว `PUT` ไฟล์ขึ้นที่เก็บไฟล์เอง (`Content-Type` ตามไฟล์) หลังอัปโหลดเสร็จจึงเอา `key` ไปใส่ใน body ของแคมเปญ

| Endpoint | Body | ใช้ |
|----------|------|-----|
| `POST /api/upload/` | `{ key, fileName, contentType, expiresIn }` | ไฟล์เดียว |
| `POST /api/upload/multiple` | `{ key, files: [{ fileName, contentType }], expiresIn }` | หลายไฟล์พร้อมกัน |

* `key` ในที่นี้คือ **prefix โฟลเดอร์** ของแคมเปญคือ `event-campaign` (ถ้าไม่ส่ง ใช้ `posts`)
* `expiresIn` ค่าเริ่มต้น 900 วินาที
* response มี `url` (presigned PUT) และ `key` ของไฟล์ (หลายไฟล์ได้ `urls[]`)

### 3.12 `POST /api/upload/ingest-url`

```json

```


## 4. ร่าง: ฟอร์มมีแล้วแต่ API ยังไม่รับ / ยังไม่ส่งกลับ

> ทุกชื่อ field ในหัวข้อนี้เป็นข้อเสนอจากฝั่ง FE ยังไม่ได้ตกลงกับ Backend FE เก็บค่าไว้ในฟอร์มเท่านั้น ยังไม่ส่งและยังไม่โหลดตอนแก้ไข (ยกเว้น 4.5)

### 4.1 สีของแคมเปญ (step 2) `color_config`

รูปแบบสี (เป็น string)

* **gradient**: `linear-gradient(<deg>deg, rgba(r,g,b,a) 0%, rgba(r,g,b,a) 100%)` หรือ `radial-gradient(circle at center, rgba(r,g,b,a) 0%, rgba(r,g,b,a) 100%)` มี **สองจุดสีเท่านั้น** (เป็นรูปแบบเดียวที่ parser ของเว็บสาธารณะอ่านได้)
* **solid**: `rgba(r,g,b,a)`

```json
{
  "color_config": {
    "navbar": { "background": "<gradient>", "text": "<solid>" },
    "band_background": "<gradient>",
    "sections": {
      "booking_promotion": { "header": "<gradient>", "text": "<solid>", "background": "<gradient>" },
      "articles_videos":   { "header": "<gradient>", "text": "<solid>", "background": "<gradient>" },
      "promotion_videos":  { "text": "<solid>", "background": "<solid>" }
    },
    "button": { "background": "<gradient>", "text": "<solid>" }
  }
}
```

| Field | ฟอร์ม (`step2.colorConfig`) | ชนิดสี |
|-------|---------------------------|--------|
| `navbar.background` / `navbar.text` | `navbar.background` / `.text` | gradient / solid |
| `band_background` | `campaignBackground` (ใช้เมื่อ `background_type = campaign_color`) | gradient |
| `sections.booking_promotion.*` | `sections.bookingPromotion.*` | header gradient, text solid, background gradient |
| `sections.articles_videos.*` | `sections.articlesVideos.*` | header gradient, text solid, background gradient |
| `sections.promotion_videos.*` | `sections.promotionVideos.*` | text solid, background solid (พื้นขาวที่มีแสงวงกลมสองดวงจากสีนี้) |
| `button.*` | `button.*`                | background gradient, text solid |

รวม 13 ค่า เว็บสาธารณะ (หน้า landing) **ยังไม่อ่าน** `color_config` ใช้ธีมแบรนด์เดิม

```json
      "id": "uuid-หรือ-id-เดิม",

      "desktop_banners": [{ "image_path": "event-campaign/d1.webp", "link_url": "https://example.com" }],
      "mobile_banners":  [{ "image_path": "event-campaign/m1.webp", "link_url": "https://example.com" }],
      "categories": ["new", "secondhand"],
      "colors": {
        "header": "rgba(1,61,162,1)",
        "text": "rgba(255,255,255,1)",
        "background": "linear-gradient(180deg, rgba(1,61,162,1) 0%, rgba(248,101,1,1) 100%)"
      }
    }
  ]
}
```

* ส่งตามลำดับในรายการ (ลากเรียงในฟอร์ม)
* `title` 1–30 ตัวอักษร, `desktop_banners` และ `mobile_banners` อย่างละ ≥ 1 รูป, `categories` ≥ 1
* `header` และ `text` เป็นสีเดียว `rgba(...)`, `background` เป็น gradient สองจุด
* ปีกซ้าย-ขวาของแถบหัวข้อ **ไม่เก็บ** เป็นสีหนึ่งต่างหาก คือสี `header` ลดความสว่างเหลือ 78% (`filter: brightness(0.78)`) เว็บสาธารณะต้องคำนวณแบบเดียวกัน
* ในหน้า step 6 FE นับ "จำนวนใบประกาศ" ของ Main Sponsor จากใบประกาศที่ร่วมแคมเปญในหมวดของมัน (คำนวณฝั่ง FE ไม่ต้องมี field)

### 4.3 Flash Deal (step 5) `flash_deal`

ร่องรอยเดียวที่ API มีตอนนี้คือ slug `flash_deal` ใน `section_order` และ category `flash_deal` ของ lead

```json
{
  "flash_deal": {
    "is_visible": true,
    "start_date": "2026-11-20T00:00:00+07:00",
    "end_date": "2026-11-22T23:59:59+07:00",
    "logo_path": "event-campaign/fd-logo.webp",
    "desktop_banners": [{ "image_path": "event-campaign/fd-d1.webp", "link_url": "https://example.com" }],
    "mobile_banners":  [{ "image_path": "event-campaign/fd-m1.webp", "link_url": "https://example.com" }],
    "colors": {
      "header": "linear-gradient(260deg, rgba(1,61,162,1) 0%, rgba(1,61,162,1) 100%)",
      "text": "rgba(255,255,255,1)",
      "background": "linear-gradient(180deg, rgba(1,61,162,1) 0%, rgba(248,101,1,1) 100%)"
    },
    "listings": [
      { "category": "new", "listing_id": 3001, "is_top": true },
      { "category": "secondhand", "listing_id": 4120, "is_top": false }
    ]
  }
}
```

| Field | ฟอร์ม | กติกา (FE) |
|-------|-------|------------|
| `is_visible` | สวิตช์ที่หัวการ์ด | ปิดอยู่ = ไม่บังคับกรอกอะไร และไม่แสดงในสรุป |
| `start_date`, `end_date` | ช่วงวัน Flash Deal | เปิดอยู่ = บังคับทั้งคู่ และ `end_date` ต้องไม่ก่อน `start_date` |
| `logo_path` | โลโก้ Flash Deal | ไม่บังคับ, 0–1 รูป, อัตราส่วน 2:1 ถ้าไม่มี ไม่แสดงกรอบเทาในพรีวิว |
| `desktop_banners`, `mobile_banners` | แบนเนอร์ | เปิดอยู่ = ฝั่งละ ≥ 1 รูป แต่ละรูปมีลิงก์ของตัวเอง ลำดับตามที่แสดง |
| `colors.header`, `.background` | สีแถบหัว / พื้นหลัง | gradient สองจุด |
| `colors.text` | สีตัวอักษร | `rgba(...)` |
| `listings[]` | ตารางใบประกาศ | `category` เป็น `new` / `secondhand` / `rent` / `home_builder`, `listing_id` = id ใบประกาศ, `is_top` = Top Flash Deal |

### 4.4 รูปดัก Lead (step 2)

```json
{
  "lead_registration_images": {
    "new": "event-campaign/lead-new.webp",
    "secondhand": "event-campaign/lead-sh.webp",
    "rent": "event-campaign/lead-rent.webp",
```

* `lead_popup_image_path` = "ภาพ popup ลงทะเบียน ดัก Lead" บังคับ

### 4.5 ปกวิดีโอโปรโมท (step 1) `promote_videos[].cover_image_path`

**ส่งและอ่านแล้ว แต่ชื่อ field เป็นชื่อร่างที่ FE ตั้งเอง** (API ยังไม่มี)

* ส่งเมื่อมีรูปปก อ่านกลับแล้วไม่ไปดึงจากลิงก์วิดีโออีก (ถ้าไม่มี เช่น แคมเปญเก่า FE ดึงจากลิงก์เหมือนเดิม)
* ค่าเป็น storage key สำหรับ Shorts / TikTok (ได้จาก `ingest-url` ข้อ 3.12) หรือลิงก์ `i.ytimg.com` สำหรับ YouTube ปกติ
* ถ้า Backend ตรวจ key แบบเข้มงวด (strict) การบันทึกที่มีวิดีโอจะ error จนกว่าจะเพิ่ม field นี้
* `participants[].campaign_videos[]` ใช้ตัวอ่านเดียวกันแต่ **ยังไม่ส่งปก**

### 4.6 `campaign_registration` ของลีด (รายชื่อผู้สนใจของแคมเปญ)

ใส่ใน item ของ `GET /api/leads` (ทุก field optional หน้าจอยังแสดงได้จาก `type`, `category`, `display_snapshot`, `enroll` ถ้าไม่มี)

```json
{
  "campaign_registration": {
    "category": "new",
    "page": "Search รวมโครงการใหม่",
    "page_detail": "โครงการ A",
    "forward_status": "sent",
    "answers": [{ "question": "งบประมาณ", "answer": "3-5 ล้านบาท" }]
  }
}
```

| Field | ความหมาย |
|-------|----------|
| `category` | `brand_project`, `new`, `secondhand`, `rent`, `home_builder`, `campaign_special`, `flash_deal` ชิปในคอลัมน์ "ลงทะเบียนสนใจ" |
| `page` | "หน้าที่ลงทะเบียน" เช่น "Search รวมโครงการใหม่", "Landing Page" |
| `page_detail` | บรรทัดที่สอง เช่น ชื่อโครงการ, "Section ลงทะเบียน" |
| `forward_status` | `sent`, `not_sent` หรือ `""` (ไม่เกี่ยวข้อง แสดง "-") คอลัมน์ "ส่งรายชื่อลูกค้า" |
| `answers[]` | คำตอบของผู้สนใจตามลำดับที่แสดง ใน modal "ข้อมูลเพิ่มเติม" (คำถามต่างกันตามหมวด) |

## 5. `section_order` (step 6)

ส่ง array ของ slug ตามลำดับที่แสดงบนหน้า landing

| ลำดับเริ่มต้น | slug | ชื่อในหน้า BO | หมายเหตุ |
|---------------|------|---------------|----------|
| 1             | `hero` | ภาพโปรโมต, ลงทะเบียน, คำอธิบายแคมเปญ | ล็อก ตำแหน่งแรกเสมอ |
| 2             | `promote_videos` | วิดีโอโปรโมต  |          |
| 3             | `flash_deal` | Flash Deal    |          |
| 4             | `booking_promotion` | โปรโมชันจองบ้าน |          |
| 5             | `walkin_promotion` | โปร Walk-in   |          |
| 6             | `lucky_winners` | รายชื่อผู้โชคดี |          |
| 7             | `participants` | ใบประกาศที่เข้าร่วม (Main Sponsor) |          |
| 8             | `project_map` | แผนที่โครงการและบริษัทรับสร้างบ้านที่เข้าร่วม |          |
| 9             | `floor_plan` | แผนผังจัดแสดงแคมเปญ |          |
| 10            | `brands` | แบรนด์ที่เข้าร่วมแคมเปญ |          |

| 12            | `sponsors` | ผู้สนับสนุนแคมเปญ | ล็อก ตำแหน่งสุดท้ายเสมอ |

* ลำดับเริ่มต้นใช้เฉพาะแคมเปญ **ใหม่** แคมเปญที่บันทึกไว้แล้วใช้ตามที่ API ส่ง

* ถ้า API ส่ง `section_order` ไม่ครบ (เช่น แคมเปญเก่าที่ยังไม่มี `flash_deal`) FE แสดงเท่าที่ได้ และตอนบันทึกก็ส่งกลับเท่าที่มี ไม่เติมให้ (ข้อ 6)

## 6. คำถามที่ต้องตกลงกับ Backend

| \#  | เรื่อง | รายละเอียด |
|-----|--------|------------|
| 1   | ชื่อและการตรวจ `promote_videos[].cover_image_path` | FE ส่งชื่อนี้อยู่แล้ว ถ้า API ตรวจ key เข้มงวดจะเซฟไม่ได้ ต้องยืนยันชื่อ field และให้รับค่า (storage key หรือลิงก์ ytimg) |
| 2   | `PATCH` ที่ส่งชุดเต็ม | FE ส่ง array ทั้งชุด (`participants`, `lucky_winners`, `promote_videos`, `ghost_articles`, sponsors) ทุกครั้ง Backend ต้องถือเป็น **แทนที่ทั้งชุด** (รายการที่หายไป = ลบ) ใช่หรือไม่ และตัวระบุรายการคือ `promote_videos[].id`, `lucky_winners[].winner_id` ใช่หรือไม่ |
| 3   | บันทึกร่าง vs เผยแพร่ | บันทึกร่างไม่ส่ง `visibility` field ไหนบังคับเฉพาะตอน `online` และ Backend ตรวจซ้ำตามตาราง "กติกาตรวจฝั่ง FE" หรือไม่ |
| 4   | `card_frames` | บันทึกเป็น string อ่านกลับเป็น `{ th, en, zh, i18n }` ขอให้ตรงกัน |
| 5   | ภาษาจีน `cn` กับ `zh` | `localized string` ใช้ `cn` แต่ `card_frames` อ่านกลับใช้ `zh` ต้องเลือกแบบเดียว |
| 6   | `pagination` ของรายการ | camelCase หรือ snake_case และ `listing-picker` คืน array ตรง ๆ หรือ `{ items, pagination }` |
| 7   | `status` ของรายการ | FE ยังเทียบ `end_at` กับเวลาเครื่องเองเพื่อตัดสิน "สิ้นสุด" ถ้า `status` จาก API เชื่อถือได้ FE จะเลิกคำนวณ |
| 8   | `check-slug` | ใช้ `available` ตัวเดียว (ตอนนี้ FE รองรับ 5 ชื่อ) |
| 9   | `blocked-dates` | ยืนยันรูปแบบเวลาใน `blocked_ranges` และ Backend ตรวจวันทับตอนบันทึกซ้ำอีกชั้น |
| 10  | `create` คืน id | ขอให้คืน `data.campaign_id` ชื่อเดียวกับรายการและ `raw` (ตอนนี้ FE อ่าน `campaign_id` หรือ `id`) |
| 11  | `entity_sub_id` ของ `hb_branch` | FE ส่ง id จังหวัดของ BO ยืนยันความหมาย |
| 12  | `lucky_winners[].updated_at` | FE ส่งกลับตามที่อ่านมา ขอให้ Backend ตั้งเอง |
| 13  | `section_order` ของแคมเปญเก่า | แคมเปญที่บันทึกก่อนมี `flash_deal` ไม่มี slug นี้ ต้องการให้ Backend เติมตอนอ่าน หรือให้ FE เติม |
| 14  | `coming_soon` | อ่านจาก `participants[].listing.coming_soon` และแต่ละ item ของ `listing-picker` ตรวจบน dev เมื่อ 10 พ.ย. ยังไม่มีเส้นไหนส่ง field นี้ ป้ายจึงยังไม่ขึ้น |
| 15  | หมวดเช่า / หอพัก | เปิดให้เลือกใน step 1 แล้ว (6 พ.ย.) ยังไม่ได้ยืนยัน `listing-picker` ของ `secondhand_rent` และว่า create / update รับ `rent` ใน `participants` กับ `card_frames.rent` ได้ครบ |
| 16  | ร่างหัวข้อ 4.1–4.4, 4.6 | `color_config`, `main_sponsor_promotions`, `flash_deal`, รูปดัก Lead, `campaign_registration` ต้องตกลงชื่อ field รูปแบบ และให้เว็บสาธารณะอ่านค่า |
| 17  | Flash Deal | รับ listing ใดก็ได้หรือเฉพาะที่ร่วมแคมเปญ (step 3) และ `is_top` มีได้มากกว่าหนึ่งหรือไม่ |
