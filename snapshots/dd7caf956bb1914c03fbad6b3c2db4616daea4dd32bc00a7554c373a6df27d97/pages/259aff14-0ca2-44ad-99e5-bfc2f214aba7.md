**Functional Requirements** 

**EP-Z ใบประกาศรออนุมัติ ที่ถูกไม่ผ่านอนุมัติที่ console เมื่อแก้ไขแล้วใบประกาศนั้นหากกดเผยแพร่จะไม่ออนไลน์ทันที ต้องกลับเข้ามารอในใบประกาศรออนุมัติอีกครั้ง**

**EP-A  ผู้ที่มีสิทธิ์เข้าถึงระบบ console ของโครงการมือ 1 ได้แก่ บัญชีแม่ และ บัญชีแอดมิน โครงการ**

**EP-B การจัดการใบประกาศ ถ้าเป็น super admin สามารถสร้างใบประกาศได้ทุกจังหวัด ถ้าเป็น admin สามารถสร้างใบประกาศเฉพาะที่จังหวัดตนเองดูแลเท่านั้น** 

**ในการลงใบประกาศจะต้อง log จังหวัดในการเลือกตาม role สิทธิ์ของแอดมิน**

**EP-00 ใบประกาศที่ถูก auto approve จะขึ้นสถานะ ออนไลน์ โดยทันที ใน console ของเจ้าของโครงการ** 

● มีการดักใบประกาศที่ราคา >=100,000,000 บาท ถ้าลงเกินใบประกาศนั้นจะเป็นใบประกาศรออนุมัติ

**EP-01 ระบบจัดการใบประกาศโครงการมือ 1 จะถูกแยกออกจากระบบ nayoo ต้องเข้าสู่ระบบจากทางฝั่ง น่าอยู่ก่อน แล้วค่อยเลือกใช้ระบบ ระหว่างจะใช้ระบบ console หรือ ใช้งานทางฝั่งเว็บน่าอยู่ ทุกครั้งที่เข้าใช้งานหลังจากเข้าใช้งานครั้งแรก**

**Column โปรโมชั่น**

⁠  ■ กรณีมี โปรโมชั่น  2โปรโมชั่น

ดู UI ใบประกาศลำดับที่ 1 โปรโมชั่น แสดงผลถ้ามีโปรโมชั่น มีคำสื่อสาร มีโปรโมชั่น

พร้อมบอกวันหมดอายุ (วันสิ้นสุดโปรโมชั่น) หากหมดอายุจะแสดง UI เหมือนลำดับที่ 3

โปรปัจจุบันหมดอายุ แสดงเมื่อลงโปรโมชั่น เมื่อลงโปรโมชั่น ตัวเลขวันที่จะสื่อสารเป็นตัวเลขสีเขียว 

โปรปัจจุบันหมดอายุ ตัวเลขจะเป็นสีแดงเมื่อโปรโมชั่นใกล้หมดอายุ นับถอยหลัง 7 วันสุดท้าย หากโปรโมชั่นใกล้หมดอายุ

โปรล่วงหน้าเริ่ม  แสดงเมื่อลงโปรโมชั่นล่วงหน้า เมื่อลงโปรโมชั่นล่วงหน้า ตัวเลขวันที่จะสื่อสารเป็นตัวเลขดำ จะเป็นตัวเลขสีเขียวเมื่อโปรโมชั่นก่อนหน้านั้นหมดอายุ

⁠  ■ กรณีไม่มี โปรโมชั่น

ดู UI ใบประกาศลำดับที่ 2 กดปุ่มเพิ่มโปรโมชั่น (เมื่อ hover เมาส์ จะแสดงคำ เพิ่มโปรโมชั่น ) จะนำพา user ไปหน้าลงโปรโมชั่นของโครงการนั้น

⁠   ● แสดง คำสื่อสาร ไม่มีโปรโมชั่นสีแดง

⁠   ● หมดอายุในวันที่ จะไม่แสดง เนื่องจากไม่มีวันที่

● กรณีมีโปรชั่น 1 โปรโมชั่น

  ดู UI ใบประกาศลำดับที่ 3 จะมีปุ่มเพิ่มโปรโมชั่นล่วงหน้า เมื่อกดจะ ไปหน้าเพิ่มโปรโมชั่น ใน section เพิ่มโปรโมชั่นล่วงหน้า

**หน้าลงโปรโมชั่นใช้ logic เดียวกับหน้าลงใปบระกาศโครงการมือ 1** 

**การกรอกข้อมูลโปรโมชั่น** 

● โปรโมชั่น วันที่เริ่มต้นและสิ้นสุด หากไม่ใส่วันที่เริ่มต้นและสิ้นสุด จะ disable ช่องกรอกทุกช่องกรอกไว้  เมื่อใส่วันที่เริ่มต้นและสิ้นสุดแล้ว ช่องกรอกด้านล่างจะไม่ disable สามาารถใส่ข้อความได้  ถ้าใส่ข้อมูลแล้ว ต้องใส่ข้อมูลหัวข้อถึงจะกดถัดไปได้

● การยกเลิกวันที่เริ่มต้นและสิ้นสุด ต้องกดลบ โดยใช้ backspace ในการลบวันที่เริ่มต้นและสิ้นสุด ถ้าลบแล้วข้อมูลในส่วนที่กรอกไปยังคงอยู่ แต่จะไม่ถูกนับคะแนน

 ![](/api/attachments.redirect?id=3be66003-1f2f-4731-85fc-b37aa27dc52f)

● หากกรอกข้อมูลโปรโมชั่น 1 โปรโมชั่นได้ โปรโมชั่น 10 คะแนน (ยึดคะแนนโปรโมชั่นแรกเป็นหลัก ไม่เอาโปรโมชั่นล่วงหน้ามาคิดคะแนน)

⁠ ○ ลงรูปโปรโมชั่น >= 1 รูปได้ 5 คะแนน

⁠ ○ ลงข้อความมากกว่า 300 ตัวอักษรได้ 5 คะแนน

● การกรอกโปรโมชั่นเพิ่มได้สูงสุดแค่ 1 โปรโมชั่น รวมกับโปรที่กรอกเป็น 2 โปรโมชั่น

● หากมีการเลือกโปรโมชั่น เมื่อเพิ่มโปรโมชั่นแล้ว จะไม่สามารถเลือกวันที่เริ่มต้นและวันที่สิ้นสุด ไม่ซ้ำกันกับโปรโมชั่นก่อนหน้า

● มีการแสดงพรีวิวโปรโมชั่นแบบเหมือนของบริษัทรับสร้างบ้าน

⁠ ○ ใส่รูปแสดงพรีวิวเลย

⁠ ○ ใส่ข้อความแสดงพรีวิวเลย  ห้ามต่ำกว่า 20 ตัวอักษร

**__กรณี ใบประกาศธรรมดา__** 

ลำดับการแสดงผล จะมี logic นับตามการแสดงผลที่การ์ดใบนั้นอยู่จริง แบบ real time (เฉลี่ยรอบรายวัน)

**__กรณี ใบประกาศ top ads__** 

จะขึ้นการแสดงผลลำดับที่ top ads ไม่ถูกนับในลำดับการแสดงผลของใบประกาศนั้น แบบ real time  

ลำดับที่ไม่เป็น Top ads แสดงตัวเลขตามหลังในหน้าใบประกาศนั้น เช่น ลำดับที่  16 

ลำดับที่ไม่เป็น top ads รันเลขลำดับต่อจาก top ads

(จะแสดงปุ่มดันใบประกาศ  เมื่อกดปุ่มดันใบประกาศ จะแสดง modal ดังต่อไปนี้)

**EP-06 สถานะใบประกาศรออนมุติ function การทำงาน** 

**ใบประกาศที่ไม่ผ่านการอนุมัติจาก AE**

 ![](https://wiki.infonayoo.co/api/attachments.redirect?id=613148de-ed83-4f41-b793-f8b561a002b5)

● สถานะใบประกาศ รออนุมัติ เกิดจากการที่ admin backoffice ในจังหวัดที่ user ลงใบประกาศนั้น ตรวจสอบใบประกาศย้อนหลังที่ผ่านการ auto approve แล้วเจอความผิดปรกติของใบประกาศ admin  backoffice น่าอยู่ แล้วทำการให้ใบประกาศที่ออนไลน์ไปแล้วกลับมาอยู่ในสถานะรออนุมัติ  หรือกรณีที่ไม่ผ่านเงื่อนไข logic auto apporve

● หลังจากที่ User มาแก้ไขใบประกาศ ใบประกาศนั้นจะไม่ถูกออนไลน์ในทันที จะต้องส่ง notification ไปที่ backoffice ของจังหวัดนั้น admin backoffice จะต้องเข้ามาตรวจใบประกาศที่รออนุมัติอีกรอบ 1 

● ใบประกาศที่รออนุมัติ จะไม่ถูกแสดงบนเว็บไซต์น่าอยู่  User สามารถกดดูเหตุผลของการรออนุมัติใบประกาศนั้นได้ เมื่อกดที่ สาเหตุ(ไอคอนรูปตา) จะแสดง modal ดังต่อไปนี้

\*\*\*\*\*ใบประกาศที่รออนุมัติ จากการไม่ผ่านการตรวจสอบ  ใบประกาศนั้นจะไม่ถูกออนไลน์ในทันที จะต้องส่ง notification ไปที่ backoffice ของจังหวัดนั้น admin backoffice จะต้องเข้ามาตรวจใบประกาศที่รออนุมัติอีกรอบ 1 

● ใบประกาศที่รออนุมัติ ไม่ผ่านเงื่อนไขตาม logic role ของ user และใบที่เกิน logic ราคา

ใน ตัวเลือกมีแค่ 10,20  การเลือกการแสดงมีผลต่อจำนวนการแสดงแบบบ้านในใบประกาศนั้น

ถ้าเลือก 20 การแสดงผลจะแสดงแบบบ้าน 20 แบบบ้านในหน้าที่ 1  ส่งผลต่อการแสดงผลปุ่มตัวเลข หน้าที่มีอยู่ลดลงเนื่องจาก แสดงผลต่อหน้ามากขึ้น  

**การกดปุ่มเปลี่ยนหน้า จะเป็นดังต่อไปนี้** 

● กดต่อไป เท่ากับไปทีละหน้า

● กดก่อนหน้า เท่ากับ กลับไปทีละหน้า

● กดเลข 2 ตัวเลขเพจจิเนทจะเปลี่ยนเป็น 2 3 4 เป็นต้น

● ถ้ามีแค่ 3 หน้า เลข 4 จะไม่ปรากฎ 

Disabled ถ้าอยู่ที่ หน้า 1  ปุ่ม "ก่อนหน้า" ต้องถูก Disable (กดไม่ได้/เป็นสีเทา)

ถ้าอยู่ที่ หน้าสุดท้าย ปุ่ม "ต่อไป" ต้องถูก Disable
