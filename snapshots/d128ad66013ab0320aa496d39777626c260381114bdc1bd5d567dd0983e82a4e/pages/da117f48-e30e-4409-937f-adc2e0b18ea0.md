**คำตัดสินเพิ่มเติมของผู้ใช้:** เปลี่ยนภาษาแล้ว Shuffle ใหม่แบบ Top Banner แต่ยังตรวจเวลาและ Session เดิม การเปลี่ยนภาษาจึงไม่ทำให้ได้สิทธิ์เปิด Pop-up ที่เคยเปิดไปแล้วใหม่

## EP-01 ขอบเขตและเงื่อนไขการแสดงผล

**หลักการทำงาน:** ดึง Pop-up ของจังหวัดปัจจุบัน รวมหมวดน่าอยู่ → ตรวจสถานะ ระยะเวลา สิทธิ์ และไทยบังคับ → Shuffle Slot ต้นทางทั้งหมดโดยไม่ตัดจำนวน → เลือกภาษาหลักหรือไทยสำรองและเลือก A/B หนึ่งภาพต่อ Slot → เก็บเป็นคิว → เมื่อหน้า เวลา ความถี่ และ Session อนุญาต จึงเปิดรายการถัดไปที่ยังมีสิทธิ์ครั้งละหนึ่ง Pop-up

| รหัส | หัวข้อ | เงื่อนไข / การกระทำ | Logic การแสดงผล / การทำงาน |
|------|--------|---------------------|----------------------------|
| PPP-01 | จังหวัด | ผู้ใช้อยู่จังหวัดขอนแก่น | ดึงเฉพาะ Pop-up ที่มีสิทธิ์ของขอนแก่น ไม่ดึงจังหวัดอื่นมาเติม |
| PPP-02 | หมวด   | โครงการใหม่ รับสร้างบ้าน น่าอยู่ หรือหมวดอื่นผ่านเงื่อนไข | รวมใน Candidate จังหวัดเดียวกัน หมวดน่าอยู่ไม่ถูกตัดด้วยกฎ Center |
| PPP-03 | เงื่อนไขต้นทาง | สถานะ ช่วงเวลา สิทธิ์ของรายการและภาพ A/B | ตรวจเงื่อนไขเดิมก่อนเลือก และตรวจอีกครั้งก่อนเปิดจริง |
| PPP-04 | ไม่จำกัด Slot | มี Candidate S รายการ | ใช้ทั้งหมด M=S ไม่ตัดเหลือ 8, 3 หรือ K รายการ และไม่กำหนดจำนวนตายตัวใหม่ |
| PPP-05 | หน่วยนับ | รายการเดียวมีหลายภาษาและ A/B | นับ Source Slot เดียว เข้า Shuffle หนึ่งครั้ง ไม่แตกเป็นหลายรายการ |
| PPP-06 | การเปิดจริง | มีคิวแล้ว แต่กฎเปิดยังไม่อนุญาต | ยังไม่เปิด ไม่ถือว่าผู้ใช้เห็น และไม่บันทึก Impression เพียงเพราะอยู่ในคิว |
| PPP-07 | จำนวนหน้าต่าง | กฎอนุญาตเปิดรายการถัดไป | เปิดครั้งละหนึ่ง Pop-up ไม่เปิดหลายรายการซ้อนหรือพร้อมกัน |
| PPP-08 | ขอบเขต Product | มี Pop-up โฆษณาและ Pop-up โปร Walk-in/แคมเปญ | Solution นี้เป็น Product โฆษณา โปร Walk-in/โปรจองยังใช้ flow ของตน ไม่ถูกนำมาต่อท้ายคิวนี้อัตโนมัติ |

**ไม่จำกัด Slot หมายถึงคิวมีได้ตามจำนวนรายการที่ผ่านเงื่อนไขจริง** ผู้ใช้อาจเห็นไม่ครบทั้งหมด เพราะยังต้องผ่านหน้า เวลา และสิทธิ์การเปิด ไม่ใช่สัญญาว่าจะเปิดทุกตัวในการเข้าหน้าครั้งเดียว

## EP-03 การเลือกภาษาและไทยสำรอง

**ภาษาที่ผู้ใช้เลือก → หากไม่มีภาพใช้ได้ ให้ใช้ไทยของ Source เดิม** ไม่ใช้จีนแทนอังกฤษหรืออังกฤษแทนจีน และไม่ผสมภาษาเพื่อทำให้มี A/B ครบ

| รหัส | เงื่อนไข | Logic การทำงาน |
|------|----------|----------------|
| PPP-L01 | ผู้ใช้เลือกไทย | ใช้ภาพไทยของ Source เดิม |
| PPP-L02 | เลือกจีน/อังกฤษและมีภาพภาษานั้นอย่างน้อยหนึ่งฝั่ง | ใช้ภาษานั้นก่อน ไม่ใช้ไทยเพียงเพราะไทยมีภาพมากกว่า |
| PPP-L03 | ไม่มีภาพภาษาที่เลือกใช้ได้ แต่มีไทย | ใช้ไทยสำรอง ไม่ลดจำนวน Slot เพราะไม่มีจีน/อังกฤษ |
| PPP-L04 | ภาษาหลักมีเพียง A | ใช้ A 100% ไม่ดึงไทย B หรือภาพภาษาอื่นมารวม |
| PPP-L05 | ภาษาหลักมีเพียง B | ใช้ B 100% ไม่สร้าง A เพิ่ม |
| PPP-L06 | ไม่มีไทยที่ใช้ได้ | ข้อมูลไม่ผ่าน requirement ของ Candidate ไม่ถือเป็นกรณีปกติสำหรับรายการที่พร้อมใช้งาน |
| PPP-L07 | เปิดบน Mobile แทน Desktop | ใช้ชุดภาพภาษาเดียวกัน ไม่มีการเลือกไฟล์อีกอุปกรณ์หรือ fallback เพราะไม่มีไฟล์ Mobile |
| PPP-L08 | เว็บอังกฤษ/จีนใช้ไทยสำรอง | เว็บไซต์คงภาษาที่เลือก ภาพไม่ถูกแปลอัตโนมัติ |
| PPP-L09 | ไทยสำรองมี A/B | เลือกด้วยน้ำหนักไทย และนับ input ตามภาพไทย ไม่ใช้ weight ของภาษาเว็บไซต์ |
| PPP-L10 | แสดงหรือคลิกภาพไทยสำรอง | เหตุการณ์หนึ่งเข้า input ไทยครั้งเดียว ไม่ลงซ้ำเป็น input อังกฤษ/จีน |

## EP-04 Shuffle คิวและเลือกภาพ A/B

| รหัส | หัวข้อ | เงื่อนไข / การกระทำ | ผลการทำงาน |
|------|--------|---------------------|------------|
| PPP-S01 | หน่วย Shuffle | จัดคิวใหม่          | Source แต่ละรายการมีหนึ่งตำแหน่งในคิว ไม่ใช้จำนวนไฟล์เป็นน้ำหนัก |
| PPP-S02 | จำนวน  | มี Candidate S รายการ | Shuffle ทั้ง S แล้วเก็บครบ S รายการ ไม่สุ่มทิ้งบางรายการด้วยเพดานของ Product อื่น |
| PPP-S03 | หมวด/ภาษา | บางรายการเป็นน่าอยู่หรือไทยสำรอง | ร่วม Shuffle ตามปกติ ไม่ถูกจัดท้ายเพราะหมวดหรือภาษาสำรอง |
| PPP-S04 | ไม่ใช้ Ranking เดิม | จัดลำดับ Source     | ไม่ใช้ Phase Rotate หรือ Impression-based ranking และไม่เอา CTR มาเรียง Source |
| PPP-S05 | A/B ใน Source | ภาษาที่เลือกมี A/B ครบ | สุ่มหนึ่งภาพด้วยน้ำหนักล่าสุดของ Source+ภาษาภาพจริงตาม EP-10 |
| PPP-S06 | ภาพเดียว | มี A หรือ B ใช้ได้เพียงฝั่งเดียว | ใช้ฝั่งนั้น 100% ไม่สุ่มไปฝั่งที่ใช้ไม่ได้ |
| PPP-S07 | เลือกภาพแล้ว | เตรียม Pop-up ของ Source | เก็บภาพหนึ่งภาพไว้ในคิวนั้น อีกภาพไม่เป็น Pop-up เพิ่ม |
| PPP-S08 | ระหว่างเปิด | ผู้ใช้ยังไม่ปิดและไม่ได้เปลี่ยนภาษา | คงภาพเดิม ไม่มี Auto Slide ไม่สลับ A/B หรือวน Loop หากผู้ใช้เปลี่ยนภาษาให้ใช้ข้อยกเว้นใน EP-06 |
| PPP-S09 | คิวว่าง/ไม่มีรายการที่ยังมีสิทธิ์ | ถึงจังหวะตรวจเปิด   | ไม่เปิด ไม่ทำรายการเดิมซ้ำ ไม่วนล้างประวัติเพียงเพื่อให้มีภาพ |
| PPP-S10 | รายการในคิวหมดสิทธิ์ภายหลัง | กำลังจะเปิด         | ตรวจใหม่และไม่เปิดรายการที่ไม่ผ่าน ใช้รายการถัดไปที่ยังมีสิทธิ์ตามกฎเดิม |

**โอกาส A/B เป็นการสุ่มต่อ Source ไม่ใช่โควตา:** 70:30 ไม่รับประกันว่าทุก 10 ครั้งต้องได้ A 7 ครั้ง/B 3 ครั้ง และไม่ได้แบ่งคิวเป็น Slot กลุ่ม A กับกลุ่ม B

### 5.2 Gate ของหน้า Walk-in / แคมเปญ / พรีเมี่ยม

คง [EP-change จังหวัด](https://wiki.infonayoo.co/doc/ep-change-ab2LaeyD3b) และ [Pop-up พรีเมี่ยม](https://wiki.infonayoo.co/doc/pop-up-vEZRjm9Dqo) เฉพาะหน้าที่ตารางต้นทางกำหนด ไม่ขยายเป็นการห้ามโฆษณาทุกหน้าทั้งเว็บ

| เงื่อนไขในหน้าที่ต้นทางระบุ | Pop-up โฆษณา | Flow ที่คงแยกต่างหาก |
|-----------------------------|--------------|----------------------|
| เข้าร่วม Walk-in            | ไม่เปิดโฆษณาในหน้าโครงการปกติ/เฟดใหม่/เปิดใหม่ หน้าแบบบ้าน และโปรไฟล์บริษัทรับสร้างบ้านตามตาราง | โปร Walk-in ใช้กฎของตน |
| เข้าร่วมแคมเปญ              | ไม่เปิดโฆษณาในหน้าโครงการ แบบบ้าน มือสอง/เช่า และโปรไฟล์บริษัทรับสร้างบ้านตาม EP-change | โปรจองในช่วงแคมเปญตามกฎเดิม |
| เข้าร่วม Walk-in และแคมเปญ  | ไม่เปิดโฆษณาในหน้าที่กำหนด | คงลำดับเงื่อนไขโปรตามต้นทาง ไม่รวมเป็นหลายโฆษณาซ้อน |
| พรีเมี่ยมที่เข้าร่วมแคมเปญหรือ Walk-in | ไม่เปิดโฆษณาตามตารางพรีเมี่ยม | คงโปรที่มีสิทธิ์ ไม่เพิ่มกฎห้ามโฆษณาทุกหน้าจากคำว่าพรีเมี่ยมอย่างเดียว |
| ไม่มีเงื่อนไขห้ามและยังมีสิทธิ์เปิด | พิจารณาคิว Pop-up จังหวัดตามปกติ | ยังต้องผ่านเวลา/Session |

ตัวเลข **4 วินาทีในต้นทางเป็นของ Pop-up โปร Walk-in** ไม่ใช่เวลาสลับ Pop-up โฆษณา ไม่ใช้แทนเวลารอของจังหวัด และหน้าตัวอย่าง Center ที่เป็นข้อยกเว้นไม่ใช่กฎขยายให้จังหวัด

หนึ่ง Source มีน้ำหนักไทย จีน และอังกฤษอย่างละชุด ภายในภาษาเดียวรวมเหตุการณ์ที่เกิดจาก Desktop/Mobile เพราะใช้ไฟล์กราฟฟิกเดียวกัน แต่ **ไม่มี inputแยกคู่ภาษา–อุปกรณ์สำหรับการรีเซ็ต** หากเก็บอุปกรณ์เพื่อวิเคราะห์รายงานก็ไม่เปลี่ยนขอบเขตการเริ่มคำนวณใหม่

| รหัส | หัวข้อ | เงื่อนไข / การกระทำ | ผลการทำงาน |
|------|--------|---------------------|------------|
| PPP-CTR01 | หน่วยคำนวณ | คำนวณหนึ่งSource    | แยกTH/ZH/EN และA/B ไม่รวมข้ามSource จังหวัด หรือProduct |
| PPP-CTR02 | ยอดใช้คำนวณ | ภาษาภาพจริง L       | รวมClickและIMPของ L จากการใช้งานทุกอุปกรณ์หลังresetของ L ไม่เฉลี่ยCTRของDesktopกับMobile |
| PPP-CTR03 | ภาพสำรอง | ไทยแสดงบนเว็บอังกฤษ/จีน | ใช้น้ำหนักไทยและinputไทย เหตุการณ์เดียวไม่ลงซ้ำให้ภาษาหน้าเว็บ |

| PPP-CTR10 | Performance | เริ่มรอบinputA/Bใหม่ | เก็บPerformance/รุ่นภาพเดิม ไม่ลบประวัติจริง |

| PPP-CTR12 | น้ำหนักใหม่ | รอบรายวันคำนวณเสร็จ | ใช้เลือกภาพเมื่อจัดชุดใหม่ ไม่เปลี่ยนภาพA/BของPop-upที่เปิดอยู่เองเพียงเพราะน้ำหนักใหม่ กรณีผู้ใช้เปลี่ยนภาษาใช้ EP-06 |

กำหนด L เป็นTH, ZH หรือEN และใช้ยอดของ Source เดียวกัน

```text
CTR_A[L] = CLICK_A[L] / IMP_A[L] × 100
CTR_B[L] = CLICK_B[L] / IMP_B[L] × 100

RAW_A[L] = CTR_A[L] / (CTR_A[L] + CTR_B[L]) × 100
P_A[L] = MAX(30, MIN(70, RAW_A[L]))
P_B[L] = 100 - P_A[L]
```

ใช้สูตรเมื่อ IMP_A และIMP_Bมากกว่า0 และCTR_A+CTR_Bมากกว่า0 มิฉะนั้นใช้50:50 คำนวณจากค่าจริงก่อนย่อทศนิยมเพื่อแสดงผล

**จำลองสูตรจำกัดช่วงให้เห็นทีละขั้น**

| น้ำหนักดิบ A | MIN(70, น้ำหนักดิบ A) | MAX(30, ผลขั้นก่อน) | น้ำหนัก A:B |
|--------------|-----------------------|---------------------|-------------|
| 90%          | 70                    | 70                  | 70:30       |
| 10%          | 10                    | 30                  | 30:70       |
| 60%          | 60                    | 60                  | 60:40       |

| CTR A | CTR B | ดิบ A:B | น้ำหนักใช้จริง |
|-------|-------|---------|----------------|
| 3%    | 2%    | 60:40   | 60:40          |
| 9%    | 1%    | 90:10   | 70:30          |
| 1%    | 9%    | 10:90   | 30:70          |
| 2%    | 2%    | 50:50   | 50:50          |
| 0% แต่มีIMP | 2%    | 0:100   | 30:70          |
| 2%    | 0% แต่มีIMP | 100:0   | 70:30          |
| 0%    | 0%    | หารศูนย์ไม่ได้ | 50:50          |
| ฝั่งใดIMPเป็น0 | —     | ข้อมูลยังไม่ครบ | 50:50          |

70:30 เป็นขอบเขต ไม่ใช่Aชนะเสมอ และไม่ทำให้ภาพที่CTRสูงแสดง100% หากมีA/Bใช้ได้ทั้งคู่ รอบนี้ไม่เพิ่มเกณฑ์จำนวนIMPขั้นต่ำหรือการทดสอบนัยสำคัญทางสถิติที่ต้นทางยังไม่กำหนด

## EP-11 จำลองการคำนวณสามภาษา

ใช้ข้อมูลสมมติ **Source SX** แยกจาก SourceS1–S7ของตัวอย่างคิว ยอดในตารางรวมการใช้งานทั้งสองอุปกรณ์ภายในภาษาเดียวอยู่แล้ว

| ภาษา | A Click/IMP | CTR A | B Click/IMP | CTR B | ดิบ A:B | น้ำหนักล่าสุด |
|------|-------------|-------|-------------|-------|---------|---------------|
| ไทย  | 400/10,000  | 4%    | 200/10,000  | 2%    | 66\.6667:33.3333 | 66\.67:33.33  |
| จีน  | 10/1,000    | 1%    | 50/1,000    | 5%    | 16\.6667:83.3333 | 30:70         |
| อังกฤษ | 30/1,000    | 3%    | 30/1,000    | 3%    | 50:50   | 50:50         |

| เหตุการณ์ | ภาพและน้ำหนักที่ใช้ |
|-----------|---------------------|
| เว็บไทยและมีไทยA/B | เลือกหนึ่งภาพด้วยไทย66.67:33.33 |
| เว็บจีนและมีจีนA/B | เลือกหนึ่งภาพด้วยจีน30:70 |
| เว็บอังกฤษและมีอังกฤษA/B | เลือกหนึ่งภาพด้วยอังกฤษ50:50 |
| เว็บอังกฤษแต่Sourceนั้นไม่มีอังกฤษ | ไทยสำรอง ใช้ไทย66.67:33.33 นับinputไทย |
| จีนมีAภาพเดียว | ใช้จีนA100% ไม่เปลี่ยนไปไทยเพื่อหาB |
| เปิดไฟล์เดียวบนMobileหรือDesktop | ใช้weightภาษาเดียวกัน ไม่แยกภาพหรือweightอุปกรณ์ |

รายงานรวมเพื่อดูภาพรวมทำได้ แต่ไม่ใช้น้ำหนักรวมสามภาษามาแทนการเลือกของแต่ละภาษา และCTRที่ต่างกันระหว่างภาษาไม่ได้แปลว่าต้องบังคับผู้ใช้เปลี่ยนไปดูภาษาที่CTRสูงสุด

## EP-12 จำลองเปลี่ยนภาพและรีเซ็ต

ใช้SourceSXจากEP-11 สมมติเปลี่ยน **ภาพจีน A** ซึ่งเป็นไฟล์ร่วมDesktop/Mobile

| รายการ | ก่อนแก้ | หลังแก้สำเร็จ |
|--------|---------|---------------|
| inputจีนA | 10Click/1,000IMP | เริ่มใหม่0/0  |
| inputจีนB | 50Click/1,000IMP | เริ่มใหม่0/0ด้วย แม้ไม่ได้แก้B |
| inputไทย/อังกฤษ | ตามEP-11 | คงเดิม        |
| น้ำหนักจีน | 30:70   | 50:50ทันทีจนรอบรายวันถัดไป |
| น้ำหนักไทย/อังกฤษ | 66\.67:33.33 และ50:50 | คงเดิม        |
| Performanceก่อนแก้ | จีนA10/1,000 B50/1,000 | เก็บประวัติครบ ไม่ล้างเป็น0 |
| ภาพที่เปิดอยู่ | ภาพที่เลือกไว้ | ไม่สลับA/Bอัตโนมัติจากการคำนวณหรือreset |

**Pop-up ไม่มีคู่จีนDesktopที่เก็บinputเก่าไว้** เพราะไม่ได้แยกไฟล์อุปกรณ์ จึงไม่ใช้ตัวอย่าง17/700และ27/700จากTop Bannerมาคำนวณในกรณีนี้

| เวลา / เหตุการณ์ | ผลที่ใช้กับการจัดภาพใหม่ |
|------------------|--------------------------|
| แก้จีนAสำเร็จ    | จีน50:50 ไทยและอังกฤษคงเดิม |
| ยังไม่ถึงรอบคำนวณถัดไป | จีนยัง50:50 แม้เริ่มมีข้อมูล |
| ถึงรอบหลัง00:00แต่จีนไม่มีข้อมูลใหม่ที่คำนวณได้ | จีนยัง50:50 ไม่ยืมประวัติก่อนresetหรือภาษาอื่น |
| ถึงรอบหลัง00:00และจีนมีข้อมูลใหม่ตามตารางล่าง | คำนวณจากinputใหม่ทั้งภาษา |
| แก้จีนอีกครั้งก่อนรอบถัดไป | เริ่มinputจีนA/Bใหม่และกลับ50:50อีกครั้ง |
| แก้ไทยและจีนพร้อมกัน | resetไทยA/BและจีนA/B น้ำหนักสองภาษานี้50:50 อังกฤษคงเดิม |

### ตัวอย่างข้อมูลใหม่หลังรีเซ็ต

| ภาษา / ทางเลือก | Click | IMP | CTR |
|-----------------|-------|-----|-----|
| จีน A           | 12    | 200 | 6%  |
| จีน B           | 2     | 200 | 1%  |

น้ำหนักดิบA = 6÷(6+1)×100 = 85.714286% → จำกัดช่วงได้ **จีน70:30** เมื่อถึงรอบรายวันถัดไป

หากนำPerformanceเก่ามารวมผิด จะได้A22/1,200 และB52/1,200 แล้วได้weightประมาณ29.73:70.27ก่อนจำกัดช่วง เป็น30:70 ซึ่งผิดจากinputใหม่ที่ต้องได้70:30 จึงต้องแยกสองชุดข้อมูลให้ชัด

## EP-14 ภาพจำลองและแนวทางส่งต่อ

### 14.1 คิว Pop-up จังหวัดและการเปิดทีละหนึ่ง

 ![ภาพจำลอง Pop-up จังหวัด: คิวไม่จำกัดและเปิดทีละหนึ่ง](https://wiki.infonayoo.co/api/attachments.redirect?id=c0159362-45b0-44dc-be60-a20118259fbe)

ภาพอ้างอิงข้อมูลสมมติEP-07 แสดงคิวทั้งหมด ภาพร่วมอุปกรณ์ และจังหวะเปิด ไม่ใช่ภาพระบบจริง และไม่ได้รับประกันว่าผู้ใช้จะเห็นครบคิว

### 14.2 สูตร A/B สามภาษาและการแก้ภาพ

 ![ภาพสูตร A/B แยกภาษาและรีเซ็ต Pop-up แบบใช้ภาพร่วมอุปกรณ์](https://wiki.infonayoo.co/api/attachments.redirect?id=7d11975b-6317-4540-b4fa-692007eeb208)

ภาพใช้SourceSXจากEP-11–12 ไม่ใช่weightของS1–S7ในตัวอย่างคิว

### 14.3 ข้อเสนอทางเทคนิคและขอบเขตที่คงเดิม

| เรื่อง | แนวทาง/ข้อจำกัด |

| แยกState | เก็บCandidate/คิว ภาพที่เลือก หน้าต่างที่เปิด และประวัติสิทธิ์เดิมแยกจากinputA/B เพื่อไม่ให้Shuffleล้างประวัติเปิด |
| หน่วยรีเซ็ต | แยกProduct=Pop-up, Source, ภาษา, A/Bและรุ่นภาพ อุปกรณ์เป็นข้อมูลวิเคราะห์ได้แต่ไม่เป็นคู่รีเซ็ตภาพ |
| Eventภาพเก่า | ป้องกันeventของกราฟฟิกก่อนแก้ปนinputรอบใหม่ ส่วนPerformanceเก็บประวัติเดิม |

| Session/TTLเดิม | ไม่พบค่าตัวเลขครบในsourcesที่อ่าน ให้Dev/Testerอ้างการตั้งค่าและเกณฑ์เปิดเดิมก่อนทดสอบ regression หากต้องเปลี่ยนต้องให้ผู้ใช้ตัดสินเพิ่ม |
| ลิงก์  | ไม่เพิ่มpolicyแท็บเดิม/แท็บใหม่เมื่อไม่มีหลักฐาน คงพฤติกรรมPop-upเดิมและลิงก์ภาพจริง |
| ขอบเขต | ข้อเสนอข้างต้นไม่ใช่ชื่อAPI/schemaจริง ไม่เพิ่มProductใหม่ ไม่เพิ่มหน้ารายงานใหม่ |
