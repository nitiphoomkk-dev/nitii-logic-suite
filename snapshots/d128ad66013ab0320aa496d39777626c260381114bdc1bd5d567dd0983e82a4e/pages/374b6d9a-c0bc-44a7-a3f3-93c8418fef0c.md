## 2. กติกากลาง

### Header

ทุกเส้นข้างบน (ยกเว้นระบุไว้) ส่ง

| Header | ค่า |
|--------|-----|
| `apikey` | `NEXT_PUBLIC_API_KEY` |
| `Authorization` | `Bearer <accessToken>` ของผู้ใช้ที่ login |
| `province` | id จังหวัดที่เลือกอยู่ (ตัวเลขตัวเดียว ไม่ใช่ list `province_ids` ของ user) |
| `Content-Type` | `application/json` |

`GET /api/leads` ส่ง header ระบุผู้กระทำเพิ่มตาม spec ของ Leads

### Envelope

```json
{ "success": true, "data": { }, "message": "..." }
```

Error: HTTP ไม่ใช่ 2xx หรือ `success: false` พร้อม

```json
{ "success": false, "error": { "code": "...", "message": "...", "traceId": "...", "chain": ["..."] } }
```

FE แสดง `error.message` (ต่อท้ายด้วย `chain` ถ้ามี) เป็น toast

### ข้อความหลายภาษา (`localized string`)

ฟิลด์ชื่อ / คำอธิบาย / หัวข้อ ใช้รูป `{ "th": "...", "en": "...", "cn": "..." }` (Backend ยืนยันแล้วว่าใช้ key `cn` ไม่ใช่ `zh`) ตอนนี้ **FE ส่งเฉพาะ** `th` และตอนอ่านเลือก `th` → `en` → `cn`

### วันที่ / เวลา

* ส่งเป็น ISO 8601 UTC (`Date.toISOString()`) จากเวลาท้องถิ่นของเบราว์เซอร์ (Asia/Bangkok)
* ตัวเลือกวันในฟอร์มเป็นวันที่ล้วน ได้ `00:00` ตามเวลาไทย เช่น 15 พ.ย. 2569 = `2026-11-14T17:00:00.000Z`
* `web_period.end_at` ส่งเป็น **สิ้นวัน** `23:59:59.999` ตามเวลาไทย เช่น 30 พ.ย. = `2026-11-30T16:59:59.999Z`
* `onsite.start_at` / `end_at` รวม "วัน" กับ "เวลา (HH:mm)" ที่กรอก
* `flash_deal.start_at` / `end_at` ส่งแบบเดียวกับ `web_period` (เริ่ม = วันที่เลือก `00:00`, สิ้นสุด = สิ้นวัน) ฟอร์มยังไม่มีช่องเวลา

### รูปภาพ

ทุก `*_image_path`, `images[]`, `icon_image_path`, `image_path` ของ banner ฯลฯ เป็น **storage key / path** ที่ได้หลังอัปโหลด (ข้อ 3.11) FE ไม่ส่ง base64 หรือไฟล์ใน body ของแคมเปญ ถ้าช่องไหนไม่มีรูป FE ส่ง `""` หรือไม่ส่งตามที่ระบุในตาราง

### ชื่อหมวดที่ใช้ในแต่ละ API

| ฟอร์ม step 1 | event-campaign API | listing-picker `category` | ป้ายในรายการ BO |
|--------------|--------------------|-------------------------|-----------------|
| โครงการใหม่  | `new`              | `new`                   | โครงการใหม่     |
| อสังหาฯ มือสอง | `secondhand`       | `secondhand_sale`       | อสังหาฯ มือสอง  |
| เช่า / หอพัก | `rent`             | `secondhand_rent`       | เช่า / หอพัก    |
| รับสร้างบ้าน | `home_builder`     | `home_builder`          | รับสร้างบ้าน    |

```json

```

Field ที่ FE อ่าน

| Field | ใช้ทำอะไร |
|-------|-----------|
| `campaign_id` | id แถว    |
| `slug` | ชื่อ URL  |
| `name` | ชื่อแคมเปญ (`localized string` หรือ string ก็ได้) |
| `promote_image_path` / `logo_image_path` | รูปในแถว (ใช้ promote ก่อน ไม่มีค่อยใช้ logo) |
| `participant_types[]` | ชิปหมวดที่ร่วม |
| `participant_counts.top` | คอลัมน์ "Top Campaign" |
| `lead_count` | คอลัมน์ผู้สนใจ |
| `visibility` | `draft` / `online` / `offline` |
| `status` | `pre_event` / `active` / `expired` (Backend ยืนยัน **ไม่ใช่** `ended`) ร่าง = `""` Backend คำนวณตามวันไทย และมี `status_label` ภาษาไทยให้ด้วย |
| `web_period.*` | วันที่ Pre / เริ่ม / สิ้นสุด |

สถานะที่แสดงในตาราง (FE คำนวณ)

| เงื่อนไข (ตามลำดับ) | สถานะ |
|---------------------|-------|
| `visibility = draft` | แบบร่าง |
| `visibility = offline` | ออฟไลน์ |
| `status = pre_event` | รอออนไลน์ |
| `status = expired`  | สิ้นสุด |
| `web_period.end_at` ผ่านแล้ว | สิ้นสุด (FE เทียบกับเวลาเครื่องเอง) |
| อื่น ๆ              | ออนไลน์ |

> ⚠️ โค้ดฝั่ง FE (`services/manageCampaign/index.ts`) ยังเทียบกับค่า `ended` ต้องแก้เป็น `expired` ตอนนี้แถวที่หมดอายุยังแสดง "สิ้นสุด" ได้เพราะ FE เทียบ `end_at` กับเวลาเครื่องอีกชั้น

`pagination` FE รับได้ทั้ง camelCase (`currentPage`, `itemsPerPage`, `totalItems`, `totalPages`) และ snake_case ขอให้ Backend เลือกแบบเดียว

### 3.2 `GET /api/event-campaigns/{id}` รายละเอียดแคมเปญ

ใช้ตอนเปิดหน้าแก้ไข ผลลัพธ์ถูกแปลงกลับเป็นฟอร์มทุก step ได้ `data` เป็น field เดียวกับ body ของข้อ 3.3 บวก

| Field เพิ่ม | ความหมาย |
|-------------|----------|
| `campaign_id` | id แคมเปญ (FE อ่านทั้ง `campaign_id` และ `id`) |
| `participants[]` | ใบประกาศที่ร่วม พร้อม snapshot ของใบประกาศ (ดูตารางข้างล่าง) |
| `lucky_winners[]` | ผู้โชคดี (มี `id` / `winner_id`, `created_at`, `updated_at`, `order`) |
| `participant_counts` | `{ new, secondhand, rent, home_builder }` |
| `ghost_articles[].article` | `{ title, feature_image }` ของบทความ ใช้แสดงในรายการ (อ่านอย่างเดียว) |
| `status`, `status_label` | สถานะที่ Backend คำนวณ (ข้อ 3.1) |

แคมเปญที่บันทึกก่อนมี field ของหัวข้อ 4 จะได้ค่าว่างดังนี้ FE ถือว่า "ยังไม่ตั้งค่า" และใช้ค่าเริ่มต้นของฟอร์ม

| Field | ค่าที่ได้ |
|-------|-----------|
| `color_config` | `null`    |
| `lead_registration_images` | ทุก key เป็น `""` |
| `lead_popup_image_path` | `""`      |
| `main_sponsor_promotions` | `[]` (ไม่เคยเป็น `null`) |
| `section_order` | Backend เติม slug ที่ขาดให้ตอนอ่าน |

`participants[]` ที่ FE อ่าน

| Field | หมายเหตุ |

| `joined_at` | วันที่เข้าร่วม |

### 3.3 `POST /api/event-campaigns` สร้าง, `PATCH /api/event-campaigns/{id}` แก้ไข

* `POST` ได้ response `data.campaign_id` (ไม่มี `id`)
* `PATCH` FE ส่ง **body ชุดเต็มทุกครั้ง** (ทุก step รวมกัน ไม่ใช่เฉพาะที่เปลี่ยน)
* **บันทึกร่าง**: ไม่ส่ง `visibility`
* **เผยแพร่**: ส่ง `"visibility": "online"`

**ความหมายของ** `**PATCH**` **(Backend ยืนยัน)**

| ส่งอะไร | ผลที่ Backend ทำ |
|---------|------------------|
| ไม่ส่ง key | ไม่แตะค่าเดิม    |
| object ก้อนใหญ่ (`color_config`, `lead_registration_images`, `flash_deal`) | **เขียนทับทั้งก้อน** ทุก field ที่ไม่ส่งในก้อนนั้นจะถูกลบ |
| array (`participants`, `lucky_winners`, `promote_videos`, `main_sponsor_promotions` ฯลฯ) | **แทนที่ทั้งชุด** แถวที่ไม่ส่ง = ลบ, `[]` = ลบทั้งหมด |

### 3.11 อัปโหลดรูป

FE ขอ presigned URL แล้ว `PUT` ไฟล์ขึ้นที่เก็บไฟล์เอง (`Content-Type` ตามไฟล์) หลังอัปโหลดเสร็จจึงเอา `key` ไปใส่ใน body ของแคมเปญ

| Endpoint | Body | ใช้ |
|----------|------|-----|
| `POST /api/upload/` | `{ key, fileName, contentType, expiresIn }` | ไฟล์เดียว |
| `POST /api/upload/multiple` | `{ key, files: [{ fileName, contentType }], expiresIn }` | หลายไฟล์พร้อมกัน |

* `key` ในที่นี้คือ **prefix โฟลเดอร์** ของแคมเปญคือ `event-campaign` (ถ้าไม่ส่ง ใช้ `posts`)
* `expiresIn` ค่าเริ่มต้น 900 วินาที
* response มี `url` (presigned PUT) และ `key` ของไฟล์ (หลายไฟล์ได้ `urls[]`)
* รูปดัก Lead (หัวข้อ 4.4) เลือกแบบไม่ crop จึงเก็บในฟอร์มเป็น data URL FE แปลงเป็นไฟล์แล้วอัปโหลดตอนบันทึก ส่วนค่าที่โหลดมาจากแคมเปญที่บันทึกไว้ (เป็น key อยู่แล้ว) ส่งกลับตามเดิม

### 3.12 `POST /api/upload/ingest-url`

ให้ Backend ไปดึงรูปปกวิดีโอจาก URL ภายนอกมาเก็บ เพราะลิงก์ภาพปก TikTok หมดอายุราว 47 ชั่วโมง

```json
{ "source_url": "https://p16-sign.tiktokcdn.com/....jpeg", "key_prefix": "video-covers" }
```

```json
{ "success": true, "data": { "key": "video-covers/abc123.jpg" } }
```

* FE ตั้ง timeout 12 วินาที
* `504` หรือ timeout = ปัญหาชั่วคราว FE ไม่ลอง URL อื่นต่อ
* `400`, `413`, `415`, `502` = ปัญหาของรูปนั้น FE ลองรูปอื่นต่อได้ (เช่น YouTube Shorts ลอง `oar2.jpg` แล้ว `maxresdefault.jpg`)
* ถ้า ingest ไม่ได้เลย FE ใช้ URL ดิบแสดงในฟอร์มต่อ แต่ **ไม่ส่ง URL ดิบของ TikTok ไปเก็บ** (หมดอายุ ดูหัวข้อ 4.5)
* `GET /api/video-meta?url=` เป็น route ใน FE เอง (ไม่ใช่ Backend) ใช้ดึงชื่อและ thumbnail ของ TikTok / YouTube

### 3.13 `GET /api/leads?campaign_id={id}` ผู้สนใจของแคมเปญ

Spec หลักของ Leads อยู่ที่เอกสาร Interested-parties ตรงนี้ระบุเฉพาะส่วนของแคมเปญ

| Param | ความหมาย |
|-------|----------|
| `campaign_id` | แคมเปญที่ดู |
| `page`, `per_page`, `search` | แบ่งหน้า / ค้นหา |
| `registration_page` | 📝 **ร่าง** Backend ยังไม่รองรับ CSV ของ `search_brand_project`, `search_new`, `search_secondhand`, `search_rent`, `search_home_builder`, `search_house_model`, `listing_detail_section`, `landing_page` ใช้กรอง "หน้าที่ลงทะเบียน" ให้ตรงกับ `campaign_registration.page` (หัวข้อ 4.6) เลือกครบทุกหน้า FE ไม่ส่ง param นี้ ชื่อค่าเป็นของฝั่ง FE ยังไม่ได้ตกลงกับ Backend |
| `follow_up_status` | CSV ของ `not_contacted`, `unreachable`, `contact_again`, `waiting_booking`, `booked`, `transferred`, `rejected` |
| `interest_category` | CSV ของหมวดที่เลือกใน "ลงทะเบียนสนใจ": `new`, `secondhand`, `rent`, `home_builder` เลือกครบทุกหมวด FE ไม่ส่ง param นี้ (ตัวกรองเดียวกับที่ `staging` ใช้อยู่ commit `60004aeb`) |

ตัวกรองของหน้านี้มี 3 ตัว: "หน้าที่ลงทะเบียน" (`registration_page`), "ลงทะเบียนสนใจ" (`interest_category`), "การติดตาม" (`follow_up_status`) **หน้าแคมเปญไม่มีตัวกรอง "ประเมินลูกค้า"** FE จึงไม่ส่ง `assessment` จากหน้านี้ (ผลประเมินรายคนยังแก้ได้ผ่าน `PATCH /api/leads/{id}`)

**ต้องตกลงกับ Backend:** รับ `registration_page` แล้วกรองตามหน้าที่ลีดลงทะเบียน และให้ค่า `campaign_registration.page` ของลีดแต่ละรายการสอดคล้องกับ 8 ค่าข้างบน (ชื่อค่าเป็นข้อเสนอของ FE) จนกว่าจะรองรับ ตัวกรองนี้ยังไม่มีผลกับรายการ

Response: `data.items[]`, `data.pagination.total` และ `PATCH /api/leads/{id}` ใช้อัปเดตผลประเมิน (assessment) ตาม spec ของ Leads

ที่ลีดแต่ละรายการ FE อ่าน `events[]` (`{ id, type: "campaign" }`) เพื่อรู้ว่ามาจากแคมเปญไหน และมี **ร่าง** `campaign_registration` (หัวข้อ 4.6)

## 4. Contract ที่ Backend ยืนยันแล้ว (12 พ.ย. 2569): step 2, 3, 5

* ใช้ endpoint เดิม (`POST` / `PATCH` / `GET /api/event-campaigns`) ส่งใน body เดียวกับข้อ 3.3
* ชื่อ field ต้องตรงตามหัวข้อนี้ทุกตัว (Backend ทิ้งค่าของ field ที่ไม่รู้จักเงียบ ๆ) การ map ทั้งหมดของ FE อยู่ที่ `utils/campaign/eventCampaignSections.ts` และมี test ล็อกชื่อ key ของทุกก้อน
* FE ส่งทุกก้อนในหัวข้อนี้ **ครบทุกครั้ง** ที่บันทึก (ก้อนที่ถูกเขียนทับทั้งก้อนต้องครบ ไม่งั้นค่าเดิมถูกลบ)

### 4.1 สีของแคมเปญ (step 2) `color_config`

รูปแบบสี (เป็น string)

* **gradient**: `linear-gradient(<deg>deg, rgba(r,g,b,a) 0%, rgba(r,g,b,a) 100%)` หรือ `radial-gradient(circle at center, rgba(r,g,b,a) 0%, rgba(r,g,b,a) 100%)` มี **สองจุดสีเท่านั้น** (เป็นรูปแบบเดียวที่ parser ของเว็บสาธารณะอ่านได้)
* **solid**: `rgba(r,g,b,a)` (ไม่มีช่องว่างในวงเล็บ `rgba(1,61,162,1)` ไม่ใช่ `rgba(1,61,162),1`)

```json
{
  "color_config": {
    "navbar": { "background": "<gradient>", "text": "<solid>" },
    "band_background": "<gradient>",
    "sections": {
      "booking_promotion": { "header": "<gradient>", "text": "<solid>", "background": "<gradient>" },
      "articles_videos":   { "header": "<gradient>", "text": "<solid>", "background": "<gradient>" },
      "promotion_videos":  { "text": "<solid>", "background": "<solid>" }
    },
    "button": { "background": "<gradient>", "text": "<solid>" }
  }
}
```

| Field | ฟอร์ม (`step2.colorConfig`) | ชนิดสี |
|-------|---------------------------|--------|
| `navbar.background` / `navbar.text` | `navbar.background` / `.text` | gradient / solid |
| `band_background` | `campaignBackground` (ใช้เมื่อ `background_type = campaign_color`) | gradient |
| `sections.booking_promotion.*` | `sections.bookingPromotion.*` | header gradient, text solid, background gradient |
| `sections.articles_videos.*` | `sections.articlesVideos.*` | header gradient, text solid, background gradient |
| `sections.promotion_videos.*` | `sections.promotionVideos.*` | text solid, background solid (พื้นขาวที่มีแสงวงกลมสองดวงจากสีนี้) |
| `button.*` | `button.*`                | background gradient, text solid |

รวม 13 ค่า

* Backend เก็บ string ตามที่ส่ง **ไม่ validate** FE ต้องสร้างรูปแบบให้ถูกเอง (FE ตรวจก่อนบันทึก)
* `sections.promotion_videos` ไม่มี `header` ตอน `GET` Backend คืน `"header": ""` (FE เมิน)
* แคมเปญเก่า `GET` ได้ `color_config: null` FE ใช้สีเริ่มต้นของฟอร์ม และสีใดที่ไม่อยู่ในรูปแบบของช่องนั้นก็ใช้ค่าเริ่มต้นของช่องนั้น
* ส่ง `color_config: null` เพื่อล้างค่าไม่ได้ (ไม่รองรับ) ถ้าต้องการรีเซ็ตให้ส่ง object ค่าว่าง FE ส่ง object เต็มเสมอ
* เว็บสาธารณะ (หน้า landing) **ยังไม่อ่าน** `color_config` และ parser เดิมของหน้าบ้านรับรูปแบบอื่น (`background`, `section_header`, `section_text`, `action`) ต้องปรับให้อ่านรูปแบบของหัวข้อนี้

### 4.2 Main Sponsor (step 3) `main_sponsor_promotions`

แยกจาก `main_sponsors` ของ step 1 (โลโก้ผู้สนับสนุนหลัก step 1 ไม่เปลี่ยน)

```json
{
  "main_sponsor_promotions": [
    {
      "id": 1,
      "title": "SCG",
      "banners": {
        "desktop": [{ "alt": "", "image_path": "event-campaign/d1.webp", "link": "https://example.com" }],
        "mobile":  [{ "alt": "", "image_path": "event-campaign/m1.webp", "link": "https://example.com" }]
      },
      "categories": ["new", "secondhand"],
      "colors": {
        "header": "rgba(1,61,162,1)",
        "text": "rgba(255,255,255,1)",
        "background": "linear-gradient(180deg, rgba(1,61,162,1) 0%, rgba(248,101,1,1) 100%)"
      }
    }
  ]
}
```

* `title` เป็น **string ธรรมดา** (ไม่ใช่ `{ th }`) FE จำกัด 1–30 ตัวอักษร
* `banners.desktop` / `banners.mobile` แต่ละรายการ `{ id?, alt, image_path, link }` FE ไม่ส่ง banner `id` (Backend เติมตามตำแหน่ง) ส่ง `alt: ""` และ `link` ผูกกับรูปแต่ละรูป ฝั่งละ ≥ 1 รูป
* `categories` ใช้ได้เฉพาะ `new` / `secondhand` / `rent` / `home_builder` อย่างน้อย 1 ไม่ซ้ำ
* `colors.header` และ `colors.text` FE ส่งเป็นสีเดียว `rgba(...)` ส่วน `colors.background` เป็น gradient สองจุด Backend เก็บตามที่ส่ง (ตัวอย่างของ Backend เขียน `header` เป็น `<gradient>` แต่ไม่ได้ validate) ปีกซ้าย-ขวาของแถบหัวข้อ **ไม่เก็บ** เป็นสีหนึ่งต่างหาก คือสี `header` ลดความสว่างเหลือ 78% (`filter: brightness(0.78)`) เว็บสาธารณะต้องคำนวณแบบเดียวกัน
* `**id**`: เป็น integer ที่ Backend ออกให้ แถวใหม่ไม่ส่ง `id` (หรือส่ง 0) แถวเดิมส่ง `id` ที่ได้จาก response (ในฟอร์ม FE ใช้ uuid จนกว่าจะได้เลข: ส่ง `id` เฉพาะค่าที่เป็นเลขจำนวนเต็มบวก) `id` ที่ไม่มีในแคมเปญนี้ ซ้ำ หรือติดลบ → 400
* **ส่งทั้งรายการตามลำดับที่ลากทุกครั้ง**: แถวที่ไม่ส่ง = ลบ, `[]` = ลบทั้งหมด, ไม่ส่ง key = ไม่แตะ ไม่ต้องส่ง `order` (Backend ใช้ตำแหน่งใน array + 1)
* `GET` คืน `[]` เสมอ ไม่คืน `null`
* หลังบันทึก FE กลับไปหน้ารายการเสมอ (ทั้งบันทึกร่างและเผยแพร่) แถวใหม่ได้ `id` ตอนเปิดหน้าแก้ไขรอบถัดไป
* ในหน้า step 6 FE นับ "จำนวนใบประกาศ" ของ Main Sponsor จากใบประกาศที่ร่วมแคมเปญในหมวดของมัน (คำนวณฝั่ง FE ไม่ต้องมี field)

### 4.3 Flash Deal (step 5) `flash_deal`

```json
{
  "flash_deal": {
    "is_visible": true,
    "start_at": "2026-11-19T17:00:00.000Z",
    "end_at": "2026-11-22T16:59:59.999Z",
    "logo_image_path": "event-campaign/fd-logo.webp",
    "banners": {
      "desktop": [{ "alt": "", "image_path": "event-campaign/fd-d1.webp", "link": "https://example.com" }],
      "mobile":  [{ "alt": "", "image_path": "event-campaign/fd-m1.webp", "link": "https://example.com" }]
    },
    "colors": {
      "header": "linear-gradient(260deg, rgba(1,61,162,1) 0%, rgba(1,61,162,1) 100%)",
      "text": "rgba(255,255,255,1)",
      "background": "linear-gradient(180deg, rgba(1,61,162,1) 0%, rgba(248,101,1,1) 100%)"
    },
    "items": [
      { "entity_kind": "post", "entity_id": 4577, "is_top": true },
      { "entity_kind": "hb_branch", "entity_id": 120, "entity_sub_id": 65, "is_top": false }
    ]
  }
}
```

| Field | ฟอร์ม (`flashDeal`) | กติกา |
|-------|-------------------|-------|
| `is_visible` | `enabled` (สวิตช์ที่หัวการ์ด) | ปิดอยู่ = FE ไม่บังคับกรอกอะไร และไม่แสดงในสรุป แต่ยังส่ง `flash_deal` ครบทุก field |
| `start_at`, `end_at` | `startDate`, `endDate` | ISO 8601 FE ส่งแบบ `web_period` (เริ่ม = วันที่เลือก `00:00`, สิ้นสุด = สิ้นวัน) ไม่ส่งตัวที่ยังไม่ได้เลือก เปิดอยู่ = FE บังคับทั้งคู่และสิ้นสุดไม่ก่อนเริ่ม |
| `logo_image_path` | `logo`            | ไม่บังคับ, 0–1 รูป, อัตราส่วน 2:1 ไม่มี = `""` |
| `banners.desktop`, `banners.mobile` | `desktopBanners`, `mobileBanners` | `{ alt, image_path, link }` แต่ละรูปมีลิงก์ของตัวเอง เปิดอยู่ = ฝั่งละ ≥ 1 รูป |
| `colors.header`, `.background` | สีแถบหัว / พื้นหลัง | gradient สองจุด |
| `colors.text` | สีตัวอักษร        | `rgba(...)` |
| `items[]` | `listings` (ตารางใบประกาศ) | `{ entity_kind, entity_id, entity_sub_id?, is_top }` ไม่มี `category` และไม่ต้องส่ง `order` (ใช้ตำแหน่งใน array) `is_top` ติ๊กได้หลายใบ |

* **เขียนทับทั้งก้อน**: ทุกครั้งที่ส่งต้องส่งครบทุก field (ไม่ส่ง `logo_image_path` หรือ `colors` = ค่าเดิมถูกลบ) ปิด section = ส่ง `is_visible: false` พร้อมข้อมูลเดิมทั้งหมด `flash_deal: null` = ลบทั้ง section (FE ไม่ส่ง `null`)
* `**items**` **ต้องเป็นใบที่ "เข้าร่วมแคมเปญ" (**`**participants**`**)**: FE จึงให้เลือกจากใบที่เลือกไว้ใน **step 3** (ไม่ใช่ `listing-picker`) และ `entity_kind` / `entity_id` / `entity_sub_id` ใช้ฟังก์ชันเดียวกับที่สร้าง `participants[]` (`getListingEntity`) เพื่อไม่ให้สองรายการเพี้ยนกัน
  * ใบที่ไม่ได้เข้าร่วมและเพิ่งเพิ่มใหม่ → 400 `flash_deal.items[i]: ... is not a participant of this campaign`
  * ใบที่เคยอยู่ใน Flash Deal แล้วถูกเอาออกจาก `participants` → Backend ลบออกจาก `items` เองโดยไม่ error FE ทำแบบเดียวกัน: เอาใบที่ถูกลบจาก step 3 ออกจาก Flash Deal ในฟอร์ม และไม่ส่งใบที่ไม่อยู่ใน step 3
  * `hb_branch`: `entity_id` = central_id ของบริษัท, `entity_sub_id` = province_id ของสาขา (FE ส่ง province ของแคมเปญ ดูข้อ 6 #11)
* ตอนอ่านกลับ FE จับคู่ item กับ participant ด้วย kind + id (`hb_branch` ดู `entity_sub_id` ด้วย) แล้วแสดงข้อมูลใบประกาศจากรายการใน step 3 item ที่ไม่ตรงกับ participant จะถูกข้าม
* แคมเปญที่ไม่มี `flash_deal` FE ใช้ฟอร์ม Flash Deal เปล่า

### 4.5 ปกวิดีโอ `cover_image`

* `promote_videos[].cover_image` (step 1) รับ storage key (Shorts / TikTok จาก `ingest-url` ข้อ 3.12) หรือลิงก์ `i.ytimg.com` (YouTube ปกติ) ส่งเมื่อมีปก อ่านกลับแล้วไม่ไปดึงจากลิงก์วิดีโออีก
* **ชื่อต้องเป็น** `**cover_image**` ถ้าส่ง `cover_image_path` ค่าจะหายทุกครั้ง (FE เคยส่งชื่อนี้ ปกจึงไม่เคยถูกเก็บ แก้แล้ว 12 พ.ย.)
* **ปก TikTok เก็บเฉพาะ storage key**: ลิงก์ดิบของ TikTok หมดอายุราว 2 วัน FE จึงไม่ส่งลิงก์ดิบ (ถ้า ingest ไม่สำเร็จ ไม่ส่งปก) และถ้าอ่านเจอปก TikTok ที่เป็นลิงก์ `http(s)` ที่เคยถูกเก็บไว้ จะไม่เชื่อ แต่ดึงใหม่จากลิงก์วิดีโอ ปก YouTube / Shorts ที่เป็นลิงก์ ytimg ไม่หมดอายุ เก็บได้
* `participants[].campaign_videos[].cover_image` (step 3) FE ส่งตามกติกาเดียวกัน (modal แสดงรูปดิบทันที แล้วสลับเป็น key เมื่อ ingest เสร็จ) แต่ **ฟิลด์นี้ไม่อยู่ใน contract ของ Backend** ถ้า Backend ไม่รับจะถูกทิ้งเงียบ ๆ รอยืนยัน (ข้อ 6 #18)

### 4.6 📝 `campaign_registration` ของลีด (รายชื่อผู้สนใจของแคมเปญ) ร่าง

> ชื่อ field ในหัวข้อนี้เป็นข้อเสนอจากฝั่ง FE ยังไม่ได้ตกลงกับ Backend

ใส่ใน item ของ `GET /api/leads` (ทุก field optional หน้าจอยังแสดงได้จาก `type`, `category`, `display_snapshot`, `enroll` ถ้าไม่มี)

```json
{
  "campaign_registration": {
    "category": "new",
    "page": "Search รวมโครงการใหม่",
    "page_detail": "โครงการ A",
    "forward_status": "sent",
    "answers": [{ "question": "งบประมาณ", "answer": "3-5 ล้านบาท" }]
  }
}
```

| Field | ความหมาย |
|-------|----------|
| `category` | `brand_project`, `new`, `secondhand`, `rent`, `home_builder`, `campaign_special`, `flash_deal` ชิปในคอลัมน์ "ลงทะเบียนสนใจ" |
| `page` | "หน้าที่ลงทะเบียน" เช่น "Search รวมโครงการใหม่", "Landing Page" |
| `page_detail` | บรรทัดที่สอง เช่น ชื่อโครงการ, "Section ลงทะเบียน" |
| `forward_status` | `sent`, `not_sent` หรือ `""` (ไม่เกี่ยวข้อง แสดง "-") คอลัมน์ "ส่งรายชื่อลูกค้า" |
| `answers[]` | คำตอบของผู้สนใจตามลำดับที่แสดง ใน modal "ข้อมูลเพิ่มเติม" (คำถามต่างกันตามหมวด) |

## 6. คำถามที่ต้องตกลงกับ Backend

✅ = Backend ตอบแล้ว (12 พ.ย.) / 📝 = ยังค้าง

| \#  | เรื่อง | สถานะ / รายละเอียด |
|-----|--------|--------------------|
| 1   | ชื่อและการตรวจ `promote_videos[].cover_image` | ✅ ชื่อที่ถูกคือ `cover_image` (ไม่ใช่ `cover_image_path`) รับ storage key หรือลิงก์ ytimg FE แก้แล้ว |
| 2   | `PATCH` ที่ส่งชุดเต็ม | ✅ array แทนที่ทั้งชุด (แถวที่ไม่ส่ง = ลบ) ตัวระบุ: `promote_videos[].id`, `lucky_winners[].winner_id` (ไม่ส่ง / 0 = แถวใหม่), `participants` (`entity_kind + entity_id + entity_sub_id`), `main_sponsor_promotions[].id`; `ghost_articles` และ `main_sponsors` ไม่มี id แทนที่ทั้งชุด |
| 3   | บันทึกร่าง vs เผยแพร่ | ✅ Backend ตรวจรูปแบบข้อมูลเสมอ และตอน `online` ตรวจ field บังคับ (ข้อ 3.3) ไม่ผ่าน → 422 ส่วนกติกาตรวจฝั่ง FE Backend ไม่ตรวจ |
| 4   | `card_frames` | ✅ เป็น string ทั้งบันทึกและอ่าน |
| 5   | ภาษาจีน `cn` กับ `zh` | ✅ ใช้ `cn`         |
| 6   | `pagination` ของรายการ | 📝 camelCase หรือ snake_case และ `listing-picker` คืน array ตรง ๆ หรือ `{ items, pagination }` |
| 7   | `status` ของรายการ | ✅ `pre_event` / `active` / `expired` (ไม่ใช่ `ended`) Backend คำนวณตามวันไทย พร้อม `status_label` FE ต้องแก้จาก `ended` เป็น `expired` และเลิกเทียบ `end_at` เองได้ |
| 8   | `check-slug` | 📝 ใช้ `available` ตัวเดียว (ตอนนี้ FE รองรับ 5 ชื่อ) |
| 9   | `blocked-dates` | ✅ `start` / `end` เป็น `YYYY-MM-DD` ตามวันไทย Backend ตรวจวันทับตอนบันทึก (409) |
| 10  | `create` คืน id | ✅ คืน `data.campaign_id` (ไม่มี `id`) |
| 11  | `entity_sub_id` ของ `hb_branch` | ✅ Backend: `entity_id` = central_id ของบริษัท, `entity_sub_id` = province_id ของ **สาขา** 📝 FE ส่ง province ของแคมเปญ ยืนยันว่าเท่ากับ province ของสาขา (ถ้าแคมเปญเลือกสาขาข้ามจังหวัดได้ ต้องเปลี่ยน) |
| 12  | `lucky_winners[].updated_at` | ✅ Backend ตั้งเอง FE เลิกส่งแล้ว |
| 13  | `section_order` ของแคมเปญเก่า | ✅ Backend เติม slug ที่ขาดตอน `GET` |
| 14  | `coming_soon` | 📝 อ่านจาก `participants[].listing.coming_soon` และแต่ละ item ของ `listing-picker` ตรวจบน dev เมื่อ 10 พ.ย. ยังไม่มีเส้นไหนส่ง field นี้ ป้ายจึงยังไม่ขึ้น |
| 15  | หมวดเช่า / หอพัก | 📝 เปิดให้เลือกใน step 1 แล้ว (6 พ.ย.) ยังไม่ได้ยืนยัน `listing-picker` ของ `secondhand_rent` และว่า create / update รับ `rent` ใน `participants` กับ `card_frames.rent` ได้ครบ |
| 16  | ชื่อ field ของหัวข้อ 4.1–4.5 | ✅ ตกลงแล้วตามหัวข้อ 4 (4.6 `campaign_registration` ยังเป็นร่าง) 📝 เว็บสาธารณะต้องปรับ parser ให้อ่าน `color_config` และก้อนใหม่ |
