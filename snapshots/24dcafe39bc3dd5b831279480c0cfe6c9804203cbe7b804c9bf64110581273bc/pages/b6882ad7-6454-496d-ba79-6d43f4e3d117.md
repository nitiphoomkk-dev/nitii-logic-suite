ศูนย์กลางวิธีทำงานและชุดติดตั้งนิติ๊สำหรับทีม NaYoo รุ่น 1.0.0 จัดทำวันที่ 15 ตุลาคม 2569

## เริ่มใช้งาน


1. รับชุดติดตั้งหรือ clone Private Repository ของทีม แล้วเปิดโฟลเดอร์โปรเจกต์ใน Codex
2. ติดตั้ง Plugin nitii จาก Marketplace nayoo-team และเริ่มแชทใหม่
3. เชื่อม Wiki ด้วย OAuth บัญชีของตัวเอง และเชื่อม Google Drive เมื่อต้องอ่านเอกสารต้นฉบับ
4. เรียก $nitii-setup เพื่อตรวจการเชื่อมต่อ แล้วเรียกนิติ๊ทำงานตามโจทย์

## หน้าที่ของนิติ๊

อ่านแหล่งข้อมูลปัจจุบัน แยกกฎยืนยัน ข้อเสนอ ตัวอย่าง ข้อขัดแย้งและเรื่องรอตัดสิน เลือกทีม BA QA SA PO PM UXUI Backend Frontend เฉพาะที่จำเป็น และรวมผลด้วยคำตัดสินชุดเดียวกัน

ตัวอย่างคำสั่ง:

* นิติ๊ ใช้ QA และ SA ตรวจช่องโหว่ Logic นี้
* นิติ๊ ทำ Solution สำนวน BA และแยกเงื่อนไขรอยืนยัน
* นิติ๊ ให้ PM ประเมินเฉพาะเวลาของ BA

## กติกาความรู้ร่วมกัน

* Google Docs, Sheets, Canva และ Figma ต้นฉบับใช้อ่านและอ้างอิง ห้ามแก้ไขต้นทางตามกติกาทีม
* ผู้ใช้หรือผู้รับผิดชอบ Business เป็นผู้ตัดสินกฎ PO เสนอทางเลือก PM ไม่ commit วันเสร็จแทนทีม
* ก่อนตอบงานเฉพาะเรื่องให้อ่านแท็บที่เกี่ยวข้องล่าสุด หรือใช้ snapshot ที่มี source URL และเวลาอ่านในรอบเดียวกัน
* แยกจังหวัดกับ Center บริษัทกับสาขา Slot ต้นทางกับการ์ดแสดง และสิทธิ์ Ads กับรายการที่ถูกเลือกแสดง
* ประวัติแชท รหัสเอเจนประจำแท็บและบัญชีของผู้สร้างไม่ติดไปกับ Plugin; ข้อตกลงในแชทหนึ่งไม่กลายเป็นความรู้ทั้งทีมอัตโนมัติ
* ผลวิเคราะห์หรือ Test Design ไม่ใช่ผลทดสอบระบบจริง เคสที่ยังไม่รันใช้ Not Run

## บันทึกคำตัดสินของทีม

เมื่อมีคำตัดสินใหม่ ให้บันทึก Product/หน้า จังหวัดหรือ Center รหัสกฎ ข้อความที่ยืนยัน ผู้ยืนยัน วันเวลามีผล ลิงก์ source กฎที่แทน และประเด็นค้าง หลังได้รับอนุญาตให้บันทึก Wiki แล้ว ห้ามคัดข้อเสนอหรือ Demo มาเป็นกฎยืนยันเอง

## เวอร์ชันและการอัปเดต

ชุดรุ่น 1.0.0 จัดทำและตรวจรูปแบบไฟล์ Skill ทั้ง 10 ตัว รวมถึง schema ของ Plugin/MCP แล้ว ผ่านการทดลองด้วยข้อมูลจำลองและตรวจการย้ายโฟลเดอร์ มี Local Git Repository และ tag v1.0.0 พร้อมชุด ZIP สำหรับส่งต่อ Repository บน GitHub ยังรอเจ้าของระบุบัญชีหรือองค์กรและชื่อ Private Repository ยังไม่ได้เผยแพร่ Marketplace ให้องค์กรหรือยืนยันติดตั้งในบัญชีสมาชิก

ผู้ดูแลอัปเดตแพ็กเกจและ CHANGELOG → ตรวจ → commit/tag → สมาชิกอัปเดต Marketplace และตรวจเวอร์ชันจริง บัญชีและสิทธิ์เชื่อมต่อของแต่ละคนแยกกัน

งานซิงก์ Docs เข้า Wiki ให้ใช้ routine กลางที่มีผู้ดูแล การติดตั้ง Plugin ไม่สร้างงานซิงก์อีกชุดบนทุกเครื่อง ก่อนเขียนต้องตรวจ baseline และ conflict และอ่านกลับหลังเขียน
