## **1) แนวคิดและขอบเขต**\n**1.1 การแสดง Tab ลงทะเบียน**

ฟอร์มลงทะเบียนเป็นเนื้อหาของ **Tab ลงทะเบียน** ผู้ใช้เปิดฟอร์มด้วยการเลือก Tab นี้ การจัดวาง Tab และหน้าตาฟอร์มให้ใช้ UI ที่แนบเป็นหลัก

Tab ลงทะเบียนเป็นส่วนของการนำทางในแกลเลอรี จึงไม่ใช่รายการภาพ และไม่ต้องใช้จำนวนหรือลำดับรูปภาพเป็นเงื่อนไขในการสร้างฟอร์ม

### **1.2 ขอบเขตหน้าจอตาม UI**

|----------|-------|--------------------------|

| โครงการ Walk-in | ฟอร์มโครงการพร้อมตัวเลือกเข้าร่วม Walk-in | Modal “สรุปคูปองที่เก็บ” |
| แบบบ้าน  | ฟอร์มขอคำปรึกษาจากบริษัทรับสร้างบ้าน | Modal “บันทึกข้อมูลสำเร็จ” |

ใช้รูปแบบ Desktop และ Mobile ของแต่ละกลุ่มตาม UI โดยชื่อ หัวข้อ ปุ่ม และปลายทางการติดต่อจะต้องตรงกับใบประกาศที่ผู้ใช้เปิด

ขอบเขตทั่วเว็บไซต์ในเอกสารนี้หมายถึง **ฟอร์มลงทะเบียนความสนใจหรือขอให้ติดต่อกลับ** ไม่รวมฟอร์มสมัครบัญชีผู้ใช้หรือเข้าสู่ระบบ

## **3) Flow การใช้งาน Tab ลงทะเบียน**

### **3.1 ผู้ใช้เปิดฟอร์ม**


1. ผู้ใช้เปิดแกลเลอรีของใบประกาศ
2. แกลเลอรีแสดง Tab ลงทะเบียนตามตำแหน่งใน UI
3. ผู้ใช้เลือก Tab ลงทะเบียน
4. ระบบแสดงฟอร์มของใบประกาศนั้น โดยใช้หัวข้อและปุ่มตามประเภท
5. ผู้ใช้กรอกข้อมูลและกดปุ่มลงทะเบียน

การเลือก Tab มีหน้าที่เปิดเนื้อหาฟอร์ม การส่งข้อมูลเริ่มจากการกดปุ่มลงทะเบียนเท่านั้น

### **3.2 ผู้ใช้ลงทะเบียนสำเร็จ**


1. ระบบตรวจข้อมูลตามเงื่อนไขที่กำหนดให้ฟอร์มนั้น
2. ระบบรับและบันทึกการลงทะเบียน โดยอ้างอิงใบประกาศที่เปิดอยู่
3. การลงทะเบียนครั้งนี้ต้องส่งเข้ารายชื่อผู้สนใจและส่งเข้า LINE “ลูกค้ามาแล้ว” ตามผู้รับที่ถูกต้อง
4. ระบบแสดง Modal ผลลงทะเบียนตาม Flow ซ่อนบนฟอร์ม
5. ฟอร์มลงทะเบียนยังคงอยู่ใน Tab ด้านหลัง Modal
6. เมื่อ Modal สิ้นสุด ผู้ใช้กลับมาเข้าถึงฟอร์มใน Tab ลงทะเบียนได้

**การลงทะเบียนสำเร็จไม่ทำให้ Tab หรือฟอร์มลงทะเบียนหายไป**

### **3.3 ภาพรวม Flow**

เปิดแกลเลอรีใบประกาศ

→ เลือก Tab ลงทะเบียน

→ แสดงฟอร์มตาม UI ของประเภทใบประกาศ

→ ผู้ใช้กรอกข้อมูลและกดลงทะเบียน

→ รับและบันทึกการลงทะเบียน

→ ส่งรายชื่อผู้สนใจ และส่ง LINE ลูกค้ามาแล้ว

→ แสดง Modal ผลลงทะเบียนซ่อนบนฟอร์ม

→ Modal สิ้นสุดตามพฤติกรรมของ UI

→ กลับมาเข้าถึงฟอร์มใน Tab ลงทะเบียนได้


## **4) Logic การแสดง Modal และฟอร์ม**

### **4.1 Modal ผลลงทะเบียนธรรมดา**

เมื่อระบบบันทึกการลงทะเบียนสำเร็จ ให้แสดง Modal **“บันทึกข้อมูลสำเร็จ”** พร้อมสัญลักษณ์สำเร็จตาม UI โดย Modal ซ่อนบนฟอร์มลงทะเบียน

ฟอร์มยังอยู่ด้านหลัง Modal เมื่อ Modal สิ้นสุดให้กลับมาเข้าถึงฟอร์มใน Tab ลงทะเบียนได้

ภาพ UI ไม่ระบุเวลาสิ้นสุดหรือวิธีปิด Modal ธรรมดานี้ จึงยังไม่กำหนดระยะเวลาปิดอัตโนมัติใน Solution

### **4.2 Modal สรุปคูปองตาม UI Walk-in**

กรณี Flow รับคูปองสำเร็จ ให้แสดง Modal **“สรุปคูปองที่เก็บ”** โดยมีข้อความ **“เก็บคูปองสำเร็จ”** และรายละเอียดคูปองตามผลที่ระบบรับจริง

UI มีปุ่มปิด **X** และปุ่ม **“ตกลง”** เมื่อผู้ใช้กดปุ่มดังกล่าวให้ปิด Modal สรุปคูปอง โดยฟอร์มลงทะเบียนยังอยู่ใน Tab

จำนวนและรายการคูปองที่แสดงต้องอ้างอิงผลจริง ภาพตัวอย่างไม่ได้กำหนดจำนวนคูปองตายตัวหรือเงื่อนไขสิทธิ์รับคูปอง

### **4.3 ตารางสถานะการแสดงผล**

| **สถานะ** | **Tab ลงทะเบียน / ฟอร์ม** | **Modal ผลลงทะเบียน** |
|-------|-----------------------|-------------------|
| ผู้ใช้เลือก Tab ลงทะเบียน | แสดงฟอร์มของใบประกาศนั้น | ยังไม่แสดงผลสำเร็จ |
| ลงทะเบียนสำเร็จแบบธรรมดา | ฟอร์มยังอยู่          | แสดง “บันทึกข้อมูลสำเร็จ” ซ่อนบนฟอร์ม |
| รับคูปองสำเร็จใน Flow Walk-in | ฟอร์มยังอยู่          | แสดง “สรุปคูปองที่เก็บ” ซ่อนบนฟอร์ม |
| Modal ผลลงทะเบียนสิ้นสุด | ฟอร์มยังเข้าถึงได้    | ปิดเฉพาะ Modal ผลลัพธ์ |

| ลงทะเบียนไม่สำเร็จ | ฟอร์มยังอยู่          | ไม่แสดงผลสำเร็จ   |

### **6.2 ข้อกำหนดการส่งข้อมูล**


1. การลงทะเบียนที่รับสำเร็จต้องมีผลลัพธ์ครบทั้งรายชื่อผู้สนใจและ LINE “ลูกค้ามาแล้ว”
2. ทั้งสองช่องทางต้องอ้างอิงข้อมูลการลงทะเบียนครั้งเดียวกัน
3. ต้องระบุใบประกาศและผู้รับให้ตรงกับฟอร์มที่ผู้ใช้ลงทะเบียน
4. การเปิด Tab ลงทะเบียน การเห็นฟอร์ม หรือการปิด Modal ไม่ทำให้เกิดการส่งใหม่
5. การแสดง Modal สำเร็จต้องอ้างอิงผลบันทึกการลงทะเบียนจริง

ชื่อ/เบอร์เดิมหรือใหม่เป็นเงื่อนไขรับการลงทะเบียนตามตาราง ไม่ได้กำหนดวิธีรวมข้อมูลบุคคลหรือสูตรนับตัวเลข Lead ในรายงาน

## **7) Acceptance Criteria สำหรับ QA**

รายการนี้เป็นการออกแบบกรณีตรวจรับ ยังไม่ได้ทดสอบระบบจริง กรณีที่เกี่ยวกับรายละเอียดในหัวข้อ 7 ต้องกำหนดผลที่คาดหวังเพิ่มเติมก่อนตรวจรับส่วนนั้น

| **รหัส** | **กรณีตรวจรับ** | **ผลที่ต้องได้** |
|------|-------------|--------------|
| REG-T01 | เปิดแกลเลอรีและเลือก Tab ลงทะเบียน | แสดงฟอร์มใน Tab ตาม UI ของใบประกาศที่เปิด |
| REG-T02 | เปลี่ยนจำนวนภาพของใบประกาศที่มี Tab ลงทะเบียน | ฟอร์มยังเปิดจาก Tab ลงทะเบียน ไม่ต้องคำนวณจุดแทรกตามจำนวนหรือลำดับภาพ |
| REG-T03 | เลือก Tab ลงทะเบียนโดยยังไม่กดส่ง | ไม่เกิดการส่งรายชื่อผู้สนใจหรือ LINE |
| REG-T04 | ตรวจ Desktop และ Mobile | การเปิด Tab และรูปแบบฟอร์มตรง UI ของแต่ละอุปกรณ์ |
| REG-T05 | ลงทะเบียนธรรมดาสำเร็จ | แสดง Modal “บันทึกข้อมูลสำเร็จ” ซ่อนบนฟอร์ม |
| REG-T06 | Modal ธรรมดาสิ้นสุดตามพฤติกรรมที่กำหนด | ฟอร์มยังอยู่และเข้าถึงได้ใน Tab ลงทะเบียน |
| REG-T07 | Flow รับคูปองสำเร็จ | แสดง Modal “สรุปคูปองที่เก็บ” พร้อมข้อมูลคูปองตามผลจริง |
| REG-T08 | กด X หรือ “ตกลง” ใน Modal สรุปคูปอง | Modal ปิด แต่ฟอร์มลงทะเบียนยังอยู่ใน Tab |
| REG-T09 | เลือก Tab ลงทะเบียนอีกครั้งหลังลงทะเบียนสำเร็จ | ฟอร์มยังแสดงและการเปิด Tab ไม่ส่งข้อมูลเพิ่มเอง |
| REG-T10 | ทดสอบหมายเลขเต็มที่ขึ้นต้น 01–09 และผ่านเงื่อนไขรูปแบบที่กำหนด | ทุกกลุ่มผ่านเงื่อนไขเลขขึ้นต้นทั้ง Frontend และ Backend |
| REG-T11 | ตรวจฟอร์มลงทะเบียนความสนใจทุกจุดในเว็บไซต์ | ใช้กฎเลขขึ้นต้น 01–09 และส่งรายชื่อ/LINE ตามขอบเขตเดียวกัน |
| REG-T12 | ชื่อเดิมและเบอร์เดิม ลงทะเบียนใหม่สำเร็จ | ส่งรายชื่อผู้สนใจและ LINE ทั้งสองทาง<br>ตามเงื่อนไข |
| REG-T13 | ชื่อเดิมและเบอร์ใหม่ ลงทะเบียนใหม่สำเร็จ | ส่งรายชื่อผู้สนใจและ LINE ทั้งสองทาง<br>ตามเงื่อนไข |
| REG-T14 | ชื่อใหม่และเบอร์เดิม ลงทะเบียนใหม่สำเร็จ | ส่งรายชื่อผู้สนใจและ LINE ทั้งสองทาง<br>ตามเงื่อนไข |
| REG-T15 | ชื่อใหม่และเบอร์ใหม่ ลงทะเบียนใหม่สำเร็จ | ส่งรายชื่อผู้สนใจและ LINE ทั้งสองทาง<br>ตามเงื่อนไข |
| REG-T16 | ลงทะเบียนจากใบประกาศ A และ B | รายชื่อและ LINE ของแต่ละครั้งอ้างอิงใบและผู้รับที่ถูกต้อง |
| REG-T17 | ปิด Modal ผลลัพธ์โดยไม่ได้ลงทะเบียนใหม่ | ไม่ส่งรายชื่อผู้สนใจหรือ LINE เพิ่ม |

## **8) Requirement สำหรับคัดลอกไปใช้**

ระบบต้องแสดงฟอร์มเป็น Tab ลงทะเบียนภายในแกลเลอรีใบประกาศตาม UI ทั้ง Desktop และ Mobile ผู้ใช้เลือก Tab นี้เพื่อเปิดฟอร์ม โดยฟอร์มไม่เป็นรายการภาพและไม่ใช้จำนวนหรือลำดับภาพเป็นเงื่อนไขการแสดง เมื่อลงทะเบียนสำเร็จ ให้แสดง Modal ผลลงทะเบียนตาม Flow ซ่อนบนฟอร์ม โดยฟอร์มและ Tab ลงทะเบียนยังอยู่และเข้าถึงได้เมื่อ Modal สิ้นสุด

ฟอร์มลงทะเบียนความสนใจทั้งเว็บไซต์ต้องรับหมายเลขที่ขึ้นต้น 01, 02, 03, 04, 05, 06, 07, 08 และ 09 ด้วยเงื่อนไขเลขขึ้นต้นเดียวกันทั้ง Frontend และ Backend ทุกการลงทะเบียนใหม่ที่ระบบรับสำเร็จต้องส่งเข้ารายชื่อผู้สนใจและส่งเข้า LINE “ลูกค้ามาแล้ว” ตามใบประกาศและผู้รับที่ถูกต้อง ครอบคลุมทุกกรณีชื่อเดิม/ชื่อใหม่และเบอร์เดิม/เบอร์ใหม่ การเปิด Tab หรือปิด Modal อย่างเดียวไม่ถือเป็นการลงทะเบียนใหม่\n
