## **EP-02 หน้า Home (รอ แสดงตัวนับเวลาถอยหลัง)**

ออกแบบ CTA ให้น่ากดเข้าไปสู่หน้า landing page

•        **หลักการ:** หน้า Home ไม่เน้นเอาสินค้า/Super Top Ads ขึ้นมาแสดง เพราะยังเดาความสนใจผู้ใช้ไม่ได้ (CTR เสี่ยง) เป้าหมายคือดึงดูดให้ผู้ใช้คลิกเข้าหน้า Landing

•        **Section Event Online:** เป็น Section ที่แทรกขึ้นมาในหน้า Home ได้ (เช่น ก่อน Section Review) โดยมี Theme ที่มองแล้วรู้ทันทีว่าเป็น Event

•        **พื้นที่แสดงผล:** Section Event บนหน้า Home ควรกินพื้นที่จำกัด (ประมาณเท่าของเดิม) ไม่แสดงเยอะ เพราะแสดงได้หลายตำแหน่งในหน้าอื่นอยู่แล้ว

•        **ประเด็นถกเถียง (Open):** Section Video ของเดิม (ที่ลูกค้าชอบ ตามที่พี่เบียร์ระบุ) จะแสดงหรือไม่ และจะวางต่อจาก Section Video เดิมหรือซ้อนกัน — รอดูข้อมูลว่าผู้ใช้คลิกจากหน้าไหนก่อนตัดสินใจ

## **EP-03 หน้า Search (แต่ละหมวด)  (รอ data ว่าจะแสดงระหว่าง ใบประกาศ วิดีโอ โปรโมชั่น)**

ออกแบบ CTA ให้น่ากดเข้าไปสู่หน้า landing page  ออกแบบให้เป้นแคมเปญ

•        **หลักการ:** เมื่อผู้ใช้เข้าหน้า Search แต่ละหมวด แสดงว่ารู้ความสนใจของผู้ใช้แล้ว การเอาสินค้าขึ้นมาแสดงจึงน่าสนใจกว่าหน้า Home

•        โครงการ/ลูกค้าที่เข้าร่วม Campaign จะถูกแสดงในจุดที่ผู้ใช้สนใจ ทำให้ได้คลิกมากกว่า (แยกตามความสนใจ)

•        การ์ดที่ออกแบบใหม่สำหรับ Event ต้องไม่แตกต่างจากการ์ดเดิมมากเกินไป เพื่อไม่ให้ผู้ใช้สับสน (Size/Template Standard) แต่ใช้กรอบ (Frame) หรือ Graphic เพื่อบ่งบอกว่าเป็น Event

•        Tag Event ปัจจุบันเป็น “กรอบ” หากกรอบไม่พอ ให้ออกแบบการ์ดแบบใหม่ที่ยังเข้าธีมกับการ์ดอื่นได้

•        **ประเด็นถกเถียง (Open):** ลำดับ Section บน/กลาง/ล่าง และจะวาง Section Event ก่อนวิดีโอ หรือเอาวิดีโอ Event ขึ้นก่อน — ยังมี 2 แนวคิด (รวมกรอบไว้ใน Event ให้จบ vs Split Event ออกมาเป็นกลุ่ม) ต้องคุยเพิ่ม

## **EP-04 หน้าใบประกาศ (Listing Detail)**

แบ่งเป็น 2 กรณีตามสถานะการเข้าร่วม Campaign:

### **กรณีที่ 1: โครงการที่เข้าร่วม Campaign (และซื้อสิทธิ Premium/Top Event)**

•        แสดง Short Video ที่ลอยมุมขวาล่างใน mobile และ PC แสดงตำแหน่งงเดิม(เหมือน เฉพาะช่วงแคมเปญ

•      Section Promotion ของโครงการที่เข้าร่วม (รายละเอียดการแสดงผลรอประชุมเรื่องคูปองพรุ่งนี้)

* โปรโมชั่นตอนนี้มี event ของโครงการต้องแสดงให้โดนเด่น

**กรณีที่ 2: โครงการที่ไม่เข้าร่วม (หรือเข้าร่วมแต่ไม่ซื้อ Premium)**

•        ด้านล่างแสดงโฆษณา/Top Event ของโครงการอื่นที่ซื้อมาแสดง

•        จะไม่แสดงโฆษณาก็ต่อเมื่อโครงการนั้นซื้อ Premium (รายละเอียด Premium ค่อยว่ากันภายหลัง)

•        Section นำเสนอแบบ “คนสนใจแล้วลากไปต่อ” (Design ใหม่) เพื่อกระตุ้นการคลิก

### **องค์ประกอบร่วมของหน้าใบประกาศ**

•        Pop-up ติดตาม: ยังมีใน V2 / เว็บใหม่ (เป็น Pop-up เล็กมุมขวา-ซ้าย ติดตามไปทุกหน้า) — ปัจจุบันแยกตามรายโครงการไม่ได้ เป็นทั้งเว็บ

•        Pop-up ติดตาม สามารถ Modify ใส่ Logic เพิ่มได้ (เช่น โครงการเข้าร่วมแสดงแบบหนึ่ง ไม่เข้าร่วมแสดงอีกแบบ) แต่ต้องระวังไม่ให้สร้างความรำคาญ

**EP-05 เนื้อหาที่แพลตฟอร์มต้องการสื่อสาร (Content / How-to / ประกาศรางวัล)**

ปัญหาเดิม: แพลตฟอร์มไม่มีที่สื่อสารว่า Campaign (เช่น Walk-in) คืออะไร ทำให้คนทั่วไปไม่เข้าใจ ปัจจุบันใส่ได้แค่ VDO เดียว

### **ความต้องการ**

•        รองรับการใส่ VDO ได้หลายตัว (เป็น VDO ที่แพลตฟอร์มต้องการสื่อสาร คนละชุดกับ VDO ของลูกค้า)

•        มี Section บทความ / How-to อธิบายว่า Campaign คืออะไร (เขียนครั้งเดียวใช้ได้ตลอด)

•        **Feature ประกาศรางวัล:** ต้องมี Section ประกาศรางวัล รองรับการกด URL จาก Email/Broadcast แล้ววิ่งเข้าหน้านี้/Section นี้โดยตรง (Deep link)

•        **Sponsor:** ยังมีอยู่ แต่ไม่ต้องเด่นมาก เลื่อนขึ้น-ลงได้

### **ประเด็นเรื่อง Tag บทความ (ข้อจำกัดปัจจุบัน)**

Tag ที่มีในระบบปัจจุบัน:

| **ประเภทเนื้อหา** | **Tag ที่มี** |
|---------------|-----------|
| บทความ        | สาระเรื่องบ้าน, Lifestyle, อัปเดตข่าวสาร, Review |
| VDO           | โครงการใหม่, รับสร้างบ้าน, อสังหามือสอง, Lifestyle (4 Tag) |

•        **ข้อจำกัด:** ระบบบทความปัจจุบันเป็นระบบ Code ติดได้ Tag เดียว (เลือกได้อย่างใดอย่างหนึ่ง) ยังไม่รองรับการติดหลาย Tag — ต้องตัดสินใจว่าจะเอาบทความ Campaign ไปไว้ Tag ใด

## **User Journey หลักในหน้า Landing/Campaign**

1\.      ผู้ใช้เข้าหน้า Landing เห็น Section ลงทะเบียนบนสุด (ฟันธงว่าอยู่บนสุด ไม่ต้องสลับ — ออกแบบให้สื่อสารง่ายขึ้น)

2\.      เลื่อนลงเห็น Section Promotion / Top Event ที่นำเสนอจุดที่น่าสนใจ

3\.      ถ้าสนใจรายการบน (3-4 อันแรก) คลิกเข้าดูได้เลย (Conversion)

4\.      ถ้าไม่ถูกใจ กด “ดูทั้งหมด” → วิ่งไปหน้า Search ที่รวม Filter (Filter Event ทั้งหมดที่เข้าร่วม

•        **หลักการปิดท้ายหน้า (Locked Section):** Section ปิดท้ายควร Lock ด้วยปุ่ม “ดูทั้งหมด” ที่นำไปหน้า Search ไม่ควรปิดท้ายด้วยโปรโมชัน เพราะโปรโมชันไม่ระบุหมวด ทำให้ผู้ใช้ลำบาก

•        **งานที่ต้องการให้ Team data ช่วย:** ออกแบบ Logic การ Recommend / สลับความสนใจของผู้ใช้ในหน้านี้

**•**    **ปัญหาหลักที่ถูกหยิบยกตลอดการประชุม คือ “เนื้อหากินพื้นที่มากเกินไป” ทำให้หน้ายาว เลื่อนนาน และไม่ผ่านการรีวิวบนมือถือ (Mobile)**

**•**    **ทิศทางที่ตกลงร่วมกัน คือ ทำให้แต่ละ section กระชับ ต่อเนื่องเป็นเนื้อเดียวกัน คงธีม Event และดึงผู้ใช้ไปสู่ปุ่ม Call to Action หลักให้ชัด**

**•**    **ยังมีบางประเด็นที่ต้องรอข้อมูลจากทีม Data และต้องยืนยันรายละเอียดการขายกับฝ่ายขาย (P'Dear) ก่อนสรุปดีไซน์บางส่วน**

# **4. สรุปประเด็นการพิจารณาและมติ**

## **4.1 หน้า Event Landing (ภาพรวม / ส่วนหัว)**

**•**    **ออกแบบส่วนโปรโมชันการจองใหม่ จากเดิมคล้ายคูปอง ให้โชว์ภาพเด่นขึ้น และระบุชัดว่ามาจากโครงการ/บริษัทใด**

**•**    **ส่วน Login ปรับเป็นการ์ดแบบตัวหนังสือพื้นหลังขาว และพื้นหลังภาพใช้โทนเขียว–ส้ม**

**•**    **มติ: หน้า Landing ยาวเกินไป ไม่ผ่าน Mobile ให้ปรับใหม่ให้ “กระชับ” จัดชิดซ้าย–ขวา คงธีม Event ให้ผู้ใช้เข้าใจว่าเป็นงานอะไร และใช้โลโก้/ไอคอนงาน (Home Expo) เด่นเต็มด้านบน**

**•**    **มติ: ดีไซน์ด้านในหน้า Landing ต้องสอดคล้องกับดีไซน์ด้านนอก**

## **4.2 ส่วนโปรจอง (Booking Promotion)**

**•**    **ปัญหา: วางการ์ด 3 แถวต่อกัน ทำให้ยาวมาก**

**•**    **มติ: รวมให้เหลือแถวเดียว ใช้ฟิลเตอร์/แท็กแบบเดียวกับ section วิดีโอ (อ้างอิงรูปแบบฟิลเตอร์ของ Shopee) ทำเป็น section แบบปิด เลื่อนซ้าย–ขวา**

**•**    **มติ: แยกโปรของ “หน้าอยู่” (น่าอยู่) ออกจากกลุ่มโปรของโครงการ**

## **4.3 Section Walk-in (รับสร้างบ้าน / พาร์ทเนอร์)**

**•**    **เดิมเป็น 3 แถวแนวนอน จัดชิดซ้าย (โครงสร้าง 3 layer) และย่อให้เล็กกว่านี้ไม่ได้ อีกทั้งจำนวนรายการอาจมาก (อย่างน้อยหมวดละ \~20 รายการ)**

**•**    **มติ: เปลี่ยนเป็นแถวเดียว เลื่อนซ้าย–ขวา ออกแบบการ์ดให้สื่อว่าเลื่อนได้ และไม่ต้องมีฟิลเตอร์ (เพราะจะใช้ Pop-up กระตุ้นผู้ใช้แทน)**

## **4.4 ระยะห่างระหว่าง Section และปุ่ม CTA**

**•**    **ปัญหา: ระยะห่าง (โดยเฉพาะส่วน Login/Consent) ไม่สม่ำเสมอ และพื้นหลังสีฟ้าทำให้ section ดูแยกออกจากกัน**

**•**    **มติ: เอาพื้นหลังสีฟ้าออก เพื่อให้ดูเป็นเนื้อเดียวกัน และให้ปุ่ม CTA (เก็บโปร) อยู่ใน section เดียวกับ Walk-in**

## **4.5 Section แผนที่ (Map)**

**•**    **Mobile ปรับเป็น dropdown แบบ default ทั้งหมด**

**•**    **มติ: ฝั่ง PC ให้ปรับเป็นรูปแบบเดียวกับ Mobile (dropdown) เพื่อความสอดคล้อง**

## **4.6 การเลือกสไตล์ดีไซน์ Section (รูปภาพ)**

**•**    **นำเสนอ 2 ทางเลือก: แบบมีแถบ + รูปเมืองด้านบน กับแบบมีรูปตึกการ์ตูนขนาบข้าง**

**•**    **มติ: เลือกแบบฝั่งซ้าย เพราะรูปไม่กินเข้าไปในตัวอักษร (ที่ประชุมเห็นพ้องกัน)**

## **4.7 Section ทางลัด (Shortcut)**

**•**    **ใส่ภาพพื้นหลังเพื่อให้สื่อความเป็น Event และนำเสนอ 3 แบบให้เลือก**

**•**    **มติ: เลือกแบบที่ 3 (ข้อความอยู่ในบล็อกสี อ่านได้ชัดเจนกว่า)**

## **4.8 User Journey การลงทะเบียน Pro Walk-in (ประเด็นสำคัญที่สุด)**

**•**    **ปัญหา: เมื่อมีโครงการจำนวนมาก (20–40 โครงการ) หน้าจะยาวมาก ผู้ใช้ต้องเลื่อนนานกว่าจะถึงปุ่มลงทะเบียนและ Consent ทำให้ “แรงเสียดทาน” ในการสมัครสูง**

**•**    **ข้อสังเกตหลัก: ผู้ใช้ส่วนใหญ่ต้องการแค่ “ลงทะเบียน” อาจยังไม่ได้สนใจโครงการใดเป็นพิเศษ**

**•**    **มติ – ปุ่มลงทะเบียน: ทำให้ปุ่ม (สีฟ้า) ค้างอยู่ด้านล่างเสมอ (sticky) เพื่อให้กดได้ง่าย**

**•**    **มติ – แนวทางแบบไฮบริด: ตั้งค่า default เป็น “ส่งทั้งหมด (All)” แต่ให้ผู้ใช้สามารถติ๊กออก หรือเลือกเฉพาะหมวด/โครงการที่สนใจได้เอง (สมดุลระหว่างปริมาณและคุณภาพ)**

**•**    **มติ – Flow ใหม่: กรอกชื่อ + เบอร์โทร → กดลงทะเบียน → ขึ้น Modal ให้เลือกหมวดที่สนใจ → ติ๊ก Consent → กดยืนยัน**

**•**    **ข้อกำหนด: รายชื่อจากการลงทะเบียนนี้ “ไม่ถูกส่งเข้าโครงการโดยตรง” แต่จะเก็บในถังของแอดมินเพื่อคัดกรองและติดต่อภายหลัง**

**•**    **มติ: ตัดรายการ list โครงการที่แสดงตอนเข้าหน้าออก (ยุบเก็บไว้) และเอาติ๊ก Walk-in ที่เบียร์เพิ่มเข้ามาออก เพราะทำให้สับสน**

**•**    **Consent (PDPA): ให้ใช้ wording เวอร์ชันล่าสุดที่จ้างที่ปรึกษาทำ ไม่ใช้ของเดิม (เบียร์ตรวจสอบ)**

## **4.9 หน้าคูปอง และ Pop-up หลังลงทะเบียน**

**•**    **หลังกดส่งสำเร็จ จะมี Pop-up แสดงคูปองให้ดู พร้อมปุ่ม “ไปคูปองของฉัน”**

**•**    **เลขจำนวนคูณบนคูปองเล็กเกินไป ให้ปรับให้ใหญ่ขึ้น และระวังขนาดกรอบที่กระทบขนาดภาพ (รองรับชื่อยาวเป็น 2 บรรทัด)**

**•**    **ใน Pop-up ของหน้าใบประกาศ: ออกแบบให้ผู้ใช้อ่านเงื่อนไขทีละใบ (ปิด/ถัดไป) หรือเลื่อนดูภายในได้ และเลื่อนการ์ดซ้าย–ขวาได้**

## **4.10 Section วิดีโอ (Video)**

**•**    **ประเด็นค้าง: ต้องยืนยันว่าวิดีโอที่นำมาแสดงเป็นวิดีโอ Event จริง หรือเป็นวิดีโอทั่วไป**

**•**    **ถ้าเกี่ยวกับ Event: ต้องเพิ่มดีไซน์/แท็ก Event ให้ผู้ใช้รู้ว่าเป็นของช่วงงาน; ถ้าไม่เกี่ยว: ควรไปแสดงในหน้าใบประกาศแทน**

**•**    **ต้องสอบถาม P'Dear เรื่องวิธีขายวิดีโอ และว่าขายพร้อม Event หรือไม่ ก่อนสรุปดีไซน์**

**•**    **มติเบื้องต้น: ตัดวิดีโอออกจากหน้า Home (P'Pop โหวตเอาออก) ส่วนหน้าเสิร์ช (ในหมวด) ยังคงไว้ แต่ตำแหน่งวางยังต้องสรุป; การ์ดวิดีโอเมื่อกดต้องเปิดเข้าหน้ารายละเอียด (ใบประกาศ)**

## **4.11 หน้า Home เทียบกับหน้าเสิร์ช (Search)**

**•**    **หน้า Home: ไม่มีโปรโมชัน ควรสั้นลง ตัดวิดีโอออก เน้นแสดงโปร/โครงการที่ดึงความสนใจเพื่อให้กดเข้าไปดูต่อ และให้ปุ่ม Event เป็นปุ่มหลัก (CTA)**

**•**    **หน้า Home: 4 หมวดด้านบน + 4 หมวดด้านล่าง ให้วางต่อกันด้วยดีไซน์เดียวกัน (รวมเป็นชุดเดียว)**

**•**    **หน้าเสิร์ช: โครงสร้างคล้ายหน้า Home แต่เป็นช่วง Event โดยนำดีไซน์โปรโมชันจากหน้า Event มาปรับใช้**

## **4.12 โปรจองของโครงการ – ดีไซน์ซ้าย–ขวา**

**•**    **โปรจองเป็นดีไซน์ของโครงการเอง เป็น section เต็ม และมีได้ 1 โปรจองต่อ 1 โครงการเท่านั้น**

**•**    **ภาพใหญ่ได้แต่ถูกจำกัดด้วย description เมื่ออยู่บน Mobile ในเลย์เอาต์ซ้าย–ขวาจะเล็กลง**

**•**    **พาร์ทเนอร์และ “หน้าอยู่” ไม่มีโปรจอง**

**•**    **เมื่อส่งใบจอง จะมี Pop-up (อาจเป็นของหน้าอยู่/ธนาคาร ฯลฯ) สื่อสารรวมในรูป/section เดียว แต่ไม่ระบุว่าเป็นของหน้าอยู่ — ปรับเฉพาะหัวข้อ (wording)**

# **5. ประเด็นค้างพิจารณา / รอตัดสินใจ (Open Issues)**

**•**    **วิดีโอ Event ขายพร้อม Event จริงหรือไม่ และขายอย่างไร — รอสอบถาม P'Dear (มีผลต่อการออกแบบ section วิดีโอ)**

**•**    **ตำแหน่งการวางโปรจองและวิดีโอบนหน้าเสิร์ช — รอสรุปหลังได้ภาพรวมเนื้อหา**

**•**    **ข้อมูลจากทีม Data (บ่ายวันอังคาร) เพื่อตัดสินใจว่าจะตัด/เพิ่มเนื้อหาส่วนใด**

**•**    **รายละเอียด User Journey ให้ครบลูปถึงการเก็บคูปองสำเร็จ และวิธีแจ้งผลหลังส่ง (เช่น SMS) — รอสรุป**

**•**    **ยืนยัน wording ของ Consent (PDPA) ให้เป็นเวอร์ชันล่าสุด**

# **1. บริบทและวัตถุประสงค์ของฟีเจอร์**

**การประชุมเป็นการทบทวนดีไซน์และตกลงข้อกำหนดของฟีเจอร์ “Online Event / Campaign” ซึ่งเป็นช่วงกิจกรรมส่งเสริมการขายบนแพลตฟอร์มอสังหาฯ โดยมีกลไกหลักคือการให้ผู้ใช้ “เก็บคูปอง” เพื่อนำไปใช้สิทธิ์แบบ Walk-in ที่โครงการ ทั้งนี้ฟีเจอร์ครอบคลุมทรัพย์หลายประเภท ได้แก่ โครงการใหม่, รับสร้างบ้าน (Walk-in), ทรัพย์จากพาร์ทเนอร์ และทรัพย์มือสอง**

**วัตถุประสงค์ทางธุรกิจที่ระบุในที่ประชุม:**

**•**        **เพิ่มจำนวนการลงทะเบียน (Lead) ให้สำเร็จมากขึ้น โดยเฉพาะผ่านฟีเจอร์ Pop-up**

**•**        **เพิ่ม Click-through Rate (CTR) เข้าสู่หน้าใบประกาศ ผ่านการแสดงผลโปรโมชัน/แคมเปญในหน้าอื่น ๆ**

**•**        **แก้ปัญหาเดิม: ผู้ใช้ “เก็บคูปองแต่ไม่ Walk-in” เนื่องจากไม่เข้าใจว่า Walk-in คืออะไร**

# **3. ข้อกำหนดเชิงหน้าที่ (Functional Requirements)**

## **3.1 Flow การลงทะเบียน & เก็บคูปอง Walk-in**

**•**        **ลำดับ flow: ผู้ใช้กรอกชื่อ–นามสกุล + เบอร์โทร → กด Consent → กดลงทะเบียน/สนใจ → เด้ง Modal ให้เลือกประเภททรัพย์**

**•**        **การเลือกประเภททรัพย์เป็นแบบ Checkbox/Combo (เลือกได้หลายประเภท) แต่ “ต้องติ๊กเลือกเอง” และ “ไม่มี Default”**

**•**        **เหตุผลของการไม่มี Default: ถ้า default เป็น All การส่งต่อแอดมิน/เบอร์โทรของแต่ละหมวดจะไม่ถูกต้อง ระบบจึงบังคับให้เลือกหมวดเอง**

**•**        **Consent + Cloudflare/CAPTCHA จะแสดงหลังกรอกข้อมูลครบ (เด้งลงมาด้านล่างให้เลือกอีกที คล้าย flow สินเชื่อ) ไม่ซ่อนใน Modal**

**•**        **Bot detection: การลงทะเบียนจะไม่สำเร็จจนกว่าจะกรอก/กดยืนยัน จึงไม่กระทบการตรวจจับบอท (ให้ทีม text/Cloudflare โหลดเฉพาะส่วนคาแฟ/ตรวจสอบเล็กน้อย)**

**•**        **เมื่อเก็บคูปองสำเร็จ → แสดงคูปองทั้งหมดในโครงการนั้น และถาม “ต้องการเก็บคูปองต่อหรือไม่” (เก็บในหมวดเดิม)**

**•**        **Mobile: ปรับ Modal ให้สั้นลง จัด 4 หมวดให้อยู่บรรทัดเดียวเพื่อประหยัดพื้นที่**

## **3.2 การแสดงผล Promotion / Campaign**

**•**        **แสดงแบบ Tab — ประเด็นเปิด: ต้องมี Default tab หรือไม่ (ดู Open Items)**

**•**        **โครงการใหม่แสดงเด่นสุด/ชิดซ้ายสุด หรือเรียงเฉพาะโครงการใหม่มาก่อน**

**•**        **ฟิลเตอร์ “แนะนำสำหรับคุณ”: เพิ่มฟิลเตอร์แนวคิดคล้าย Shopee โดยใช้การ Tag ผู้ใช้ (เช่น ช่วงราคาบ้าน 3–5 ล้าน) เพื่อหยิบโปรที่ตรงกลุ่มขึ้นก่อน — ต้องคุยกับทีม Data ว่า tag อะไรได้บ้าง**

**•**        **สิทธิพิเศษจากพาร์ทเนอร์ (Top-up): ใช้ Header รวม + ปรับดีไซน์เป็นแนวยาว (การ์ดแนวนอน), ไม่ต้องระบุชื่อพาร์ทเนอร์ให้ผู้ใช้เห็น**

**•**        **รวม Header ภาษาไทยกับ Header โลโก้ให้เป็นอันเดียวกัน และจัดโลโก้ไม่ให้ถูกตัด/บีบ**

## **3.3 การออกแบบการ์ด (Card Design)**

**•**        **เพิ่ม “ราคาเริ่มต้น + โซน” เป็นอีก 1 บรรทัดบนการ์ด (ของเดิมไม่มี ทำให้ผู้ใช้ตัดสินใจคลิกไม่ได้)**

**•**        **จัดเงื่อนไขไว้ล่างสุดเป็น “แท็ก (Tag)” ให้เป็นเนื้อเดียวกัน ลด layout ที่ดูแปลก**

**•**        **กรอบใบประกาศด้านนอก: คงรูปแบบเดิม (กรอบทับภาพ) ไม่มีแท็กเพิ่ม เพื่อไม่ให้การ์ดรกเกินไป**

**•**        **คูปอง Walk-in: ใช้วงกลมแสดงจำนวนคน หากเกินจำนวนให้ซ้อนหลัง + แสดง “+N” (คล้าย Lazada) แต่เริ่มต้นไม่ต้องซ้อน**

**•**        **PC: รูปต้องใหญ่ขึ้นกว่าปัจจุบัน; โปรโครงการต้องเด่นสุด, โปรพาร์ทเนอร์/Top-up เล็กกว่าได้**

## **3.4 Logic ตัวนับเวลา (Countdown)**

**•**        **ช่วงที่ 1 (ช่วง P / ก่อนเริ่มงาน): แสดงเป็น “วันที่จริง” ว่างานเริ่มวันไหน–ถึงวันไหน**

**•**        **ช่วงที่ 2 (เมื่อถึงวันงาน/ใกล้จบ): เริ่มนับถอยหลังเป็น วัน → ชั่วโมง → นาที → วินาที จนถึงวันสิ้นสุด**

**•**        **นิยาม “ใกล้จบ” = 10 วันก่อนสิ้นสุดแคมเปญ จึงเริ่มนับถอยหลัง (พิจารณาเทียบ 7 วัน/10 วัน สรุปที่ 10 วัน เพื่อให้ “เร้า” และไม่งง อ้างอิงพฤติกรรมโปรช่วง \~2 สัปดาห์แบบ Shopee)**

**•**        **Mobile: ใส่หน่วย “วัน” นำหน้าเสมอ และกระชับเลย์เอาต์ส่วนวัน/เวลา/สถานที่ ไม่ให้ยาวเกิน**

## **3.5 หน้าใบประกาศ, ทรัพย์มือสอง และการ Navigate**

**•**        **กดโปรของ โครงการ/รับสร้างบ้าน (Walk-in) → วิ่งไปหน้าใบประกาศ (section ที่เกี่ยว) + เด้ง Modal โปรโมชันทับขึ้นมา**

**•**        **กดโปรของ พาร์ทเนอร์/มือสอง → แสดงเป็น Modal อย่างเดียว (เพราะไม่มีหน้าใบประกาศให้วิ่งไป) แต่ยังมีปุ่มให้ไปดูโครงการได้**

**•**        **Modal โปรโมชัน: ภาพใหญ่ฝั่งซ้าย, รายละเอียดฝั่งขวา, มีลูกศรซ้าย–ขวาเลื่อนดูโปรอื่น, กดที่ภาพเพื่อขยาย**

**•**        **ทรัพย์มือสอง: ในรอบนี้ “แสดงผลอย่างเดียว” (ผู้ใช้ส่งใบจอง/ติดต่อมาเอง) ไม่เพิ่มปุ่มส่ง/flow หลังบ้าน เพื่อไม่ให้เพิ่มงาน — ถ้าต้องการเพิ่มภายหลังค่อยทำหลังบ้านเพิ่ม**

**•**        **รวม Event/จอง/มือสอง ได้ทั้ง 3; มือสองได้เฉพาะ Top-up; Event priority ต่ำสุดสำหรับมือสอง**

## **3.6 การวัดผล (Performance Tracking)**

**•**        **การคลิกโปร (กรณีเด้ง Modal อย่างเดียว ไม่เข้าหน้าใบประกาศ) ต้องนับเป็น Performance ของโปรโมชัน ไม่ใช่ของใบประกาศ**

**•**        **ต้อง Tag ได้ว่า traffic/คลิกมาจากหน้าใด (เช่น มาจากหน้า Landing event) — ต้องประสานทีม Data เรื่องการ Tag และการนับ**

## **3.7 Pop-up Feature (Killer Feature)**

**•**        **กลไก: เมื่อผู้ใช้เลื่อนดูใบประกาศครบ \~5 วินาที จะเด้ง Pop-up แสดงคูปอง Walk-in ทั้งหมดของแคมเปญขึ้นมาเต็มหน้า เพื่อกระตุ้นให้ลงทะเบียนสำเร็จ**

**•**        **เป็นฟังก์ชันหลักที่ทุกคนที่เข้ามาจะเจอ — ออกแบบเฉพาะช่วงแคมเปญเท่านั้น**

**•**        **คุณค่า 2 ด้าน: (1) แสดงการ์ดมากขึ้นในหน้าอื่น ๆ เพื่อเพิ่ม CTR เข้าหน้าใบประกาศ และ (2) Pop-up เพิ่ม Conversion / ลดการทิ้ง Lead**

**•**        **ความเสี่ยง: Pop-up เด้งทับขณะผู้ใช้กำลังเลื่อนดู อาจรบกวน/ดูก้าวร้าว ต้องออกแบบ copy ด้านบนและ UX อย่างระวัง**

**•**        **ตำแหน่ง “Walk-in ฮอตสุด” บนสุด: รอข้อมูลจาก Data ก่อนตัดสินใจ (อาจถูกคิวทิ้ง/ไม่เวิร์ก)**

## **3.8 การสื่อสาร Walk-in (แก้ปัญหาเก็บคูปองแต่ไม่ Walk-in)**

**•**        **ปัญหา (Root cause): ผู้ใช้ไม่รู้ว่า “Walk-in” คืออะไร แพลตฟอร์มไม่เคยสื่อสารตรง ๆ ทำให้เก็บคูปองแล้วไม่ไปใช้สิทธิ์**

**•**        **แนวทาง: เพิ่มปุ่ม/CTA หรือวิดีโอสั้น (<30 วินาที) อธิบาย Walk-in อยู่ในโซน Walk-in บนหน้า event**

**•**        **เปลี่ยน Copy: จาก “เพียงคุณ Walk-in” → “เก็บคูปองแล้วไปโครงการเลย” เพื่อขยายความ Next Action ให้ชัด**

## **3.9 การเปลี่ยนคำศัพท์ (Terminology)**

**•**        **เลิกใช้คำว่า “Event / อีเวนต์” (สื่อถึงงานใหญ่) เนื่องจากในอนาคตจะจัดเป็นแคมเปญย่อย ๆ บ่อยขึ้น (ทุก \~3 เดือน)**

**•**        **B2C (สื่อสารกับ User): ใช้ “รวมแคมเปญ (Campaign)” — สรุปว่าชัดกว่า “กิจกรรม”**

**•**        **B2B (สื่อสารกับโครงการหมู่บ้าน): ใช้ “บูทแคมเปญ”**

**•**        **ทุกจุดที่ใช้คำว่า Event ต้องเปลี่ยนใหม่ทั้งหมด**

# **4. การวิเคราะห์การเก็บคูปองและ Section Event**

**ที่ประชุมแบ่งการคลิกใน Section Event เป็น 2 เลเยอร์ (Layer) เพื่อดูพฤติกรรมการเก็บคูปอง**

| **Layer** | **นิยาม** | **จำนวน Action** | **Action ที่คลิกมากสุด** |
|-------|-------|--------------|----------------------|
| **Layer 1** | **ผู้ใช้เลื่อนเข้ามาเห็น Section แล้วมีการคลิก** | **6 (คูปอง 4 + ปุ่มเก็บทั้งหมด + ดูทั้งหมด)** | **ปุ่ม “ดูทั้งหมด”** |
| **Layer 2** | **Modal ที่เด้งขึ้นเมื่อกดดูทั้งหมด/เข้ามาสักพัก** | **5 (คูปอง 4 + ปุ่มเก็บทั้งหมด)** | **ปุ่ม “เก็บคูปองทั้งหมด” (\~7.56%)** |

### **ข้อค้นพบเรื่องคูปอง**

**•**    **คูปองที่ดีที่สุดต่อโครงการ คือ คูปองที่เกี่ยวกับของรางวัล/พาร์ทเนอร์ (อ้างถึง \~0.53%) สูงกว่าคูปองของโครงการเอง**

**•**    **ความเห็นที่ประชุม: หากรอบหน้าไม่มีของแจก ความสนใจน่าจะลดลง แต่คูปองของโครงการยังถือว่ามีคนสนใจอยู่**

**•**    **การลงทะเบียนสำเร็จผ่านการคลิก “คูปองแม่” อยู่ที่ \~30% และอัตราความสำเร็จโดยรวม \~67%**

| **ประเด็นคุณภาพ Lead (Concern สำคัญ)**<br>**ผู้ใช้จำนวนหนึ่งกด “เก็บทั้งหมด” โดยไม่รู้ว่ากำลังเก็บอะไร ทำให้เกิด Lead หลอก เมื่อ Sale โทรกลับพบว่าไม่ตรงความต้องการจริง**<br>**แนวทาง: ต้องสื่อสารให้ชัดก่อนกดว่า “เก็บแล้วจะได้คูปอง/โครงการอื่นในเครือ” และอาจเพิ่มการคัดกรอง (filter) คุณภาพมากขึ้น** |

# **5. มติการปรับดีไซน์ (Design Decisions)**

**สรุปการตัดสินใจปรับแต่ละหน้า โดยอ้างอิงจากผลข้อมูลในหัวข้อก่อนหน้า**

## **5.1 หน้าใบประกาศ (Listing)**

| **ประเด็น** | **มติ / แนวทาง** |
|---------|--------------|

| **Section Event** | **นำองค์ประกอบ Event เข้ามาอยู่ใน section เดียวกัน ไม่ทำ section ใหม่แยก** |

## **5.2 หน้า Search (มือ 1)**

**•**    **ปรับเพิ่มการสื่อสารเล็กน้อยตามเดิม เนื่องจาก CVR ต่ำ ต้องการดันให้ดีขึ้น**

**•**    **ตัดสินใจเปลี่ยนการนำเสนอจาก “ใบประกาศ/การ์ด” เป็น “โปรโมชัน” (โปรโมชันของโครงการ)**

**•**    **สมมติฐาน (ต้องตรวจสอบ):** **การนำเสนอที่เป็นสิทธิประโยชน์/คูปอง/ราคา+สถานที่ จะ impact การตัดสินใจคลิกมากกว่าการ์ดปกติ**

## **5.3 รื้อดีไซน์ Section Event (เฉพาะ section)**

**ที่ประชุมสรุปว่า section นี้ต้องรื้อดีไซน์ เพราะตัด element เดิมออกแล้วของที่เหลือดูไม่เด่น โดยจะนำเสนอ 2 รูปแบบ:**

**1.**   **แบบโปรโมชัน — ดึงรูปโปรโมชันของโครงการมาแสดง (ต้องเติมรูปปก/รูปเฟสของโครงการ เพื่อให้รู้ว่าเป็นโครงการไหน เพราะดูแค่โปรโมชันอาจไม่เข้าใจ)**

**2.**   **แบบโครงการที่เข้าร่วม — แสดงโครงการที่เข้าร่วมแคมเปญ**

**•**    **เปลี่ยนแกนการดูเป็น layout รายหน้า; การ์ดอาจปรับเป็นทรงสูงขึ้น/ใช้กราฟิกให้ดูเด่นขึ้น**

## **5.4 หน้า Home**

**•**    **เลือกแสดงได้ 2 อย่าง: โปรโมชัน และ โครงการที่เข้าร่วม — ไม่เอาวิดีโอ**

**•**    **ข้อจำกัดข้อมูล: หน้า Home เก็บได้แค่ 2 อย่าง (วิดีโอ กับ ปุ่มไปหน้าอื่น) ยังไม่มี data ช่วยตัดสินใจเชิงลึก (TBC)**

## **5.5 Pro Walk-in (จองพิเศษในแคมเปญ)**

**•**    **ปัญหาที่พบ: Pro/Walk-in ลอยอยู่และคนไม่ค่อยกด อาจเพราะวางตำแหน่งไม่ดี — แนวทางคือยัดเข้า Section และให้ชัดเจนว่าเป็นคนละก้อนกับโปรโมชัน**

**•**    **ในมือถือให้แสดงเป็น 2 ปุ่มชัดเจน (บน-ล่าง): เข้าชมโครงการ และ เก็บ/จอง**

**•**    **หลักการ: เมื่อผู้ใช้เห็นของดีแล้วต้องการกดเพิ่ม ต้องมีปุ่มให้กดในตำแหน่งที่เข้าถึงง่าย ไม่ต้องเลื่อนหา**

# **6. Logic การทำงานและงานหลังบ้าน**

## **6.1 การเก็บคูปอง / ลงทะเบียน**

**•**    **ให้การเก็บคูปอง/ลงทะเบียน “จบในที่เดียว” (ในหน้าใบประกาศที่รวม Event) ไม่ส่งผู้ใช้ออกไปหน้าโครงการเพื่อเก็บซ้ำ**

**•**    **Modal การเก็บ: กดเก็บ → กรอกชื่อ-เบอร์โทร → ยืนยันสำเร็จ → ปิด (จบที่หน้าเดิม)**

**•**    **กรณี Login: การ์ดที่เก็บแล้วต้องมีสถานะ (เช่น สีเทา/ปุ่มเทา/สแตมป์ “เก็บแล้ว”) — ต้องพัฒนาเพิ่ม**

**•**    **กรณีไม่ Login: เก็บตามเบอร์โทร; เบอร์เดิม-ชื่อเดิมที่เก็บแล้วจะกดซ้ำไม่ได้**

## **6.2 การเชื่อม Walk-in กับ Event**

**แนวทางที่ตกลง: สร้างแยกแล้วเชื่อม (ลดความเสี่ยงไม่ทันกำหนด เทียบกับการเปลี่ยน flow หลังบ้านทั้งหมด)**

| **รายการ** | **ข้อกำหนด** |
|--------|----------|
| **การสร้าง** | **สร้าง Campaign และ Walk-in แยกกัน แล้วค่อยผูก (เลือก type ว่า Walk-in อยู่ในช่วง Event หรือไม่)** |
| **เมื่อผูกกับ Event** | **เลือก Event แล้วเวลา/การลิงก์จะตรงกันเป็นชุดเดียว — ง่ายต่อการจัดการ** |
| **ข้อจำกัด** | **1 แคมเปญ ต่อ 1 ช่วงเวลา (ห้ามเวลาทับซ้อน)** |
| **Pop-up Walk-in** | **คงเงื่อนไขเดิม (ครบ \~5 วินาที จึงเด้ง Walk-in / ปิดโปรแล้วนับ) เพราะ Pop-up อื่นเวิร์ก** |

## **6.3 การ์ดวิดีโอ + Input โปรโมชัน**

**•**    **วิดีโอใหม่ที่ออกแบบ: ดึงรูป (รูปที่ 6) ผ่าน logic; การ์ดต้องขยายให้เด่นขึ้นเพราะ CVR ไม่ดี**

**•**    **ข้อเสนอ (ต้องตรวจสอบความเป็นไปได้):** **เพิ่มช่อง Input ให้ใส่ข้อความ/ราคาเริ่มต้น (เช่น “สูงสุด 200,000 บาท”) ลงบนกราฟิก เพื่อเพิ่ม Impact**

## **6.4 Logic แนะนำหมวด/โปรตามความสนใจ (Personalization)**

**•**    **เป้าหมาย: เมื่อผู้ใช้เข้า Landing ให้แสดงโปรโมชัน/หมวดที่ตรงความสนใจมากที่สุดก่อน**

**•**    **MVP: เริ่มจาก “แนะนำตาม default” ก่อน (ยังไม่มี personalization) แล้วเลื่อนเพื่อเปลี่ยนหมวดได้**

**•**    **เฟสถัดไป: ถ้าเก็บข้อมูลความสนใจ user ได้ ให้ดึงหมวด/ราคาที่ผู้ใช้ดูล่าสุดมาแนะนำ (ต้องเก็บ insert ของ user ซึ่งทำได้ยาก ฝากทีมตรวจสอบ)**
