# คำขอถึง BE (เพิ่มเติม 2026-10-16): FE ส่งภาษาของหน้าใน header `Accept-Language`

ไฟล์นี้บอกเฉพาะสิ่งที่เปลี่ยนจากฉบับที่ส่งไปแล้ว ไฟล์หลัก `docs/backend-i18n/backend-i18n-request.md` อัปเดตแล้ว ข้อความ "FE ไม่ส่ง `Accept-Language`" ในไฟล์ `backend-i18n-request-2026-10-15.md` ใช้ไม่ได้แล้ว

## สรุป

* ทุก request ที่ FE ยิงไป BE มี header `Accept-Language` บอกภาษาของหน้าที่ผู้ใช้กำลังเปิดอยู่
* ค่าที่ส่งมีแค่ `th`, `en`, `zh` ไม่มี q-value และไม่มี region (ไม่ใช่ `zh-CN`, `en-US`)
* contract `{ th, en, zh }` ใน response **ไม่เปลี่ยน** ข้อความเนื้อหายังขอให้ส่งครบทุกภาษาเหมือนเดิม

## ค่าที่ FE ส่ง

| หน้าที่ผู้ใช้เปิด | `Accept-Language` |
|-------------------|-----------------|
| ไม่มี prefix เช่น `/property-for-sale/properties/khonkaen` | `th`            |
| `/en/...`         | `en`            |
| `/zh/...`         | `zh`            |
| ไม่มีหน้าเว็บเกี่ยวข้อง (ตอน build, sitemap, การตรวจ redirect ก่อน render หน้า) | `th`            |

* ส่งทั้ง request จาก browser และจาก server ของ FE (SSR และ route `/api/*` ของ FE ที่ส่งต่อไป BE)
* ถ้าโค้ด FE จุดไหนกำหนดค่าเองอยู่แล้ว จะใช้ค่านั้น

## ขอให้ BE


1. **ข้อความที่ BE สร้างตอนรับ request** ให้ใช้ภาษาตาม header นี้ได้ เช่น `error.message`, `message` ที่แจ้งผล, email / SMS / LINE ที่ส่งจาก action นั้น จะส่งเป็น `{ th, en, zh }` ต่อไปก็ได้ FE รับได้ทั้งสองแบบ ถ้าเป็น string ภาษาเดียว FE จะแสดงตามที่ส่งมาเลย
2. **อ่านเฉพาะ** `**th**` **/** `**en**` **/** `**zh**` **ตรงตัว** ถ้าไม่มี header หรือเป็นค่าอื่น (เช่นค่าที่ browser ใส่เองตอนมีคนเรียก API ตรงๆ อย่าง `th-TH,th;q=0.9,en;q=0.8`) ให้ใช้ `th`
3. **Cache:** ถ้า BE, APISIX หรือ CDN cache response ที่เนื้อหาเปลี่ยนตามภาษา ต้องตั้ง `Vary: Accept-Language` หรือใส่ header นี้ใน cache key ไม่งั้นภาษาจะปนกัน (เช่น response ไทยถูกส่งให้หน้า `/en`)
4. **CORS:** ไม่ต้องแก้ `Access-Control-Allow-Headers` เพราะ `Accept-Language` ที่มีค่า `th` / `en` / `zh` เป็น CORS-safelisted header

## Request ที่ตั้งใจไม่ส่ง header นี้

| Request | เหตุผล | ขอให้ BE |
|---------|--------|----------|
| `GET /api/locations/tree`, `/tree/children`, `/tree/node` (ตอนโหลดต้นไม้ทำเลที่ server ของ FE เก็บ cache ร่วมกันทุกคน) | ผลลัพธ์ถูกใช้กับผู้ใช้ทุกภาษา ถ้าส่งภาษาของคนแรกที่โหลด ทุกคนจะได้ภาษานั้น | ส่ง label เป็น `{ th, en, zh }` ต่อไป อย่าเลือกภาษาจาก header ใน endpoint นี้ |
| tracking (`/api/track` → tracking backend) และ usage heartbeat | ข้อมูลวิเคราะห์ ไม่มีข้อความแสดงผู้ใช้ URL ของหน้า (มี prefix `/en`, `/zh`) อยู่ใน payload แล้ว | ไม่ต้องทำอะไร |
| managed redirect resolver | ทำงานก่อน render หน้า ส่ง `source_url` ที่มี prefix ภาษาอยู่แล้ว | ไม่ต้องทำอะไร |

## สิ่งที่ไม่เปลี่ยน

* ข้อความเนื้อหา (ชื่อ, ทำเล, ราคาที่ format แล้ว, ข้อความแคมเปญ ฯลฯ) ยังขอให้ส่งเป็น `{ th, en, zh }` ตามไฟล์หลัก response ชุดเดียวจะได้ cache ใช้ได้ทุกภาษา
* header เดิม (`apikey`, `Authorization`, `sessionId`, `pagePath`, `province`, `keycloak_id`) ยังเหมือนเดิม
* `search={keyword}` และ `service_type` ยังส่งตามที่ระบุในไฟล์หลัก

## วิธีตรวจ

* เปิดหน้า `/en/...` แล้วดูแท็บ Network ของ browser request ไป API ต้องมี `accept-language: en` (หน้า `/zh/...` ต้องได้ `zh` และหน้าไม่มี prefix ต้องได้ `th`)
* ฝั่ง BE ดูค่า `Accept-Language` ใน access log ต้องมีแค่ `th`, `en`, `zh` สำหรับ request ที่มาจาก FE
* ทดสอบ endpoint ที่แปลข้อความเองแล้ว:

```sh
curl -s -H "apikey: $APIKEY" -H "Accept-Language: en" "$API/<endpoint>"
```
